# 휴대폰이 페이지를 980px로 그리는 까닭 (viewport)

## 한 줄 요약

HTML에 `<meta name="viewport" content="width=device-width, initial-scale=1">` 한 줄이 없으면, 휴대폰 브라우저는 페이지를 **폭 980px의 데스크톱 화면처럼 그린 뒤 작게 줄여** 보여 준다. 그러면 "폭 860px 이하일 때"처럼 좁은 화면을 위해 쓴 CSS 규칙(`@media (max-width: 860px)`)이 휴대폰에서 듣지 않는다.

## 무슨 일이 있었나

프로토타입 64번째 판에 "좁은 화면에서는 도구 모음과 설정을 접어 둔다"를 넣고, 헤드리스 Chrome으로 휴대폰(폭 390px)을 흉내 내 시험했다. 그런데 메뉴가 접히지 않았다. 페이지 안에서 화면 폭(`innerWidth`)을 재 보니 390이 아니라 **980**이었다.

## 왜 980인가

휴대폰이 처음 나왔을 때 웹 페이지는 대부분 데스크톱 화면에 맞춰 만들어져 있었다. 그런 페이지를 폭 390px에 그대로 그리면 글이 줄줄이 꺾여 깨진다. 그래서 휴대폰 브라우저는 "이 페이지는 휴대폰을 모른다"고 보고, 넓은 가상의 화면(대개 980px)에 그린 다음 화면에 맞게 줄여 보여 준다. 사용자는 손가락으로 벌려 확대해 읽는다.

페이지가 "나는 휴대폰을 안다. 화면 폭 그대로 그려 달라"고 알리는 방법이 `viewport` 메타 태그다.

| 값 | 뜻 |
| --- | --- |
| `width=device-width` | 가상 화면의 폭을 기기의 실제 폭(예: 390px)으로 |
| `initial-scale=1` | 처음에 줄이거나 키우지 않고 1배로 |

## 백엔드 개발자에게 비유하면

HTTP 응답의 `Content-Type`과 비슷하다. 헤더가 없으면 클라이언트가 짐작해서 처리하고(옛날 페이지를 위한 안전한 기본값), 헤더가 있으면 적힌 대로 처리한다. `viewport`는 "이 페이지는 모바일 레이아웃을 지원한다"는 선언이다.

## 이 저장소에서는

- 프로토타입(`journal/assets/2026-10-10-ns-prototype.html`)에는 이 줄이 없었다. claude.ai에 게시할 때는 claude.ai가 감싸는 틀에 이미 들어 있어 괜찮았지만, 저장소의 사본을 휴대폰에서 직접 열면 좁은 화면 규칙이 듣지 않았을 것이다. 64번째 판에서 더했다.
- 시안 페이지는 claude.ai의 틀이 이 줄을 넣어 준다.
- 제품(웹)에서는 Vite가 만드는 `index.html`의 기본 틀에 이 줄이 들어 있다.

## 더 알아볼 것

- 휴대폰의 위아래 시스템 막대(노치, 홈 표시줄)를 피하는 `viewport-fit=cover`와 `env(safe-area-inset-*)`
