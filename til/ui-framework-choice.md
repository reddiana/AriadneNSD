# UI 프레임워크 고르기

2026-10-18 세션에서 UI 프레임워크를 React로 정하며 설명한 것을 모았습니다. 결정 자체는 [[0010-ui-framework|ADR-0010]]에, 견준 그림과 코드는 시안 M22에 있습니다.

## UI 프레임워크가 하는 일

화면의 글자나 단추는 값(지금 언어, 실행 취소를 할 수 있는가)에 따라 바뀌어야 합니다. 문제는 **값이 바뀌었을 때 화면의 어디를 고치느냐**입니다.

| 방식 | 값이 바뀌면 | 백엔드에 견주면 |
| --- | --- | --- |
| 프레임워크 없음 | 어느 글자를 어떻게 고칠지 손으로 적는다 | 캐시를 무효화할 곳을 하나하나 손으로 적기 |
| Svelte | HTML에 값을 적어 두면, 빌드할 때 컴파일러가 "고칠 곳"을 미리 계산해 둔다 | 컴파일러가 의존 관계를 분석해 만들어 둔 갱신 코드 |
| React | 화면을 그리는 함수를 통째로 다시 부르고, 앞의 결과와 견주어 다른 곳만 고친다 | 상태 → 화면을 순수 함수로 보고, 결과의 차이(diff)만 반영 |

프레임워크가 없으면 고칠 곳 하나를 빠뜨렸을 때 그 자리만 옛 글자로 남습니다. 화면 부품이 늘수록 그런 실수가 늘어납니다.

## 우리 편집기에서 프레임워크가 맡는 곳

다이어그램은 `core`의 렌더러가 SVG로 그립니다([[0030-swappable-drawing|ADR-0030]]). 키 입력, 한글 입력, 블록 위의 글자 칸도 프레임워크 없이 짭니다. 그래서 프레임워크는 **둘레의 부품**(도구 모음, 메뉴, 설정 창, AI 대화창)만 맡습니다. 나중에 프레임워크를 바꿔도 이 부품만 다시 짜면 됩니다.

## 크기는 결정을 가르지 않았다

같은 도구 모음을 넷으로 빌드해 쟀습니다(2026-10-18).

| 안 | 줄인 크기 | gzip |

## 개발자 층

조사마다 다르지만 React를 쓰는 사람이 Svelte의 6~20배쯤입니다(Stack Overflow 조사 2024 "써 봤다" 약 40% 대 약 6.5%, npm 주간 내려받기 2천만~3천만 대 1백만~2백만, 2025년 무렵. 대략). Confluence Forge와 VSCode 웹뷰의 예제도 대개 React입니다. 오픈 소스에 손을 보탤 사람, 찾을 수 있는 자료가 그만큼 많습니다. 처음에 Claude는 읽기 쉬움만 보고 Svelte를 추천했다가, 이 물음으로 React로 바꿨습니다.

## React를 읽을 때 알아 둘 것

- **부품은 함수입니다.** 값(`props`, `state`)을 받아 화면 모양(JSX, HTML처럼 생긴 글)을 돌려줍니다. 값이 바뀌면 React가 이 함수를 다시 부릅니다.
- **훅(`useState`, `useEffect` …)은 늘 같은 순서로 불러야 합니다.** `if` 안에서 부르면 안 됩니다. React가 "몇 번째 훅"으로 값을 기억하기 때문입니다.
- 우리 문서 모델은 불변입니다([[0029-immutable-document-undo|ADR-0029]]). "새 값이 오면 다시 그린다"는 React의 방식과 잘 맞습니다.

## 그 프로그램의 메뉴에 올리기

웹 · 데스크톱 · Confluence에서는 메뉴를 우리가 그립니다. Obsidian, VSCode, IntelliJ에는 그 프로그램의 명령 팔레트와 설정 화면이 있어, 사용자는 거기서 찾습니다. 그래서 편집기는 **명령의 목록**(이름, 키, 지금 할 수 있는가)을 내놓고, 셸이 그것을 자기 메뉴로 그리거나 그 프로그램의 메뉴에 올립니다([[0033-command-list-for-shells|ADR-0033]]). 이것은 어느 프레임워크를 쓰든 같습니다.

## 덧붙여: 낱말 가르기와 문법 읽기

같은 세션에서 구문 강조의 방법([[0032-token-highlighting|ADR-0032]])을 이렇게 설명했습니다.

- **낱말 가르기(lexer):** 글자를 예약어 · 글자열 · 주석 · 숫자로 자르기만 합니다. 블록 하나의 글자(`i < n`)처럼 문장 한 토막이어도 늘 됩니다.
- **문법 읽기(parser):** 낱말을 문법 나무로 엮습니다. 함수 이름과 형 이름까지 가릴 수 있지만, 토막 글자에서는 읽다 막힙니다.

## 덧붙여: 실행 취소의 두 층

글자 칸이 열려 있는 동안 `Ctrl`+`Z`는 브라우저의 글자 칸이 처리하고, 칸에 친 글자만 되돌립니다. 칸을 닫으면 고친 글자 전체가 문서의 실행 취소 하나가 됩니다 → [[02-interaction-rules#6. 실행 취소]]
