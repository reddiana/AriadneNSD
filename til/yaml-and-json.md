# YAML과 JSON

> "나중에 아래처럼 markdown의 code block에 삽입될 형식을 고려하면 yaml에 미련이 남습니다." (메인테이너, 2026-11-02 inbox)

## 한 줄 요약

프로그램이 쓰고 프로그램이 읽는 글은 JSON이, 사람이 손으로 쓰는 글은 YAML(이나 따로 만든 작은 문법)이 편합니다. 둘을 한 형식으로 맞출 필요는 없습니다.

## 같은 데이터, 두 모양

```json
{ "kind": "if", "text": "x > 0", "then": [ { "kind": "process", "text": "print(x)" } ] }
```

```yaml
kind: if
text: x > 0
then:
  - kind: process
    text: print(x)
```

YAML은 괄호와 따옴표가 없어 짧고, 주석(`#`)과 여러 줄 글이 자연스럽습니다. 그 대신 **들여쓰기가 곧 구조**입니다. 공백 하나가 바뀌면 뜻이 바뀌거나 깨집니다.

## YAML의 함정: 글자가 글자로 읽히지 않을 때

따옴표 없이 적은 값은 파서가 "무엇처럼 보이는지"로 타입을 짐작합니다.

| 적은 것 | 기대 | YAML 1.1 파서가 읽는 것 |
| --- | --- | --- |
| `yes`, `no`, `on`, `off` | 글자 | 참 · 거짓 |
| `1.10` | 글자(버전) | 수 `1.1` |
| `a: b` | 글자 | 키와 값 |
| `# 다음` | 글자 | 주석(사라짐) |

키도 마찬가지라, If의 갈래를 `yes:` · `no:`라는 키로 적으면 참 · 거짓 키가 됩니다. 이 함정 때문에 "노르웨이 문제"(나라 코드 `NO`가 거짓이 됨)라는 이름까지 있습니다. YAML 1.2는 이를 고쳤지만, 1.1을 따르는 라이브러리가 아직 많습니다.

참고로 YAML 1.2는 JSON을 포함합니다. YAML 파서는 JSON 글도 읽습니다.
