# 단축키

> [!abstract] 이 문서는
> **어떤 키가 어떤 명령인지**를 정한 표입니다. 명령이 무엇을 하는지는 [[02-interaction-rules]]에, 왜 Vim 키인지는 [[dr-0009-vim-keys|DR-0009]]에 있습니다. 2026-10-17까지는 편집기 설계([[03-editor]])의 4장에 있었고, 사용자의 조작 규칙이라 UX 설계로 옮겼습니다.

키 배열은 하나입니다. 표준 키는 그대로 두고 그 위에 Vim 키를 더합니다(→ [[dr-0009-vim-keys|DR-0009]]). 키는 이 문서의 표에만 적습니다. 다른 문서는 명령 이름으로 쓰고 이 문서를 가리킵니다.

Vim 키를 들인 까닭은 Vim을 쓰는 사람에게 익숙한 환경을 주려는 것입니다. 그래서 키와 그 동작을 정할 때는 "Vim에서 그 키가 실제로 어떻게 움직이는가"를 먼저 봅니다. 규칙을 줄이려고 Vim과 다르게 만들 때는 그 까닭을 적습니다.

Vim과 다르게 만든 곳은 넷입니다.

| 키 | Vim에서는 | 여기서는 | 까닭 |
| --- | --- | --- | --- |
| `a` / `A` | 커서 뒤 / 줄 끝에서 고치기 | 종류 글자를 기다렸다가 블록을 뒤 / 앞에 넣기 | 종류 글자 `i` `d` `k`가 Vim 키와 겹쳐 앞에 붙일 키가 필요했다 ([[dr-0009-vim-keys\|DR-0009]]) |
| `s` | 글자 하나를 지우고 고치기 | 종류 글자를 기다렸다가 감싸기 | vim-surround의 `ys` · 영역에서 `S`를 한 글자로 줄였다 |
| `x` | 글자를 지우고, 지운 것을 붙일 수 있음 | 복사 없이 지우기 (`Delete`와 같음) | `dd`(잘라내기)와 역할을 나눴다 |
| `U` | 줄 단위 되돌리기 | 다시 하기 | `Ctrl`+`R`도 받지만 브라우저에서 놓치면 새로 고침이 되어 글자 키를 하나 더 두었다 |

> [!warning] 초안 (2026-10-13)
> 굳은 것은 DR-0009의 넷입니다: 키 배열 하나, 고치다 누른 `Esc`는 받아들임, `o` / `O`와 `a` / `A` + 종류로 넣기, `dd`는 잘라내기. 나머지 키는 프로토타입(39번째 판부터 이 표대로 돕니다)으로 써 본 뒤 굳힙니다.

편집기의 상태는 셋이고 Vim의 모드와 짝이 맞습니다.

| 상태 | Vim | 들어가는 법 | 나오는 법 |
| --- | --- | --- | --- |
| 블록을 고른 상태 | Normal | 처음부터 | — |
| 글자를 고치는 중 | Insert | `i` `Enter` `F2` 더블클릭, 블록을 넣은 직후 | `Enter` `Esc` (둘 다 적은 대로 받아들임) |
| 영역을 고르는 중 | Visual | `v` | `v` `Esc`, 또는 명령을 실행하면 |

대문자는 `Shift`와 함께 누른다는 뜻입니다. 글자 키는 자판의 자리로 읽어서 한글 입력 상태에서도 같습니다. 종류 글자는 `i` If, `w` While, `d` Do-While, `k` Case, `c` 호출입니다.

두 번 누르기(`a` `A` `s` `d` `y` `z` `g` `[` `]`)는 첫 키를 누르면 둘째 키를 기다립니다. **0.4초 안에 둘째 키를 누르지 않으면 화면 아래에 안내 상자**를 띄워, 이어 누를 키와 그 명령을 모두 보입니다(Neovim의 which-key와 같은 방식). 둘째 키를 누르거나 그만두면 닫힙니다. 안내는 사용자 설정에서 끌 수 있습니다 → [[01-requirements#^edit-key-hint]], [[ux-decisions#K1. 두 키 조합의 안내|K1]] 맞지 않는 키나 `Esc`를 누르면 그만두고, 누른 키는 버립니다. 블록을 고른 상태에서 `Esc`를 한 번 누르면 안내만 띄우고, 두 번 연속 누르면 고른 것을 풉니다(2026-10-15 → [[02-interaction-rules]]). 블록을 고른 상태의 휠은 `j` `k`와 같습니다.

들이지 않는 것: 횟수와 동사 + 이동 조합(`3j`, `d2j`), 레지스터, 매크로, 마크, `:` 명령줄, 글자 칸 안의 Vim 키, `Ctrl`+글자 조합.

한 글자 키는 보기에 포커스가 있을 때만 듣습니다. 그래서 Obsidian의 기본 단축키를 가로채지 않습니다.

안쪽 블록에서 `ds`를 누르면 고르지 않은 바깥 제어 블록이 벗겨집니다.

> [!question] 미결정
> - 갈래 이름 고치기의 키. 예전 키 `L`은 `l`과 겹쳐 없앴고, 2026-10-17에 `Shift`+`L`로 되살렸다(더블클릭도 됨). 갈래 이름을 고르는 세부와 함께 굳힌다 → [[ux-decisions]] Q10
> - 옮기기 명령의 키 → [[ux-decisions]] Q6. `ddp`로 한 칸 아래로는 이미 됨
> - `Ctrl`+`←` `→`를 남길지(Q11)
> - 글자를 자판의 자리로 읽으므로 QWERTY가 아닌 배열(Dvorak, AZERTY)에서는 키에 적힌 글자와 맞지 않는다. 어떻게 할지 정하지 않음 → [[keyboard-keys-and-ime]]
> - 나중 후보: `.`(방금 한 일 되풀이), `/`(블록 글자 찾기), `cs` + 종류(제어 블록의 종류 바꾸기). 뒤의 둘은 새 요구사항
