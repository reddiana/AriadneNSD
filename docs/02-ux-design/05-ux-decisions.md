## 2. 고치기 · 넣기 · 옮기기

### Q1. 고치기를 시작하는 방법 (R1)

글자가 있는 것(블록 글자, 호출 블록의 인자와 결과, 접기 영역의 이름, Case 갈래의 이름, 머리의 이름)마다 고치기를 시작하는 방법이 다르게 적혀 있었다.

**추천: 1. 글자가 있는 것은 모두 같은 방법으로 고친다**(키는 [[03-keymap]]). 정하지 않음 → UX 규칙 시안의 "Q1" 카드

### Q2. 더블클릭의 뜻 (R1)

더블클릭이 곳에 따라 고치기 · 펴기 · 접기의 셋이다. 접힌 칸의 이름을 고치려고 더블클릭하면 펼쳐진다.

**추천: 1. 더블클릭은 어디서나 고치기. 접고 펴는 것은 접기 · 펴기 명령과, 접힌 칸 · 이름 띠 · 접힌 줄의 작은 세모(▸ ▾)로 한다.** 세모는 편집 층의 표시로 보아 저장되는 그림에 넣지 않는다. 정하지 않음 → UX 규칙 시안의 "Q2" 카드

### Q3. `Esc`의 뜻 (R1)

**정함 (2026-10-13): 3. `Enter`와 `Esc` 모두 적은 대로 받아들인다.** 고치기 전으로 되돌리려면 실행 취소를 한다. 받아들일 수 없어 다시 연 칸(겹친 머리 이름)에서만 `Esc`가 고치기 전으로 되돌린다.

- 까닭: Vim에서 `Esc`는 적은 것을 남기고 나가는 키라서, 되돌리기로 두면 Vim에 익은 손이 적은 글자를 매번 잃는다 → [[0025-vim-keys|ADR-0025]]. 처음의 추천은 "`Esc`는 되돌리기"(1)였다.
- 지금의 규칙 → [[02-interaction-rules#Event 머리]]

### Q4. 비울 수 없는 칸을 비웠을 때 (R2)

머리의 이름은 비우면 칸을 다시 열고, 호출 블록의 인자는 머리의 괄호 안 글자가 다시 들어가고, 접기 영역의 이름은 기본 이름이 된다. 곳마다 다르다.

**추천: 1. 비울 수 없는 칸을 비우면 그 칸의 기본 글자가 들어가고, 칸을 다시 열지 않는다.** 머리의 이름이 **겹칠 때만** 칸을 다시 연다. 바뀌는 것은 "머리의 이름을 비웠을 때" 하나다. 겹친 이름까지 받아들이고 표시만 붙이는 안(Q4-b)은 지금은 하지 않는다. 정하지 않음 → UX 규칙 시안의 "Q4" 카드

### Q5. 새로 생기는 것의 자리 (R3)

새 블록은 고른 것 뒤(`Shift`는 앞)인데, 붙여넣기 · Case 갈래는 앞에 넣는 방법이 없었다.

**추천: 1. 새로 생기는 것은 고른 것 뒤에, `Shift`를 함께 누르면 앞에. 블록 · 붙여넣기 · 갈래 모두 같다.** 고른 것을 바꿔 놓는 명령(감싸기, 빼기)은 고른 것이 있던 자리에, 새 다이어그램은 그 종류의 맨 뒤에. Vim의 `p` · `P`와 같은 규칙이다(붙여넣기는 이미 이대로 됨 → [[03-keymap]]). 정하지 않음 → UX 규칙 시안의 "Q5" 카드

### Q6. 순서 바꾸기를 명령 하나로 (R4)

순서를 바꾸는 일이 넷(블록, If의 참 · 거짓, Case의 갈래, 다이어그램)인데 방법이 제각각이고, 블록은 키보드로 옮길 수 없다(접근성 [[01-requirements#^nfr-a11y]]).

**추천: 1. "옮기기" 명령 하나: 위 · 아래 · 왼쪽 · 오른쪽.** 블록은 같은 줄의 앞 · 뒤와 자리를 바꾸고 줄 끝에서는 제어 블록 밖으로 나온다. If · Case 안에서 좌우는 갈래를 통째로 맞바꾼다(If의 참 · 거짓 바꾸기가 이것이 된다. default는 움직이지 않음). 머리를 골랐으면 다이어그램의 순서를 바꾼다. 끌어 놓기는 같은 일을 마우스로 하는 방법이다. 블록을 옆 제어 블록 **안으로** 넣는 것은 이 명령에 넣지 않는다. 정하지 않음 → UX 규칙 시안의 "Q6" 카드

### Q12. "빼기"라는 말

"빼기"가 "갈래 빼기"(지움)와 "Method로 빼기"(옮기고 호출 블록을 남김)의 두 뜻이다.

**추천: 1. "갈래 빼기"를 "갈래 지우기"로.** "빼기"는 Method로 빼기에만 쓰고, "머리 떼기"는 그대로 둔다. 정하지 않음 → UX 규칙 시안의 "Q12" 카드

## 3. 묶기 · 풀기 · 실행 취소

### Q7. 푸는 명령을 하나로 (R5)

**정함 (2026-10-13): 3. 껍데기를 없애고 안의 것을 남기는 "풀기"는 제어 블록과 호출 블록에 듣고, 접기 영역 풀기는 따로 둔다.**

- 까닭: Vim에서 접기(`zd`)와 둘레 지우기(vim-surround의 `ds`)는 서로 다른 가족이다. 메인테이너: "vim 단축키를 도입한 이유는 vim 사용자에게 친숙한 환경을 제공하기 위함입니다. 그점도 고려가 되면 좋겠습니다." 처음의 추천은 "풀기 하나가 셋 모두에 듣는다"(1)였다.
- 안쪽 블록을 고르고 풀면 그것을 담은 가장 가까운 제어 블록이 벗겨진다. Q8의 추천 1과 어긋나는 곳이고, 실행 취소로 되돌린다.
- 지금의 규칙 → [[02-interaction-rules#감싸기 · 풀기]], [[02-interaction-rules#접기 · 펼치기]]

### Q8. 고른 것이 명령의 대상이 아닐 때 (R6)

접기 · 펴기와 접기 영역 풀기는 고른 것을 담는 것을 찾아 올라가고, 다른 명령은 고른 것에만 듣는다.

**추천: 1. 보기만 바꾸는 명령은 찾아 올라가고, 내용을 바꾸는 명령은 고른 것에만 듣는다.** 접기 · 펴기는 잘못 눌러도 한 번 더 누르면 돌아오므로 너그러워도 된다. 정하지 않음 → UX 규칙 시안의 "Q8" 카드

### Q9. 실행 취소의 대상 (R7)

**정함 (2026-10-13): 1. 파일의 내용을 바꾸면 실행 취소의 대상이고, 보기 상태를 바꾸면 대상이 아니다.** 결과 기호(`←` / `=`)는 보기 상태에 넣는다.

- 까닭: 결과 기호는 "같은 내용을 어떻게 보여 주는가"이고 설정 화면에서 바꾸는 것이다. 이 구분은 [[0018-save-as-shown|ADR-0018]]이 파일 안에서 나눠 둔 "내용"과 "보기 상태"와 같다. 접기만 해도 "저장 안 됨" 표시는 뜬다.
- 지금의 규칙 → [[02-interaction-rules#6. 실행 취소]]

## 4. 호출 블록

### 4.1 호출 블록 펴 보기 (R6)

호출 블록 자리에 부르는 Method의 블록을 보기로만 보여 주는 기능이다. 접기 · 펴기 명령이 듣는 것에 호출 블록을 더한다. 지금의 규칙 → [[02-interaction-rules#호출 블록 펴 보기]], [[02-interaction-rules#펴 보인 곳의 접기 영역]]. 정한 과정은 [[2026-10-11-03-ux-review]]에 있다.

- **펴 보인 안쪽에서 접기 · 펴기. → 정함 (2026-10-13): 그것을 담은 가장 가까운 펴 보인 호출 블록이 접힌다.** 이 자리에서 만든 접기 영역 안이면 그 접기 영역이 먼저 접힌다.
- **펴 보인 곳의 접기 영역. → 정함 (2026-10-13).** 그 호출 블록 자리에만 생기고 Method의 원본은 그대로다.
	- **P1. 원본의 접기 영역과 가려 보이는가. → 정함: 똑같이 그린다 (1).**
	- **P2. Method가 바뀌어 묶어 둔 블록이 달라지면. → 정함: 남은 블록으로 줄어든다 (1).**
- **Q13. 펴 보인 블록을 고칠 수 있는가. → 정함 (2026-10-11): 고칠 수 없다 (E1).** 여기서 고치면 그 Method를 부르는 모든 곳이 함께 바뀌는데, 그것이 화면에서 보이지 않는다. 고르면 Method의 원래 블록으로 따라갈 수 있다.
- **Q14. 재귀. → 정함 (2026-10-11): 펴 보인 안쪽의 호출 블록도 펼 수 있다 (D2). 같은 Method가 세 번째로 펴지는 때부터 펼 때마다 알린다.** 다이어그램 자신을 첫 번째로 센다. 서로 다른 Method를 차례로 펴는 것은 재귀가 아니다(풀이는 확인받지 못함 → [[debt#확인해 주세요]]).
	- **Q14-a. 알림의 모양. → 정함 (2026-10-11): 먼저 펴고 알림 한 줄 (1).** 편집기에 입력을 막는 자리를 늘리지 않는다.
- **Q15. 펴진 접기 영역과 펴 보인 호출 블록의 모습. → 다시 정함 (2026-10-13): 접기 영역은 굵은 테두리 + 이름 띠, 펴 보인 호출 블록은 가는 점선 테두리 + 띠.** 2026-10-11의 "왼쪽 세로 막대"는 접기 영역이 겹치거나 이어질 때 알아보기 어려웠다. 접기 영역은 강조도 겸하므로 굵은 실선, 펴 보기는 강조가 아니므로 가는 점선.
	- **T1. 겹치거나 이어진 테두리 사이. → 정함 (2026-10-13): 틈을 둔다. 보통 블록은 테두리에 붙인다.** 모든 블록을 들이면 테두리와 블록의 선이 나란히 서서 호출 블록의 이중선처럼 보인다.
	- **T2. 펴 보인 호출 블록. → 정함 (2026-10-13): 가는 점선 테두리.** 띠만 두면 겹쳐 폈을 때 안쪽 호출 블록의 끝이 보이지 않는다.
	- **Q15-a. 둘을 가르는 법. → 다시 정함 (2026-10-13): 선의 모양과 색.** 흑백 인쇄에서도 실선과 점선으로 갈린다. 2026-10-11에는 "똑같이 그리고 색만 다르게"(C1)였다.
	- **Q15-b. While과 가르는 법. → 없어진 물음 (2026-10-13).** 사방을 두른 테두리는 While의 왼쪽 띠와 닮지 않았다.
	- **Q15-c. 이름 띠를 끄면. → 정함 (2026-10-11): 테두리도 함께 사라진다 (2).**
	- **Q15-d. 테두리의 색. → 다시 정함 (2026-10-17): 무채색.** 파랑이면 고른 표시와 섞여 고른 상자가 저장되는 테두리처럼 보였다(메인테이너가 시각 디자인을 Claude에게 맡김 → [[04-visual-design#원칙 3. 문서의 표시와 편집의 표시는 다른 층이다|원칙 3]]). 2026-10-11에는 짙은 파랑(1)이었다.
	- 굵기 · 색 · 치수의 값 → [[04-visual-design#6. 선]], [[04-visual-design#3.3 문서 팔레트 (기본)|3.3 문서 팔레트]]

### 4.2 호출 블록을 Method의 블록들로 바꾸기 (R5)

Q7의 "풀기"가 호출 블록에 듣는 경우다. Method로 빼기의 반대이고, 호출 블록 자리에 Method의 블록들이 복사되어 들어간다. 지금의 규칙 → [[02-interaction-rules#감싸기 · 풀기]]

- **Q16. 인자와 결과. → 정함 (2026-10-13): 글자는 그대로 복사한다.** 편집기는 글자 안을 검사하지 않으므로([[0022-call-name-follows-head|ADR-0022]]) Method 안의 이름(`a, lo, hi`)을 호출 블록의 인자(`a, lo, mid`)로 바꿔 적을 수 없다. 호출 블록에 적혀 있던 인자와 결과는 사라진다.
- **Q17. 이어진 곳이 없는 호출 블록. → 정함 (2026-10-13): 풀 수 없다.** 아무 일도 하지 않고 알린다.

## 5. 고르기 · 이동 · 접기 · Method

### Q10. 고를 수 있는 것의 목록

**정함 (2026-10-13): 2. 갈래의 이름도 고를 수 있다.** 갈래 전용 키를 줄이고, 지우기 · 옮기기가 갈래에도 듣게 하려는 것이다. 처음의 추천은 "갈래는 고를 수 없게 두고 지금 갈래로 대신한다"(1)였다(방향키가 멈추는 곳이 늘어 If · Case를 지나가기 번거로워진다는 까닭).

- 정하지 않은 것: If의 "참" · "거짓"에도 멈추는가, 위아래로 지나갈 때도 갈래 이름에 멈추는가, 갈래 전용 키(`+` `-`)를 없애는가. 프로토타입 리뷰 5판에서 그림으로 묻는다 → [[prototype#리뷰 순서]]
- 지금의 규칙 → [[02-interaction-rules#Case 블록]]

### Q11. 좌우 이동을 한 겹 줄이기

좌우로 가는 키가 세 겹이다: 옆 갈래, 한 겹 바깥의 옆 갈래, 옆 다이어그램([[03-keymap]]). 앞의 둘은 갈래의 끝에서만 다르다.

**추천: 1. 한 겹 바깥으로 가는 좌우 이동을 없애 두 겹으로.** 다만 지금의 세 겹은 2026-10-10에 써 보며 정한 것이라, 실제로 쓰였다면 지금대로(2)가 맞다. 정하지 않음 → UX 규칙 시안의 "Q11" 카드

### Q19. 언제나 무언가 골라져 있게 하기

처음 물음은 "화면에 포커스가 있으면 언제나 무언가 골라져 있게 하는가"였고 추천은 1(그렇게 한다)이었다. **2026-10-15에 고른 것을 푸는 방법(`Esc` 두 번, 빈 캔버스 클릭)이 생겨** 그 추천은 그대로 둘 수 없다.

**남은 물음: 명령이 끝난 뒤(지운 뒤 · 푼 뒤 · 실행 취소한 뒤) 무엇이 골라지는가.** 처음 추천의 나머지(만들거나 바꾼 것이 골라지고, 지운 뒤에는 다음 블록, 없으면 앞 블록)는 그대로 쓸 수 있다. 정하지 않음 → UX 규칙 시안의 "Q19" 카드

### Q20. 접기 · 펴기가 듣는 곳을 한 문장으로 (R6)

듣는 곳이 다섯 갈래이고, 놀랄 곳이 셋이다: 깊은 곳의 블록을 고르고 접으면 먼 바깥이 접히고, 제어 블록 하나로 만든 접기 영역은 그 블록을 골라서는 접을 수 없고, 큰 If 하나만 든 반복문은 접을 수 없다.

**추천: 1. 고른 것이 접을 수 있는 것이면 그것에, 아니면 그것을 담는 가장 가까운 접을 수 있는 것에 듣는다.** 제어 블록의 안쪽은 "이름 없는 접기 영역"으로 본다. "블록이 하나뿐이면 접지 않는다"는 처리 블록 하나일 때만 남긴다. 정하지 않음 → UX 규칙 시안의 "Q20" 카드

### Q21. Method가 없어질 때

**정함 (2026-10-13): 2. 지금대로 둔다.** 부르는 곳이 있는 Method를 Event로 바꾸는 것만 막고, 머리 떼기와 다이어그램 지우기는 허용한다(호출 블록은 끊긴 채 남는다). 처음의 추천은 "셋 다 허용"(1)이었다. 지금의 규칙 → [[02-interaction-rules#Method 머리]]

## 6. 이미 정한 것 가운데 처음 읽는 눈에 놀라웠던 곳

독립 검토(요구사항 문서와 용어집만 건네받은 다른 검토자)가 다시 물은 것이다. 까닭을 알고 정한 것이므로 **그대로 두는 것이 기본**이고, 사용자가 처음 만났을 때 놀랄 수 있는 곳의 목록으로 남긴다. → [[requirements-review#독립 검토와 같은 결론에 닿은 것]]

- **머리에서 괄호를 지우면 호출 블록의 인자가 사라지는 것.** 2026-10-13에 "기억하지 않는다"로 정했다. 같은 파일이 기기에 따라 다르게 되살아나지 않게 하려는 것이다.
- **인자 칸을 비울 수 없는 것.** Q4에서 공통 규칙의 한 경우가 되면 놀라움은 줄어든다.
- **접고 펴기가 실행 취소의 대상이 아닌 것.** 그림이 바뀌었는데 실행 취소가 듣지 않는다. 대신 "저장 안 됨" 표시는 뜬다(Q9).
- **붙여넣기가 고른 것을 바꿔 놓지 않고 뒤에 붙는 것.** 글자 편집기와 다르다. 구조 편집기에서는 뒤에 붙는 쪽이 안전하다고 보아 그대로 둔다.
- **새 Method가 맨 뒤에 생기고 화면이 그리로 가는 것.** 블록을 뺀 사용자가 보던 자리를 잃는다.
- **머리에서 좌우 이동이 옆 다이어그램으로 가는데, 다이어그램은 위에서 아래로 쌓이는 것.** 키의 방향과 화면의 방향이 맞지 않을 때가 있다.
