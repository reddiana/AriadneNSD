# ADR-0008: 선택은 같은 부모 아래 연속 범위

> [!NOTE] 이후 변경
> - 2026-10-10: 용어를 다시 바꿨다. "이름 붙은 범위"(한때 "이름 붙은 영역")는 지금의 **접기 영역**이다. 강조 영역을 없앤 뒤로 이 묶음의 쓰임이 접기뿐이고, 이름을 적지 않아도 생기기 때문이다 → [[06-glossary]]
> - 2026-10-10: 용어를 바꿨다. 이 문서의 "선택 범위"는 지금의 **선택 영역**, "이름 붙은 범위"는 **이름 붙은 영역**이다. 뜻은 같다 → [[06-glossary]]

## 배경

여러 블록을 선택해서 삭제·복사·이동하고, 제어 블록으로 감쌀 수 있어야 한다. ([[01-requirements#^edit-multiselect]], [[01-requirements#^edit-wrap]])
그런데 NS 차트는 트리 구조라서, 아무 블록이나 골라 묶으면 결과가 올바른 트리가 되지 않을 수 있다.

## 결정 기준

- 선택한 블록에 감싸기·이동을 적용한 결과가 항상 올바른 트리여야 한다. ([[01-requirements#^nfr-integrity]])
- 마우스와 키보드 모두 직관적으로 선택할 수 있어야 한다.

## 검토한 대안

### 자유 선택 (Ctrl+클릭으로 아무 블록이나)

- 장점: 일반 그림판과 같은 조작
- 단점: 떨어진 블록이나 다른 깊이의 블록을 감싸면 의미가 정의되지 않음

### 연속 범위만, 잘못된 선택은 거부

- 장점: 구현이 단순
- 단점: 다른 깊이를 Shift+클릭하면 아무 일도 일어나지 않아 답답함

### 연속 범위만, 다른 깊이는 공통 범위로 자동 확장

- 장점: 항상 올바른 선택, 사용자가 의도한 범위를 대부분 포함
- 단점: 사용자가 고른 것보다 넓게 선택될 수 있음

## 결정

선택은 항상 **같은 부모 아래 연속된 블록 범위**다.

- 끊긴 선택은 지원하지 않는다.
- Shift+클릭으로 다른 깊이의 블록을 고르면, 두 블록을 함께 포함하는 **가장 가까운 공통 범위로 자동 확장**한다.

## 결과

- 좋아지는 점: 감싸기·이동·삭제가 항상 올바른 트리를 만든다. 선택 상태를 `(부모, 시작 위치, 끝 위치)`로 단순하게 표현할 수 있다.
- 감수하는 점: 떨어진 블록을 한 번에 지우는 것 같은 동작은 할 수 없다.
- 후속 작업: 선택 상태와 확장 알고리즘 → [[03-editor]]
