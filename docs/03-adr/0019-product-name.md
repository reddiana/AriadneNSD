# ADR-0019: 제품 이름은 `AriadneNSD`, 식별자는 `ariadne-nsd`로 한다

> [!NOTE] 이후 변경
> - 2026-10-11: 문자 로고(그림)에서만 `Ariadne’s NSD`로 적는다. "Ariadne's Thread"(아리아드네의 실)를 떠올리게 하려는 것이다. 이 ADR에서 `Ariadne's NSD`를 고르지 않은 까닭(아포스트로피를 식별자에 쓸 수 없음)은 그림에는 해당하지 않는다. 글로 적는 제품 이름과 식별자는 이 ADR 그대로 `AriadneNSD` · `ariadne-nsd`다 → [[0020-logo|ADR-0020]]

## 배경

이 애플리케이션은 처음부터 `NSDrawing`이라는 임시 이름으로 불렸다. 메인테이너는 이 이름이 멋이 없다고 보고 `Ariadne`, `Ariadne's NSD`, `AriadneNSD`를 차례로 제안했다.

Ariadne(아리아드네)는 그리스 신화에서 테세우스가 미궁을 빠져나오도록 실을 건넨 사람이다. "얽힌 로직에서 길을 찾는다"는 뜻으로 읽을 수 있고, 겹겹이 중첩된 NS 차트의 상자 모양이 미궁 평면도와 닮았다.

이름은 저장소 주소, 패키지 이름, Obsidian 플러그인 id, 그리고 아직 정하지 않은 모델 네임스페이스 URI([[01-file-format#6. 미결정 사항]])에 들어간다. 코드가 아직 없는 지금이 바꾸는 비용이 가장 적다.

## 결정 기준

- 다른 제품과 헷갈리지 않아야 한다. 검색했을 때 이 제품이 나와야 한다.
- 저장소 이름, 패키지 이름, 플러그인 id, URL, 파일 이름에 그대로 쓸 수 있어야 한다.
- 무엇을 하는 도구인지 짐작할 실마리가 있어야 한다.
- 이야기와 로고로 이어 갈 수 있어야 한다.

## 검토한 대안

### `NSDrawing` (그대로)

- 장점: 바꿀 일이 없음. 무엇을 하는 도구인지 이름에 드러남
- 단점: 임시로 붙인 이름이고 메인테이너가 마음에 들어 하지 않음. 이야기나 로고로 이어 갈 것이 없음

### `Ariadne`

- 장점: 짧고 부르기 쉬움. 이야기와 로고에 가장 잘 맞음
- 단점: 이미 널리 쓰이는 이름. npm에 `ariadne` 패키지가 있고, Obsidian 커뮤니티 플러그인 목록에도 `Ariadne Autocomplete Accessibility`가 있음. 검색하면 신화와 다른 프로젝트가 먼저 나옴. 이름만으로는 무엇을 하는 도구인지 알 수 없음

### `Ariadne's NSD`

- 장점: 무엇의 도구인지 흔적이 남음
- 단점: 아포스트로피와 빈칸은 저장소 이름, 패키지 이름, 플러그인 id, URL에 쓸 수 없어 표기가 여러 가지로 갈림. 소유격이라 말로 부르기 어색함

### `AriadneNSD`

- 장점: 한 단어라 검색하면 이 제품만 나옴. 2026-10-10에 확인한 범위에서 겹치는 것이 없음(아래 "확인한 것"). 식별자 `ariadne-nsd`가 같은 이름에서 나옴. `NSD`가 붙어 있어 설명 문구와 함께 읽으면 무엇의 도구인지 알 수 있음
- 단점: 철자를 틀리기 쉬움(`Ariaden`, `Ariadna`). `NSD`는 널리 통하는 약어가 아님. 소문자로 붙여 쓴 `ariadnensd`는 읽기 어려움

## 결정

제품 이름을 `AriadneNSD`로 한다.

| 쓰이는 곳 | 이름 |
| --- | --- |
| 제품 이름 (화면, 문서, 로고) | `AriadneNSD` |
| 목록이나 제목에서 설명과 함께 쓸 때 | `AriadneNSD: NS Diagram Editor` |
| 저장소, 패키지, Obsidian 플러그인 id, 문서 태그 | `ariadne-nsd` |
| 확장자 `.ns` · `.ns.svg`, 모델 접두사 `nsd:` | 그대로 둔다 |

- 소문자로 붙여 쓴 `ariadnensd`는 쓰지 않는다. 붙임표를 쓸 수 없는 곳(예: 도메인)에서만 예외로 한다.
- 확장자와 모델 접두사는 "NS 차트"에서 온 것이라 제품 이름이 바뀌어도 그대로 둔다. ([[0006-file-extensions|ADR-0006]], [[0014-drive-file-extension|ADR-0014]])

### 확인한 것 (2026-10-10)

| 곳 | `ariadne-nsd` | `ariadnensd` |
| --- | --- | --- |
| npm 패키지 | 없음 | 없음 |
| PyPI, crates.io | 없음 | 없음 |
| GitHub 저장소 검색 | 0건 | 0건 |
| GitHub 사용자·조직 이름 | 없음 | 없음 |
| Obsidian 커뮤니티 플러그인 목록 | 없음 | 없음 |
| 도메인 `.com` | 등록 기록 없음 | 등록 기록 없음 |
| 도메인 `.app` `.dev` `.org` `.io` | (확인 안 함) | 등록 기록 없음 |

- 웹 검색에서 `AriadneNSD`나 `Ariadne NSD`라는 제품은 나오지 않았다. NS 차트 편집기 가운데 Ariadne라는 이름을 쓰는 것도 찾지 못했다.
- Obsidian 커뮤니티 플러그인 목록에는 NS 차트를 다루는 플러그인이 없었다.
- 확인하지 않은 것: 상표 등록. 도메인은 등록 기록(RDAP) 조회만 했고, `.io`는 이 조회가 믿을 만한지 알 수 없다. 실제로 살 수 있는지는 등록 업체에서 다시 봐야 한다.

## 결과

- 좋아지는 점: 고유한 이름이 생긴다. 이야기와 로고의 바탕이 생긴다. 모델 네임스페이스 URI를 정할 수 있게 된다.
- 감수하는 점: 문서 46개 파일에 나오는 `NSDrawing` · `nsdrawing`을 바꿔야 한다. 철자를 틀리는 사람이 생긴다.
- 후속 작업:
	- 문서 본문과 태그의 이름 바꾸기. 승인된 ADR은 본문을 두고 "이후 변경" 콜아웃으로 알린다. 세션 기록과 타임라인은 그때의 기록이므로 그대로 둔다.
	- GitHub 저장소 이름과 로컬 폴더 이름 바꾸기 (로컬 폴더를 바꾸면 Claude Code의 메모리 폴더도 옮긴다)
	- 모델 네임스페이스 URI 정하기 → [[01-file-format#6. 미결정 사항]]
	- 이름을 지키려면 npm 패키지 이름과 도메인을 미리 잡아 둘지 정하기
	- 로고 · 아이콘 · 파비콘 → [[inbox]]
