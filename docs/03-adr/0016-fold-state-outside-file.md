## 배경

제어 블록, 선택 범위, 강조 영역을 접고 펼 수 있다. ([[01-requirements#접기 · 펼치기]]) 다이어그램 여러 곳이 각각 접히거나 펼쳐져 있을 수 있다.
접힘 상태를 기억할지, 기억한다면 어디에 둘지, 저장되는 SVG 그림을 어떤 모양으로 그릴지 정해야 한다.

- 같은 모델이면 같은 파일이 나와야 한다. 불필요한 git diff를 막기 위해서다. ([[01-requirements#^fmt-deterministic]], [[01-requirements#^nfr-compat]])
- 노트에 넣은 그림은 플러그인 없이 이미지로 보인다. ([[01-requirements#^obs-embed]]) Obsidian과 GitHub은 SVG 안의 스크립트를 막으므로, 그림을 보는 사람은 접힌 칸을 펼 수 없다.

## 결정 기준

- 접고 펴기만 해서는 파일이 바뀌지 않아야 한다.
- 저장된 그림만 보는 사람도 전체 로직을 볼 수 있어야 한다.
- 다시 열었을 때 접어 둔 상태가 돌아오면 좋다. 큰 다이어그램을 매번 다시 접지 않도록.

## 검토한 대안

### A. 기억하지 않음, 그림은 펼친 모양

- 장점: 가장 단순하다. 파일이 접기와 무관하다.
- 단점: 다시 열면 모두 펼쳐져 있다.

### B. 모델에 저장, 그림도 접힌 모양

- 장점: 화면 그대로 저장된다. 문서에 요약된 그림을 넣을 수 있다.
- 단점: 접고 펴기만 해도 파일과 노트의 그림이 바뀐다. 그림을 보는 사람은 접힌 내용을 볼 방법이 없다.

### C. 모델에 저장, 그림은 펼친 모양

- 장점: 다시 열면 접힘이 돌아온다. 그림은 늘 전체를 보여 준다.
- 단점: 그림은 그대로인데 파일이 바뀐다.

### D. 파일 밖(편집기의 보기 상태)에 기억, 그림은 펼친 모양

- 장점: 파일이 접기와 무관하다. 다시 열면 접힘이 돌아온다. IDE가 코드 접기를 기억하는 방식과 같다.
- 단점: 다른 기기나 다른 배포 대상에서 열면 접힘이 돌아오지 않는다. 파일 이름을 바꾸면 잃을 수 있다.

## 결정

D. 접힘 상태는 모델과 파일에 저장하지 않는다.

- 저장되는 SVG 그림은 항상 모두 펼친 모양이다.
- 편집기는 파일별 접힘 상태를 배포 대상마다 자기 저장소에 기억한다 (Obsidian: 플러그인 데이터, 웹: 브라우저 저장소, 데스크톱: 앱 설정).
- 접힌 모양의 그림이 필요하면, 지금 화면의 접힘 그대로 PNG로 내보낸다. ([[01-requirements#^exp-png-folded]]) 발표나 문서에서 설명하는 부분에 집중하게 할 때 쓴다.

## 결과

- 좋아지는 점: 접기가 파일 형식과 git diff에 영향을 주지 않는다. 모델에 보기 상태가 섞이지 않는다.
- 감수하는 점: 접힘은 기기와 배포 대상을 넘어 옮겨지지 않는다. 문서에 넣는 접힌 그림은 편집 가능한 원본이 아니라 PNG다.
- 후속 작업: 접기 이름(요약 글)은 모델에 저장할지 정해야 한다. 이름은 접힘 상태가 아니라 내용에 가깝다. 설계 문서 [[03-editor]]에 보기 상태 저장 방식 추가
