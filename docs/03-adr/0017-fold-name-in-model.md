# ADR-0017: 접는 범위의 이름은 모델에 저장한다

> [!NOTE] 이후 변경
> - 2026-10-10: 접히는 것을 접기 영역 하나로 줄였다. 제어 블록을 고르고 접으면 그 안의 갈래마다 접기 영역이 만들어져 접힌다. 이 문서에서 "제어 블록의 접힘"을 따로 말하는 부분은 지금은 접기 영역의 접힘과 같은 것이다 → [[01-requirements#접기 · 펼치기]]
> - 2026-10-10: 용어를 다시 바꿨다. "이름 붙은 범위"(한때 "이름 붙은 영역")는 지금의 **접기 영역**이다. 강조 영역을 없앤 뒤로 이 묶음의 쓰임이 접기뿐이고, 이름을 적지 않아도 생기기 때문이다 → [[06-glossary]]
> - 2026-10-10: 강조 영역 요구사항을 없앴다. "강조 영역의 이름은 강조 영역에 저장한다"는 지금 해당하지 않는다. 이름은 모두 접기 영역에 저장한다 → [[0015-highlight-region-border|ADR-0015]]
> - 2026-10-10: 용어를 바꿨다. 이 문서의 "선택 범위"는 지금의 **선택 영역**, "이름 붙은 범위"는 **이름 붙은 영역**이다. 뜻은 같다 → [[06-glossary]]

## 배경

선택 범위를 접으면 그 칸에 이름이 보이고, 이름은 처음 접을 때 묻는다. ([[01-requirements#^edit-fold-range]])
[[0016-fold-state-outside-file|ADR-0016]]은 접힘 상태를 파일 밖에 두기로 하고, 이름을 어디에 둘지는 후속 결정으로 남겼다.

이름은 "지금 접혀 있다"는 보기 상태가 아니다. "이 블록들은 무엇을 한다"는 내용에 가깝다.

## 결정 기준

- 다른 기기나 다른 배포 대상에서 열어도 이름이 남아야 한다.
- 접고 펴기만 해서는 파일이 바뀌지 않아야 한다. ([[0016-fold-state-outside-file|ADR-0016]])

## 검토한 대안

### 파일 밖에 접힘 상태와 함께 둔다

- 장점: 모델이 그대로다.
- 단점: 다른 기기에서 열면 이름을 잃는다. 사용자가 적은 내용이 파일에 남지 않는다.

### 모델에 저장한다

- 장점: 이름이 파일과 함께 다닌다.
- 단점: 강조하지 않은 선택 범위에 이름을 붙이려면, 모델에 "이름 붙은 범위"라는 개념이 새로 생긴다.

## 결정

접는 범위의 이름은 모델에 저장한다.

- 강조 영역의 이름은 강조 영역에 저장한다.
- 강조하지 않은 선택 범위에 이름을 붙이면, 모델에 **이름 붙은 범위**가 생긴다. 범위 규칙은 선택 범위와 같다(같은 부모 아래 연속된 블록들). → [[0008-contiguous-selection|ADR-0008]]
- 이름을 붙이거나 바꾸면 파일이 바뀐다. 접고 펴는 것은 여전히 파일을 바꾸지 않는다.

## 결과

- 좋아지는 점: 이름이 어디서 열어도 남는다.
- 감수하는 점: 모델이 블록 트리 외에 "범위"를 다뤄야 한다. 범위 안의 블록을 지우거나 옮길 때 범위를 어떻게 고칠지 정해야 한다.
- 후속 작업: 설계 문서 [[01-model]]에 이름 붙은 범위와 강조 영역의 표현, 편집할 때 범위를 고치는 규칙 추가. 파일 형식 [[01-file-format]]에 반영
