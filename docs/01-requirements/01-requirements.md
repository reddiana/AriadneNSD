# 요구사항

NS 차트(Nassi-Shneiderman Diagram)를 그리는 프로그램의 요구사항입니다. 이 문서는 **무엇을** 만드는지만 다룹니다. 요구사항 하나는 한두 줄입니다.
그 기능이 **사용자에게 어떻게 보이고 어떤 규칙으로 움직이는지**는 UX 설계([[01-ux-overview]], [[02-interaction-rules]])에(결정은 → [[ux-decisions|UX 결정 모음]]), **왜** 그렇게 정했는지는 [[atelier/adr/README|ADR]]에, **어떻게** 만드는지는 [[03-architecture]]와 상세 설계 문서에 있습니다.

> [!info] 읽는 법
> - 우선순위: `P0` = 필수 · `P1` = 1차 확장 · `P2` = 나중에 · `P3` = 웹 베타 뒤. 요구사항 표의 "우선순위" 칸에 적습니다. 우선순위는 **기능의 우선순위**입니다. `P0`은 "그 배포 대상을 낼 때 꼭 있어야 하는 것"이고, 배포 대상을 내는 순서(웹 → Obsidian → 데스크톱)는 [[dr-0002-development-order|DR-0002]]가 정합니다. MVP는 웹의 `P0`입니다([[#5. MVP 범위]], [[dr-0015-mvp-scope|DR-0015]]).
> - 우선순위는 Obsidian 태그(`#P0`)로 달지 않습니다. 태그는 문서에 붙는 것이기 때문입니다(2026-11-01부터, 그 전에는 태그였습니다). `P0`만 모아 본 목록은 [[#5. MVP 범위]]입니다.
> - 요구사항 끝의 "→ 상세"는 그 기능의 세부 규칙이 적힌 설계 문서로 갑니다.
> - 기능들이 이어지는 사용자의 흐름은 [[02-use-cases|유즈케이스]]에 있습니다.
> - 요구사항마다 ID(`R-WEB-02`: `R-`, 영역, 번호)가 있습니다. 다른 문서는 `[[01-requirements#^r-web|R-WEB-02]]`처럼 그 요구사항이 든 표(`^r-web`)를 가리키고, 링크에 보이는 글자는 ID입니다. Obsidian에서는 링크가 그 표로 가고(링크에 마우스를 올리면(호버) 표가 미리 보입니다), 배포한 사이트에서는 그 줄로 바로 갑니다. Obsidian은 표의 한 줄을 가리키지 못합니다 → [[dr-0016-requirement-ids|DR-0016]]
> - ID는 바뀌지 않습니다. 새 요구사항은 그 영역의 다음 번호를 받습니다. 철회한 요구사항은 이 문서에서 지우고 [[requirement-changes|요구사항 변경 기록]]에 남기며, 그 번호는 다시 쓰지 않습니다.
> - 영역: `CORE` 핵심 원칙 · `TGT` 배포 대상 · `ALL` 모든 배포 대상 · `OBS` Obsidian · `DSK` 데스크톱 · `WEB` 웹 · `GD` Google Drive · `CF` Confluence · `SKILL` Claude skill · `IDE` IDE 플러그인 · `BLK` 블록 · `EDIT` 편집 · `LAY` 레이아웃 · `FMT` 파일 형식 · `EXP` 내보내기 · 가져오기 · `CODE` 코드 연동 · `REP` 문제 알리기 · `NFR` 비기능

## 1. 핵심 원칙

| ID | 원칙 |
| --- | --- |
| R-CORE-01 | NS 차트는 **트리 구조**다. 이 프로그램은 도형을 자유롭게 배치하는 그림판이 아니라, **구조를 편집하면 그림이 자동으로 그려지는 편집기**다. 사용자는 좌표를 직접 다루지 않는다. → [[0004-structure-editor\|ADR-0004]] |
| R-CORE-02 | 구조적으로 잘못된 차트(예: 반복문 밖으로 튀어나온 블록)는 만들 수 없어야 한다. |
| R-CORE-03 | **주 사용자는 실무에서 설계 문서를 쓰는 사람이다.** 코드와 함께 두는 문서, PDF와 인쇄의 품질을 앞에 둔다. 교육용 기능(실행 애니메이션 등)은 그 뒤다. |
| R-CORE-04 | **저장 파일 하나가 그림이자 원본이다.** 파일은 어디서나 열리는 SVG 이미지이고, 그 안에 다이어그램 모델이 함께 들어 있어 다시 열어 편집할 수 있다. → [[0005-model-embedded-svg\|ADR-0005]] |

### 2.1 Obsidian 플러그인

사용 흐름은 drawio-obsidian 플러그인과 같다. 노트에서 바로 다이어그램을 삽입하고, 삽입한 그림에서 바로 편집한다.

```mermaid
flowchart LR
    A["노트 편집 중<br/>우클릭"] -->|Insert new NS diagram| B["NS 편집 탭 열림<br/>(새 .ns.svg 파일)"]
    B -->|편집 후 탭 닫기| C["노트의 커서 위치에<br/>![[이름.ns.svg]] 삽입"]
    C -->|삽입된 그림 우클릭<br/>Edit NS diagram| D["NS 편집 탭 열림"]
    D -->|편집 후 탭 닫기| E["노트의 그림이<br/>새 내용으로 갱신"]
```

**노트에서 삽입 · 편집하기**

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| R-OBS-01 | 노트 편집 화면의 컨텍스트 메뉴에 **"Insert new NS diagram"** 항목<br>· 누르면 새 `.ns.svg` 파일을 만들고 NS 편집 탭을 연다.<br>· 편집을 마치고 탭을 닫으면, 우클릭했던 노트의 커서 위치에 `![[이름.ns.svg]]`를 삽입한다. | P0  |
| R-OBS-02 | 노트에 삽입된 NS 다이어그램 그림의 컨텍스트 메뉴에 **"Edit NS diagram"** 항목<br>· 누르면 해당 파일을 NS 편집 탭으로 연다.<br>· 저장하면 노트에 보이는 그림도 새 내용으로 갱신된다. | P0  |
| R-OBS-03 | 같은 기능을 Obsidian의 명령 팔레트(Command palette)에서도 실행 ("Insert new NS diagram") | P0  |

### 5.1 MVP 다음의 단계

웹은 MVP → 웹 베타 → 웹 1.0을 거칩니다 → [[dr-0018-release-stages|DR-0018]]

| 단계 | 버전 | 누구에게 | 저장한 파일 |
| --- | --- | --- | --- |
| MVP (지금) | `0.1.0`부터 | 링크를 아는 사람 | 형식이 바뀌면 뒤의 판에서 열리지 않을 수 있다 |
| 웹 베타 | `0.y` | 널리 알린다 | 같음 |

- Obsidian 플러그인은 웹 베타 동안 베타로 시작하고(BRAT로 설치), 커뮤니티 플러그인 목록에는 웹 1.0 뒤에 올린다. 데스크톱은 그 뒤다
- 버전은 SemVer이며, 파일 형식의 버전([[01-file-format#5. 버전 관리]])과 따로 간다

- [ ] **블록 텍스트가 지원하는 문자:** 기본 블록 글꼴(D2Coding)은 라틴 · 유럽 확장, 한글, 그리스, 키릴, 가나를 싣는다([[0034-default-block-font|ADR-0034]]). 사용자는 한국어 사용자로 국한하지 않는다. 이 밖의 문자(한자, 베트남어, 아랍 · 태국 문자, 이모지)를 블록 텍스트에서 어디까지 지원할지, 문서마다 글꼴을 선택하게 할지(예: 중국어 · 일본어용 글꼴 묶음)
- [ ] **Event를 일으키는 블록:** 호출 블록은 Method만 호출한다([[0021-event-and-method|ADR-0021]]). 다이어그램 안에서 다른 Event를 일으키는 일(신호 보내기)을 그릴 블록이 따로 필요한지 → [[#^r-blk|R-BLK-07]]
- [ ] **IDE 플러그인이 다루는 언어와 왕복:** 처음에 지원할 언어의 목록. 코드에는 있고 NS 다이어그램에는 없는 것(주석, 선언, 예외 처리, `break` · `continue`)을 다이어그램에 어떻게 보이고, 다이어그램을 편집한 뒤에도 코드에 어떻게 남기는지 → [[#2.7 IDE 플러그인 (나중에)]]
- [ ] **논리 · 물리 뷰의 범위:** 지금의 블록 글자(`text`)를 논리로 볼지 물리로 볼지, 코드에서 가져온 블록의 설명 문장을 코드의 어디(주석 등)에 남길지, 웹 · Obsidian · 데스크톱에서도 두 얼굴을 둘지 → [[#^r-ide|R-IDE-08]]
- [ ] **AI 대화창의 키 보관:** 브라우저 저장소에 둔 API 키는 같은 페이지에서 도는 다른 스크립트(광고 [[#^r-web|R-WEB-08]])가 읽을 수 있다. 광고와 한 페이지에 두어도 되는지, 탭을 닫으면 잊는 보관을 선택할 수 있게 할지 → [[#^r-web|R-WEB-07]]
- [ ] **쓰이지 않는 Method:** 아무도 호출하지 않는 Method를 화면에서 알려 줄지 → [[#^r-blk|R-BLK-11]]
- [ ] **`nschart` 코드 블록의 문법:** YAML, 의사 코드(`if … else … end`), id를 뺀 JSON 가운데 무엇으로 쓸지. YAML은 짧지만 `yes` · `no` 같은 키를 YAML 1.1 파서가 참 · 거짓으로 읽고, 의사 코드는 블록 글자에 `end` 같은 말이 들어갈 때의 규칙이 필요하다. 어느 쪽이든 블록의 id와 뷰 상태는 적지 않는다 → [[#^r-fmt|R-FMT-12]]
- [ ] **웹 광고의 자리:** 광고 네트워크(예: Google AdSense)는 팝업·대화 상자 안의 광고를 정책으로 막는 경우가 많다. 저장·내보내기·공유 때만 보이게 하는 방식([[#^r-web|R-WEB-08]])을 네트워크가 허용하는지, 허용하지 않으면 광고를 어디에 둘지
