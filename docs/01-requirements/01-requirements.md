# NSDrawing 요구사항 명세

NS 차트(Nassi-Shneiderman Diagram)를 그리는 프로그램의 요구사항입니다. 이 문서는 **무엇을** 만드는지만 다룹니다.
**왜** 그렇게 정했는지는 [[docs/README#아키텍처 결정 기록 (ADR)|ADR]]에, **어떻게** 만드는지는 [[02-architecture]]와 설계 문서에 있습니다.

> [!info] 읽는 법
> - 우선순위 태그: #P0 = MVP 필수 · #P1 = 1차 확장 · #P2 = 나중에 · #P3 = 언젠가 (하면 좋음)
> - 태그를 클릭하면 해당 우선순위 항목만 모아 볼 수 있습니다.
> - 각 요구사항은 체크박스입니다. 구현이 끝나면 체크해서 진행 상황을 관리하세요.
> - 각 요구사항 끝의 `^id`는 블록 ID입니다. 다른 문서에서 `[[01-requirements#^edit-wrap]]`처럼 해당 항목을 직접 가리킬 수 있습니다.

## 1. 핵심 원칙

- NS 차트는 **트리 구조**다. 이 프로그램은 도형을 자유롭게 배치하는 그림판이 아니라, **구조를 편집하면 그림이 자동으로 그려지는 편집기**다. 사용자는 좌표를 직접 다루지 않는다. → [[0004-structure-editor|ADR-0004]]
- 구조적으로 잘못된 차트(예: 반복문 밖으로 튀어나온 블록)는 만들 수 없어야 한다.
- **저장 파일 하나가 그림이자 원본이다.** 파일은 어디서나 열리는 SVG 이미지이고, 그 안에 다이어그램 모델이 함께 들어 있어 다시 열어 편집할 수 있다. → [[0005-model-embedded-svg|ADR-0005]]

## 2. 배포 대상

세 가지 형태로 배포한다. → [[0002-three-targets-shared-core|ADR-0002]], [[0006-file-extensions|ADR-0006]]

| 배포 대상 | 저장 확장자 | 파일 내용 |
| --- | --- | --- |
| Obsidian 플러그인 | `.ns.svg` | 다이어그램 모델이 포함된 SVG |
| 데스크톱 애플리케이션 | `.ns` | 다이어그램 모델이 포함된 SVG |
| 웹 (정적 페이지) | `.ns` | 다이어그램 모델이 포함된 SVG |

세 대상의 파일 내용은 **동일한 형식**이다. `.ns` ↔ `.ns.svg`는 뒤에 `.svg`를 붙이거나 떼는 것만으로 서로 열 수 있다.

모든 무료 배포 대상에 공통:

- [ ] #P3 후원 링크(Buy Me a Coffee): 편집을 방해하지 않는 자리에 둔다 ^all-donate
	- 웹: 광고([[#^web-ads]])와 같은 때(저장·내보내기·공유) 함께 보인다
	- Obsidian: 플러그인 manifest의 `fundingUrl`에 적는다 (커뮤니티 플러그인 화면에 후원 버튼이 보인다)
	- 데스크톱: 도움말·정보 창에 둔다

### 2.1 Obsidian 플러그인

사용 흐름은 drawio-obsidian 플러그인과 같다. 노트에서 바로 다이어그램을 넣고, 넣은 그림에서 바로 편집한다.

```mermaid
flowchart LR
    A["노트 편집 중<br/>우클릭"] -->|Insert new NS diagram| B["NS 편집 탭 열림<br/>(새 .ns.svg 파일)"]
    B -->|편집 후 탭 닫기| C["노트의 커서 위치에<br/>![[이름.ns.svg]] 삽입"]
    C -->|삽입된 그림 우클릭<br/>Edit NS diagram| D["NS 편집 탭 열림"]
    D -->|편집 후 탭 닫기| E["노트의 그림이<br/>새 내용으로 갱신"]
```

**노트에서 넣기 · 편집하기**

- [ ] #P0 노트 편집 화면의 우클릭 메뉴에 **"Insert new NS diagram"** 항목 ^obs-insert
	- 누르면 새 `.ns.svg` 파일을 만들고 NS 편집 탭을 연다.
	- 편집을 마치고 탭을 닫으면, 우클릭했던 노트의 커서 위치에 `![[이름.ns.svg]]`를 삽입한다.
- [ ] #P0 노트에 삽입된 NS 다이어그램 그림의 우클릭 메뉴에 **"Edit NS diagram"** 항목 ^obs-edit-embed
	- 누르면 해당 파일을 NS 편집 탭으로 연다.
	- 저장하면 노트에 보이는 그림도 새 내용으로 갱신된다.
	- Obsidian의 기존 우클릭 메뉴는 그대로 두고 이 항목만 더한다. 자리는 "이미지 삭제" 바로 위 구역의 맨 아래("파일 탐색기에서 파일 보기" 아래)다.
	- 파일 목록에서 `.ns.svg`를 우클릭해도 같은 항목이 나온다. 자리는 "삭제" 바로 위 구역의 맨 아래("폴더에서 보기" 아래)다.
- [ ] #P0 같은 기능을 명령 팔레트에서도 실행 ("Insert new NS diagram") ^obs-insert-command
- [ ] #P0 편집을 마치면, 그 그림을 넣은 노트가 이미 열려 있어도 다시 열지 않고 새 그림으로 보인다. 같은 그림을 넣은 다른 열린 노트도 마찬가지다. ^obs-refresh
	- drawio-obsidian은 편집을 마쳐도 노트를 다시 열어야 바뀐 그림이 보인다. 사용자는 이 때문에 [obsidian-refresh-any-view](https://github.com/mnaoumov/obsidian-refresh-any-view) 플러그인을 따로 쓰고 있다. NSDrawing은 별도 플러그인 없이 갱신되어야 한다.

**파일 다루기**

- [ ] #P0 파일 이름이 `.ns.svg`로 끝나는 파일을 파일 탐색기에서 열면 NS 편집 탭으로 열기 ^obs-open
- [ ] #P0 그 밖의 일반 `.svg` 파일은 건드리지 않고 Obsidian 기본 동작으로 열기 ^obs-plain-svg
- [ ] #P0 노트에 삽입된 `![[이름.ns.svg]]`는 플러그인이 없어도 그림으로 보임 ^obs-embed
- [ ] #P1 파일 탐색기 우클릭 메뉴에서 새 NS 다이어그램 만들기 (노트에 삽입하지 않음) ^obs-new
- [ ] #P1 이름 변경으로 `.ns`가 빠졌지만 모델이 들어 있는 `.svg` 파일은 내용으로 감지해서 "Edit NS diagram" 메뉴 제공 ^obs-detect

**화면**

- [ ] #P1 Obsidian 라이트/다크 테마에 맞춰 편집 화면 표시 (저장되는 SVG의 색상은 테마 설정을 따름) ^obs-theme

> [!question] 정해야 할 세부 사항 → [[04-obsidian-plugin]]
> - 새 파일의 이름과 저장 위치 (제안: Obsidian의 "첨부 파일 폴더" 설정을 따르고, 이름은 `노트이름-diagram-1.ns.svg`처럼 자동 생성)
> - 아무것도 그리지 않고 탭을 닫았을 때 (제안: 파일을 지우고 노트에 삽입하지 않음)
> - 편집 중 저장 시점 (탭을 닫을 때만 / 편집할 때마다 자동 저장)

## 3. 기능 요구사항

### 3.1 블록 종류

DIN 66261 / 원 논문 기준입니다.

| 블록 | 설명 | 우선순위 |
| --- | --- | --- |
| 처리 (Process) | 한 단계의 명령 | #P0 |
| 선택 (If-Then-Else) | 역삼각형 헤더와 참/거짓 두 칸 | #P0 |
| 전위 판정 반복 (While) | 조건을 먼저 검사, 왼쪽 띠 안에 본문 | #P0 |
| 후위 판정 반복 (Do-While / Repeat-Until) | 조건이 아래쪽에 위치 | #P0 |
| 다중 선택 (Switch/Case) | 여러 갈래 + default | #P1 |
| 횟수 반복 (For) | While의 변형 | #P1 |
| 호출 (Call) | 양옆 세로 이중선. 같은 문서의 다른 다이어그램을 부른다 (아래 [[#^blk-call]]) | #P1 |
| 탈출 (Exit / Break / Return) | 반복·함수 탈출 | #P2 |
| 병렬 처리 (Parallel) | 동시 실행 갈래 | #P2 |
| 주석 블록 |  | #P2 |

- [ ] #P1 이벤트 머리 블록: 다이어그램 맨 위에 "버튼을 누르면", "타이머가 끝나면" 같은 이벤트를 다는 모자 모양 머리. NS 차트 표준에는 없고 [Scratch](https://scratch.mit.edu/)에서 가져온 표기다 ^blk-event
	- 임베디드 개발에서 이벤트는 곧 인터럽트 처리기다. 다이어그램 하나가 처리기 하나를 나타낸다.
	- 한 문서 안에서 머리의 이름은 겹칠 수 없고 비울 수도 없다. 앞뒤 빈칸은 무시하고 비교하며, 대문자와 소문자는 구분한다. 겹치거나 빈 이름을 적으면 받아들이지 않고 고치던 칸을 다시 연다.
	- 새 머리에는 겹치지 않는 기본 이름("이벤트 1", "이벤트 2" …)이 미리 들어가고, 바로 이름을 고칠 수 있게 선택된 채로 열린다. Enter나 Esc를 누르면 기본 이름 그대로 둔다.
- [ ] #P1 호출 블록: 같은 문서의 다른 다이어그램을 부른다. 이벤트를 일으키는 호출(이벤트 처리기를 부름)과 Method 호출(이름 붙은 다이어그램을 부름)에 쓴다. NS 차트 표준의 서브루틴 호출 표기(양옆 세로 이중선)로 그린다 ^blk-call
	- 호출 블록은 부르는 다이어그램과 이어져 있다. 그 다이어그램의 머리 글자가 호출 블록에 보인다. 머리 글자를 고치면 그것을 부르는 호출 블록의 글자도 모두 바뀐다.
	- 호출 블록의 글자는 직접 고치지 않는다. 호출 블록을 고치려 하면(Enter · F2 · 더블클릭) 부를 다이어그램을 목록에서 고른다. 목록에는 머리가 있는 다이어그램이 모두 나오고(자기 자신 포함), "새 다이어그램을 만들고 호출"도 있다.
	- 머리가 없는 다이어그램은 부를 수 없다.
	- 부르던 다이어그램이 지워지면 호출 블록은 남고, 이어진 곳이 없다는 표시가 보인다.

### 3.2 편집

- [ ] #P0 블록 선택, 추가(선택 블록의 앞/뒤/안쪽), 삭제, 텍스트 수정(더블클릭 또는 F2) ^edit-basic
- [ ] #P0 실행 취소 / 다시 실행 (Undo/Redo) ^edit-undo
- [ ] #P0 키보드만으로 편집 가능: 방향키로 이동, 단축키로 블록 삽입 ^edit-keyboard
	- 블록은 고른 블록 **뒤에** 넣는다. `Shift`를 같이 누르면 **앞에** 넣는다. 넣을 위치를 따로 고르는 상태(모드)는 두지 않는다. 제어 블록 안에 넣으려면 안쪽 블록을 고르고 넣는다.
	- 빈 블록을 골랐으면 그 자리에 넣는다. 처리 블록이면 그 빈 블록에 바로 글자를 적고, 제어 블록이면 빈 블록을 그 제어 블록으로 바꾼다.
	- `↑` `↓`는 그림에 보이는 순서대로 움직인다.
	- `Ctrl`+`↑` `↓`는 제어 블록을 안쪽까지 한 덩어리로 보고 같은 줄의 위·아래 블록으로 간다. 제어 블록 안으로 들어가지 않고 제어 블록 전체를 고른다. 갈래의 첫 블록에서 `Ctrl`+`↑`는 담고 있는 제어 블록 전체를 고르고, 마지막 블록에서 `Ctrl`+`↓`는 담고 있는 제어 블록의 다음 블록으로 간다.
	- `Ctrl`+`←` `→`는 지금 블록을 담은 가장 가까운 If·Case의 옆 갈래 첫 블록으로 간다. 그쪽에 갈래가 더 없으면 한 겹 바깥 If·Case의 옆 갈래로 가고, 바깥에도 없으면 움직이지 않는다. If·Case 안이 아니면 위·아래 블록으로 간다.
	- 키보드로 캔버스에 들어왔을 때 고른 블록이 없으면 첫 블록(머리가 있으면 머리)을 자동으로 고른다. 캔버스 둘레에 포커스 선을 그리지 않고, 고른 블록의 테두리로 "지금 여기"를 보여 준다.
	- 방향키는 다이어그램 밖으로 나가지 않는다. 옆 다이어그램으로는 이벤트 머리에서 `←` `→`, 또는 어디서든 `Ctrl`+`Shift`+`←` `→`로 간다. "옆"은 다이어그램의 순서를 따른다. 옮겨 가면 그 다이어그램의 머리(없으면 첫 블록)를 고른다.
	- `←` `→`는 If·Case의 갈래를 건넌다. 옆 갈래가 있으면 그 갈래의 첫 블록으로 간다. 맨 왼쪽 갈래에서 `←`는 그 제어 블록(위쪽 바깥 블록)으로, 맨 오른쪽 갈래에서 `→`는 그 제어 블록의 다음 블록(아래쪽 바깥 블록)으로 간다. 갈래의 어느 블록에서든 같다.
	- 갈래 안의 제어 블록에서도 `→`는 옆 갈래로 간다. 제어 블록 안으로는 `↓`로 들어간다.

#### 여러 블록 선택 규칙

→ [[0008-contiguous-selection|ADR-0008]]

선택은 항상 **같은 부모 아래에서 연속으로 붙어 있는 블록 범위**다.

- 끊긴 선택(Ctrl+클릭으로 띄엄띄엄 고르기)은 지원하지 않는다.
- Shift+클릭으로 다른 깊이의 블록을 고르면, 두 블록을 함께 포함하는 **가장 가까운 공통 범위로 자동 확장**한다.

> [!example]- 자동 확장 예시 (클릭해서 펼치기)
> `A` 를 선택한 상태에서, `B` 아래에 있는 While 안쪽의 `C` 를 Shift+클릭하면
> → `A`와 `C`가 모두 들어가는 가장 가까운 범위인 **`A` ~ While 블록 전체**가 선택된다.
> ```
> A        ◀ 처음 선택
> B
> while
>   C      ◀ Shift+클릭
> D
> ```

#### 감싸기 · 풀기

선택한 블록들을 새 제어 블록 안에 넣는다 (IDE의 "Surround With"와 같은 기능).

| 감싸는 블록                  | 선택 블록이 들어가는 곳              | 비고                |
| ----------------------- | -------------------------- | ----------------- |
| While                   | 본문                         |                   |
| Do-While / Repeat-Until | 본문                         |                   |
| For                     | 본문                         | For 블록(#P1) 구현 후  |
| If-Then-Else            | 참 갈래 (거짓 갈래는 빈 처리 블록)      |                   |
| Switch/Case             | 첫 번째 갈래 (default는 빈 처리 블록) | Case 블록(#P1) 구현 후 |

- 감싼 제어 블록은 선택 영역이 있던 자리에 놓인다.
- 감싼 직후 조건 텍스트를 바로 입력할 수 있도록 편집 상태로 둔다.
- 감싸기와 풀기는 각각 **실행 취소 한 번**으로 되돌릴 수 있다.
- 풀기: 갈래가 여러 개인 블록(If, Case)을 풀 때는 내용이 있는 갈래들을 순서대로 이어 붙인다.
- 실행 방법: 단축키, 우클릭 메뉴, 도구 모음 모두 지원한다.

#### 접기 · 펼치기

접히는 것은 **접기 영역** 하나뿐이다. 제어 블록을 접는 것도 접기 영역으로 한다. ([[#^edit-fold]], [[#^edit-fold-range]])

- 접기 영역은 같은 부모 아래 연속된 블록들의 묶음이다. 접으면 한 칸으로 줄고 그 칸에 이름이 보인다. 펼쳐도 접기 영역은 남아 있어서 다시 접을 수 있다.
- 명령은 셋이다: **접기 영역 만들기**(`Shift`+`F`), **접기 · 펴기**(`F`), **접기 영역 풀기**(`Ctrl`+`Shift`+`F`).
- 만들기: 고른 블록들을 접기 영역으로 묶고, 바로 접으면서 이름을 묻는다.
	- 블록 하나만으로는 만들지 않는다 (제어 블록 하나는 된다).
	- 접기 영역은 중첩할 수 있다. 접기 영역 안의 블록들을 골라 또 만들 수 있다. 같은 범위에 겹쳐 만들 수는 없다.
- 접기 · 펴기는 고른 것에 따라 듣는 곳이 정해진다.
	- 접기 영역(접힌 칸)을 골랐으면 그 접기 영역.
	- 제어 블록 하나를 골랐으면 그 안의 **갈래마다 접기 영역**. 갈래 전체가 이미 접기 영역 하나이면 그것을 쓰고, 아니면 갈래 전체를 접기 영역으로 만든다. 블록이 하나뿐인 갈래는 그대로 둔다. 한 번에 여러 갈래가 접기 영역이 될 때는 이름을 묻지 않는다.
	- 그 밖에는 **고른 것을 온전히 담는 가장 작은 접기 영역**. 접기 영역 안의 블록 하나만 골라도, 그 안쪽 깊은 곳(제어 블록 안)의 블록을 골라도 된다.
	- 해당하는 접기 영역이 없으면 아무 일도 하지 않는다. 접기 · 펴기는 위의 제어 블록 경우 말고는 접기 영역을 새로 만들지 않는다.
- 풀기: 고른 것을 온전히 담는 가장 작은 접기 영역을 없앤다. 접혔든 펴졌든 영역과 이름만 사라지고 블록은 그대로 남는다. 제어 블록 풀기([[#^edit-wrap]], `U`)와는 다른 명령이다.
- 이름
	- 접기 영역에는 이름(요약 글)을 붙일 수 있다. 이름이 없으면 "첫 블록 글자 외 n개"가 보인다.
	- 이름은 파일에 저장한다. 다른 기기에서 열어도 남는다. → [[0017-fold-name-in-model|ADR-0017]]
	- 이름은 **접기 영역을 만들 때** 묻는다. 대화상자를 띄우지 않고, 접힌 칸 안에서 바로 고칠 수 있게 한다. 기본값 "첫 블록 글자 외 n개"가 선택된 상태로 나오고, 글자를 치면 그 이름이 되며, Enter나 Esc를 누르면 기본값 그대로 접힌다.
	- 그 뒤로는 묻지 않고 저장된 이름을 쓴다. 이름은 접힌 칸이나 이름 띠를 고르고 Enter나 F2를 눌러 바꾼다.
	- 모두 접기([[#^edit-fold-all]])로 한꺼번에 접을 때는 묻지 않는다.
- 펴진 접기 영역은 맨 위에 **이름 띠**(이름이 적힌 얇은 줄)를 붙여 보여 준다. 이름이 블록 글자를 가리지 않게 하려는 것이다. 띠만큼 그림이 길어진다.
	- 이름 띠를 더블클릭하면 그 접기 영역을 접는다. 이름 띠를 고르면 접기 영역 전체가 골라지고, Enter나 F2로 이름을 고친다.
	- 이름 띠는 화면에서 켜고 끌 수 있다. 저장되는 그림에는 넣지 않는다.
- 접힌 칸을 더블클릭하면 펼친다.
- 접힌 것은 통째로 옮기기·지우기·복사할 수 있다. 안쪽을 고치려면 펼친다.
- 접힘 상태는 파일에 저장하지 않는다. 저장되는 그림은 항상 모두 펼친 모양이다. 편집기는 파일별 접힘 상태를 기억해 두었다가 다시 열면 되살린다. → [[0016-fold-state-outside-file|ADR-0016]]

- [ ] #P2 단계별 실행 애니메이션 (교육용) ^code-anim

### 3.7 문제 알리기

사용자가 문제를 쉽게, 그리고 메인테이너가 다시 일으켜 볼 수 있을 만큼 정확하게 알린다. 서버가 없으므로 자동으로 보내지 않는다. 사용자가 보낼 내용을 보고 직접 보낸다.

- [ ] #P3 문제 알리기: 보고서를 만들어 보낸다. 착각이나 어설픈 보고가 이슈 목록에 쌓이지 않게 한다 ^rep-issue
	- 보내기 전에 도움말·자주 묻는 질문을 먼저 보여 준다
	- 공개: GitHub Discussions에 올린다. 양식으로 거른다 (재현 단계 필수, "도움말을 확인했음" 체크). 이슈는 메인테이너가 진짜 버그만 골라 만든다
	- 비공개: 다이어그램을 공개하고 싶지 않은 사용자는 이메일이나 폼으로 보낸다
	- 비공개로 같은 문제가 여러 번 들어오면 메인테이너가 자주 묻는 질문(FAQ) 페이지에 정리한다. 보내기 전에 보여 주는 FAQ가 이 페이지다
	- 실행 환경: NSDrawing 버전, 배포 대상(Obsidian 버전 등), OS, 브라우저, 화면 배율, 쓰는 글꼴
	- 로그: 예상 못 한 오류와 그 위치(스택), 불변 조건 검사 실패, 파일 열기·저장 실패(Drive API 오류 포함)
	- 최근 편집 기록: 문제가 나기 전 편집 명령 몇 개. 블록 글자는 빼고 명령 종류만
	- 다이어그램: 사용자가 동의하면 첨부한다. 개인적인 내용이 담길 수 있으므로 기본은 빼 둔다
	- 보내기 전에 보고서 전체를 사용자에게 보여 준다
- [ ] #P3 예상 못 한 오류가 나면 "이 문제를 알리시겠어요?"를 묻는다 ^rep-prompt

## 4. 비기능 요구사항

- **정합성:** 어떤 편집 연산을 거쳐도 트리는 항상 유효해야 한다 (빈 갈래는 빈 처리 블록으로 자동 채움). ^nfr-integrity
- **호환성:** 세 배포 대상이 만든 파일은 서로 열 수 있어야 한다. 같은 모델이면 같은 SVG를 생성해야 한다 (불필요한 git diff 방지). ^nfr-compat
- **성능:** 블록 500개 규모에서 편집 반응 100ms 이내. ^nfr-perf
- **다국어:** UI 한국어/영어, 텍스트는 UTF-8. ^nfr-i18n
- **접근성:** 키보드 전용 조작, 고대비 테마. ^nfr-a11y
- **테스트 가능성:** 모델·레이아웃·렌더러를 분리해서 레이아웃 계산을 단위 테스트할 수 있어야 한다. ^nfr-test

## 5. MVP 범위

#P0 항목만 모은 범위입니다.

- 블록 4종: 처리, If, While, Do-While
- 키보드/마우스 편집 + Undo/Redo
- 여러 블록 선택 (연속 범위, 자동 확장)
- 자동 레이아웃
- 모델 내장 SVG 저장/불러오기
- PNG 내보내기
- 배포 대상: 웹 ([[0011-development-order|ADR-0011]]에서 정한 첫 번째 대상)

## 6. 미결정 사항

요구사항 관련 미결정 사항입니다. 아키텍처 관련 미결정 사항은 "제안됨" 상태의 ADR로 관리합니다. → [[docs/README#아키텍처 결정 기록 (ADR)|ADR 목록]]

- [ ] **블록 글자는 코드인가, 일반 문장인가:** 구문 강조([[#^lay-syntax]])를 어떤 문법으로 할지가 여기서 갈린다.
- [ ] **Method 다이어그램의 머리:** 이벤트 처리기는 모자 모양 이벤트 머리([[#^blk-event]])를 단다. Method로 부르는 다이어그램의 머리를 이벤트 머리와 다르게 그릴지, 둘을 모델에서 구분할지 → [[#^blk-call]]
- [ ] **저장된 SVG의 색:** 저장할 때의 테마 색으로 고정할지, 보는 환경(예: Obsidian 다크 모드)을 따를지 → [[0013-default-visual-style|ADR-0013]]


- [ ] **웹 광고의 자리:** 광고 네트워크(예: Google AdSense)는 팝업·대화 상자 안의 광고를 정책으로 막는 경우가 많다. 저장·내보내기·공유 때만 보이게 하는 방식([[#^web-ads]])이 허용되는지 네트워크를 고를 때 확인한다.
- [ ] **주 사용자:** 교육용(학생, 강의 자료) / 실무 설계 문서용
	- 교육용 → 실행 애니메이션 중요
	- 실무용 → 코드 연동, PDF·인쇄 품질 중요
