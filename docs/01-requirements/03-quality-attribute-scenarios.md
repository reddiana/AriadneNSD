# 품질 속성 시나리오

[[01-requirements#4. 비기능 요구사항|비기능 요구사항]]을 **잴 수 있는 시나리오**로 다듬은 문서입니다. 아키텍처([[03-architecture]])는 이 시나리오들을 만족하도록 짜여 있어야 하고, 시나리오마다 그것을 확인할 시험이 있어야 합니다.

> [!info] 읽는 법
> - 시나리오는 SEI(Bass · Clements · Kazman, *Software Architecture in Practice*)의 여섯 부분으로 씁니다: **자극원**(누가 · 무엇이), **자극**(무슨 일), **환경**(어떤 상황에서), **대상**(시스템의 어느 부분), **응답**(시스템이 하는 일), **응답 측정**(합격 기준).
> - **아키텍처**는 이 시나리오를 만족시키는 구조와 그 결정(ADR)입니다. **시험**은 합격 기준을 확인하는 방법과 돌릴 때입니다. 코드가 아직 없으므로 지금의 시험은 명세이고, 코드가 생기면 같은 ID로 자동 시험을 만듭니다(시험 이름에 `QA-03`처럼 ID를 넣습니다).
> - 합격 기준의 수치 가운데 요구사항에 없던 것은 **제안값**이라고 적었습니다. 확인받기 전입니다.
> - 시나리오가 기대는 유즈케이스는 [[02-use-cases]]의 ID로 적습니다.

## 2. 시나리오

### QA-01 편집 명령과 불변식

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 편집 명령을 임의의 순서로 잇달아 실행한다(넣기, 지우기, 감싸기, 풀기, 옮기기, Method로 빼기, 실행 취소 · 다시 실행 …) |
| 환경 | 정상 편집 중. 어떤 문서 상태에서든 |
| 대상 | `core`의 모델과 편집 명령 |
| 응답 | 모든 명령의 결과 문서가 불변식을 지킨다. 지킬 수 없는 명령은 거절되고 문서는 그대로다 |
| 응답 측정 | 무작위 명령열 시험에서 불변식 위반 **0건** (제안값: 명령열 10,000개 × 길이 200) |

- **아키텍처:** 명령은 문서를 받아 새 문서를 돌려주는 순수 함수이고, 새 문서를 만들 때마다 불변식을 검사한다. 위반하는 문서는 만들어지지 않는다 → [[03-architecture#5. 공통 관심사]], [[0029-immutable-document-undo|ADR-0029]], [[01-model#3. 불변식]]
- **시험:** 속성 기반 시험(property-based test, 예: fast-check). 무작위 문서와 무작위 명령열을 만들어 매 단계 불변식을 검사한다. 실패하면 가장 짧은 반례로 줄여 회귀 시험에 더한다. **돌릴 때:** 모든 커밋(CI)

### QA-02 깨진 파일 열기

| 부분 | 내용 |
| --- | --- |
| 자극원 | 다른 도구, 망가진 동기화, 손으로 고친 파일 |
| 자극 | 모델이 없거나, JSON이 깨졌거나, 불변식을 어긴 모델이 든 파일을 연다 |
| 환경 | 모든 배포 대상 |
| 대상 | `core`의 파일 형식(역직렬화) |
| 응답 | 편집할 수 없다고 알리고 끝난다. 원본 파일에 쓰지 않는다 |
| 응답 측정 | 퍼징 입력에서 처리되지 않은 예외 **0건**, 원본 파일의 바이트 변화 **0건** |

- **아키텍처:** 역직렬화할 때도 편집 명령과 같은 불변식 검사를 한다. 열기는 읽기만 한다 → [[01-file-format#5. 버전 관리]], [[03-architecture#4.2 저장과 열기]]
- **시험:** 퍼징(올바른 파일을 무작위로 망가뜨린 입력 + 손으로 만든 깨진 파일 묶음). 열기 뒤 원본 파일의 해시가 같은지 본다. **돌릴 때:** 모든 커밋(짧게), 매일 밤(길게)

### QA-03 어디서 저장해도 같은 파일

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 같은 문서(같은 내용, 같은 보기 상태, 같은 화면 언어)를 저장한다 |
| 환경 | 서로 다른 배포 대상(웹, Obsidian, 데스크톱), 브라우저(Chrome, Edge, Firefox, Safari), OS(Windows, macOS, Linux, Android) |
| 대상 | `core`의 레이아웃 · 렌더러 · 파일 형식, `fonts` |
| 응답 | 같은 바이트의 파일을 쓴다 |
| 응답 측정 | 골든 문서 묶음의 저장 결과 SHA-256이 모든 환경에서 **100% 일치** |

- **아키텍처:** 레이아웃과 렌더러는 순수 함수다. 텍스트 폭은 브라우저에 묻지 않고 번들 글꼴의 advance 폭 테이블로 계산하고 정수 px로 올린다. JSON의 키 순서와 줄바꿈을 고정하고, 시각 · 기기 정보 · 난수를 쓰지 않는다. 서브세팅은 결정적이다 → [[03-architecture#5. 공통 관심사]], [[0026-bundled-font-metrics|ADR-0026]]
- **시험:** 골든 파일 시험. 대표 문서 묶음(한글 · 영문 · 기호, 블록 종류 모두, 접힘 · 펴 보기 포함)을 저장해 저장소의 기대 파일과 바이트로 견준다. 같은 시험을 Node와 각 브라우저(Playwright)에서 돌린다. **돌릴 때:** 모든 커밋(Node, Chromium), 출시 전(모든 브라우저와 Obsidian)
- **위험:** Firefox와 Safari는 스파이크에서 확인하지 못했다 → [[03-architecture#7. 위험과 검증이 필요한 사항]]

### QA-04 열고 바로 저장하면 그대로

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 파일을 열고 아무것도 고치지 않고 저장한다 |
| 환경 | 파일을 만든 앱과 같은 형식 버전, 같은 화면 언어 |
| 대상 | 파일 형식(역직렬화 → 직렬화) |
| 응답 | 원본과 같은 파일을 쓴다 |
| 응답 측정 | 골든 문서 묶음의 왕복(round-trip)에서 바이트 차이 **0건** |

- **아키텍처:** QA-03과 같다. 보기 상태도 파일에 들어 있어 열 때 그대로 되살아난다 → [[0018-save-as-shown|ADR-0018]]
- **시험:** 골든 파일 왕복 시험. **돌릴 때:** 모든 커밋
- **알아 둘 것:** 화면 언어가 다르면 같지 않다. 그림에 적는 글자("참", "거짓", "블록 n개")는 저장할 때의 화면 언어를 따르기 때문이다([[01-requirements#^r-nfr|R-NFR-04]]). 그래서 환경에 "같은 화면 언어"를 둔다

### QA-05 옛 파일 열기

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 옛 형식 버전으로 저장된 파일을 연다 |
| 환경 | 형식 버전이 올라간 뒤의 앱 |
| 대상 | 파일 형식의 마이그레이션 |
| 응답 | 버전별 마이그레이션을 차례로 적용해 지금 형식의 모델로 연다 |
| 응답 측정 | 형식 버전 1부터의 모든 골든 파일이 **100% 열리고** 불변식을 지킨다(프로토타입의 v0 파일은 열지 않는다 → [[0035-model-namespace-and-v0\|ADR-0035]]) |

- **아키텍처:** 형식 버전은 정수, 버전마다 마이그레이션 함수 하나 → [[01-file-format#5. 버전 관리]]
- **시험:** 형식 버전을 올릴 때마다 그 버전의 골든 파일을 저장소에 얼려 두고(지우지 않음), 모두 여는 시험. **돌릴 때:** 모든 커밋

### QA-06 어디서나 같은 그림

| 부분 | 내용 |
| --- | --- |
| 자극원 | 독자 |
| 자극 | 저장된 `.ns.svg`를 연다 |
| 환경 | AriadneNSD도 번들 글꼴도 없는 뷰어: Chrome, Firefox, Safari, GitHub의 파일 보기, Obsidian(플러그인 없음), Google Drive 미리보기 |
| 대상 | 저장된 SVG 파일 |
| 응답 | 편집기 화면의 문서 레이어와 같은 그림이 보인다. 글자는 글자로 남는다(선택 · 검색 가능) |
| 응답 측정 | SVG 1.1 검증 오류 **0건**. 빠진 글자(대체 글꼴로 그려진 글자) **0개**. 기준 그림과의 픽셀 차이 **1% 이하**(제안값, 안티앨리어싱 차이를 허용) |

- **아키텍처:** 쓰인 글자만 남긴 서브셋 글꼴과 문서 테마의 색을 파일 안에 넣는다. 편집 중에만 보이는 표시는 오버레이 레이어라 저장되지 않는다 → [[0026-bundled-font-metrics|ADR-0026]], [[0018-save-as-shown|ADR-0018]], [[03-architecture#4.2 저장과 열기]]
- **시험:** 시각 회귀 시험. 골든 문서를 각 브라우저에서 이미지로 열어(Playwright 스크린샷) 기준 그림과 픽셀로 견준다. SVG 1.1 검증기로 문법을 본다. GitHub · Drive · Obsidian은 수동 점검표. **돌릴 때:** 모든 커밋(Chromium), 출시 전(나머지)

### QA-07 편집 반응 시간

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 블록 하나의 글자를 고치거나 블록을 넣는다 |
| 환경 | 블록 500개 문서. 기준 기기(제안값: 4년 된 보급형 노트북, 예: 4코어 CPU · 8 GB, Chrome) |
| 대상 | 편집 명령 → 레이아웃 → 렌더링 → 화면 갱신 |
| 응답 | 바뀐 그림이 화면에 보인다 |
| 응답 측정 | 입력부터 화면 갱신까지 **p95 100ms 이하** |

- **아키텍처:** 불변 문서와 구조적 공유로 바뀌지 않은 하위 트리를 가려낼 수 있다. 증분 레이아웃(메모이제이션)을 할지는 측정해서 정한다 → [[0029-immutable-document-undo|ADR-0029]], [[02-layout#4. 성능]]
- **시험:** 성능 벤치마크. 블록 500개 문서에서 대표 명령 20가지를 각 100번 실행해 p95를 잰다. Node에서 `core`만(레이아웃 + 렌더링, 목표의 절반인 50ms 이하를 제안)과 브라우저에서 화면 갱신까지(Playwright, 성능 타임라인)로 나눈다. **돌릴 때:** 모든 커밋(Node, 결과를 기록해 느려지면 알림), 출시 전(기준 기기)
- **열린 물음:** "500개"를 문서의 블록 수로 셀지, 펴 보인 호출 블록까지 그려지는 블록 수로 셀지 → [[03-architecture#7. 위험과 검증이 필요한 사항]]

### QA-08 여는 시간 (제안)

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 파일을 연다 |
| 환경 | 블록 500개 문서, QA-07의 기준 기기 |
| 대상 | 역직렬화 → 마이그레이션 → 레이아웃 → 렌더링 |
| 응답 | 편집할 수 있는 화면이 보인다 |
| 응답 측정 | **1초 이하** (제안값) |

- **아키텍처:** 열 때는 모델 JSON만 읽고 그림 부분과 서브셋 글꼴은 읽지 않는다 → [[03-architecture#4.2 저장과 열기]]
- **시험:** QA-07과 같은 벤치마크에 열기를 더한다. **돌릴 때:** 모든 커밋

### QA-09 파일과 번들의 크기 (제안)

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 문서를 저장한다 / 편집기를 내려받는다 |
| 환경 | 서로 다른 한글 300자를 쓴 블록 100개 문서 / 첫 방문 |
| 대상 | 저장 파일 / 웹 번들, Obsidian `main.js` |
| 응답 | 파일과 번들이 작다 |
| 응답 측정 | 저장 파일 **300 KB 이하**, Obsidian `main.js` **3 MB 이하** (둘 다 제안값) |

- **아키텍처:** 편집기에는 기본 블록 글꼴 D2Coding 보통 굵기 하나를 번들한다. 한자를 뺀 문자(라틴 · 유럽 확장, 한글, 그리스, 키릴, 가나)를 싣고, woff2로 약 448 KB다 → [[0034-default-block-font|ADR-0034]]. 저장 파일에는 쓰인 글자만 추린 서브셋 글꼴을 넣는다. 서브셋이 300 KB 안에 드는지는 정하지 않음 → [[03-architecture#7. 위험과 검증이 필요한 사항]], [[02-layout]]
- **시험:** 크기 예산 시험(빌드 산출물과 골든 문서의 저장 결과 크기를 재고, 넘으면 실패). **돌릴 때:** 모든 커밋
