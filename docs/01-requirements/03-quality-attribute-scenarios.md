# 품질 속성 시나리오

[[01-requirements#4. 비기능 요구사항|비기능 요구사항]]을 **측정할 수 있는 시나리오**로 다듬은 문서입니다. 아키텍처([[01-architecture]])는 이 시나리오들을 만족하도록 구성되어 있어야 하고, 시나리오마다 그것을 확인할 테스트가 있어야 합니다.

> [!info] 읽는 법
> - 시나리오는 SEI(Bass · Clements · Kazman, *Software Architecture in Practice*)의 여섯 부분으로 씁니다: **자극원**(누가 · 무엇이), **자극**(무슨 일), **환경**(어떤 상황에서), **대상**(시스템의 어느 부분), **응답**(시스템이 하는 일), **응답 측정**(합격 기준).
> - **아키텍처**는 이 시나리오를 만족시키는 구조와 그 결정(ADR)입니다. **테스트**는 합격 기준을 확인하는 방법과 실행할 때입니다. 테스트는 같은 ID로 자동 테스트를 만듭니다(테스트 이름에 `T-0012 · QA-03: …`처럼 그 시나리오의 ID를 넣습니다). **테스트 ID**는 그 시나리오를 확인하는 테스트로, 테스트 목록 스크립트가 채웁니다(손으로 고치지 않습니다 → [[08-test-list]]). 층마다 어떻게 테스트하는지는 [[02-test-architecture]]에 있습니다.
> - 합격 기준의 수치 가운데 요구사항에 없던 것은 **제안값**이라고 적었습니다. 확인받기 전입니다.
> - **목표의 근거**는 그 수치를 왜 그렇게 정했는지입니다. 근거를 찾지 못한 수치는 "근거 없음(제안값)"이라고 밝혀 둡니다.
> - 시나리오가 기대는 유즈케이스는 [[02-use-cases]]의 ID로 적습니다.

## 2. 시나리오

### QA-01 편집 명령과 불변식

편집 중의 문서는 편집 명령으로만 변경되고, 명령의 조합은 테스트로 모두 열거할 수 없습니다. 어떤 순서로 실행해도 불변식이 유지되도록 보장해, 손상된 문서가 만들어지거나 저장되는 것을 막습니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 편집 명령을 임의의 순서로 잇달아 실행한다(삽입, 삭제, 감싸기, 풀기, 이동, Method로 빼기, 실행 취소 · 다시 실행 …) |
| 환경 | 정상 편집 중. 어떤 문서 상태에서든 |
| 대상 | `core`의 모델과 편집 명령 |
| 응답 | 모든 명령의 결과 문서가 불변식을 지킨다. 지킬 수 없는 명령은 거절되고 문서는 그대로다 |
| 응답 측정 | 무작위 명령열 테스트에서 불변식 위반 **0건** (제안값: 명령열 10,000개 × 길이 200) |
| 목표의 근거 | 위반 0건: 불변식을 어긴 문서는 저장하면 다른 앱에서 열리지 않으므로 하나도 허용할 수 없다. 명령열 10,000개 × 길이 200은 근거 없음(제안값) |

- **아키텍처:** 명령은 문서를 받아 새 문서를 반환하는 순수 함수이고, 새 문서를 만들 때마다 불변식을 검사한다. 위반하는 문서는 만들어지지 않는다 → [[01-architecture#6. 공통 관심사]], [[0029-immutable-document-undo|ADR-0029]], [[01-model#3. 불변식]]
- **테스트:** 속성 기반 테스트(property-based test, 예: fast-check). 무작위 문서와 무작위 명령열을 만들어 매 단계 불변식을 검사한다. 실패하면 가장 짧은 반례로 줄여 회귀 테스트에 추가한다. **실행할 때:** 모든 커밋(CI)
- **테스트 ID:** `packages/core/src/commands/properties.test.ts`의 테스트 2개([[08-test-list#^t-packages-core-src-commands-properties-test-ts|T-0171]] ~ T-0172). `packages/editor/src/session/random-keys.test.ts`의 테스트 1개([[08-test-list#^t-packages-editor-src-session-random-keys-test-ts|T-0228]])

### QA-02 깨진 파일 열기

저장 파일은 다른 도구, 동기화 오류, 수동 편집으로 손상될 수 있는 외부 입력입니다. 열 수 없는 파일을 만나도 사용자의 원본을 보존하고 편집기가 비정상 종료되지 않게 합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 다른 도구, 망가진 동기화, 손으로 수정한 파일 |
| 자극 | 모델이 없거나, JSON이 깨졌거나, 불변식을 어긴 모델이 든 파일을 연다 |
| 환경 | 모든 배포 대상 |
| 대상 | `core`의 파일 형식(역직렬화) |
| 응답 | 편집할 수 없다고 알리고 끝난다. 원본 파일에 쓰지 않는다 |
| 응답 측정 | 퍼징 입력에서 처리되지 않은 예외 **0건**, 원본 파일의 바이트 변화 **0건** |
| 목표의 근거 | 0건: 사용자의 파일을 망가뜨리거나 편집기가 죽는 일은 한 번도 허용할 수 없다([[01-requirements#^r-fmt\|R-FMT-06]]) |

- **아키텍처:** 역직렬화할 때도 편집 명령과 같은 불변식 검사를 한다. 열기는 읽기만 한다 → [[01-file-format#5. 버전 관리]], [[01-architecture#5.2 저장과 열기]]
- **테스트:** 퍼징(올바른 파일을 무작위로 망가뜨린 입력 + 손으로 만든 깨진 파일 묶음). 열기 뒤 원본 파일의 해시가 같은지 검증한다. **실행할 때:** 모든 커밋(짧게), 매일 밤(길게)
- **테스트 ID:** [[08-test-list#^t-packages-core-src-format-parse-model-test-ts|T-0419]], [[08-test-list#^t-packages-core-src-format-round-trip-test-ts|T-0424]], [[08-test-list#^t-packages-core-src-format-svg-file-test-ts|T-0436]]. 인수 테스트 [[01-requirements#^at|AT-06]]([[08-test-list#^t-apps-web-e2e-acceptance-spec-ts|T-0008]])

### QA-03 결정적 저장 출력

저장한 다이어그램을 git 같은 버전 관리 시스템으로 관리할 때, 실행 환경에 따라 바이트가 달라지면 내용을 바꾸지 않은 파일에도 diff가 생깁니다. 저장 결과가 문서의 내용과 뷰 상태만으로 결정되게 해 배포 대상, 브라우저, OS의 영향을 배제합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 같은 문서(같은 내용, 같은 뷰 상태)를 저장한다. 저장하는 사람의 화면 언어는 달라도 된다 |
| 환경 | 서로 다른 배포 대상(웹, Obsidian, 데스크톱), 브라우저(Chrome, Edge, Firefox, Safari), OS(Windows, macOS, Linux, Android) |
| 대상 | `core`의 레이아웃 · 렌더러 · 파일 형식, `fonts` |
| 응답 | 같은 바이트의 파일을 쓴다 |
| 응답 측정 | 골든 문서 묶음의 저장 결과 SHA-256이 모든 환경에서 **100% 일치** |
| 목표의 근거 | 100%: 그림을 git 같은 버전 관리 시스템으로 관리할 때 한 바이트만 달라도 바꾸지 않은 그림에 diff가 생긴다([[01-requirements#^r-nfr\|R-NFR-02]]의 "불필요한 git diff 방지") |

- **아키텍처:** 레이아웃과 렌더러는 순수 함수다. 텍스트 폭은 브라우저에 조회하지 않고 번들 글꼴의 advance 폭 테이블로 계산하고 정수 px로 올린다. JSON의 키 순서와 줄바꿈을 고정하고, 시각 · 기기 정보 · 난수를 쓰지 않는다. 서브세팅은 결정적이다 → [[01-architecture#6. 공통 관심사]], [[0026-bundled-font-metrics|ADR-0026]]
- **테스트:** 골든 파일 테스트. 대표 문서 묶음(한글 · 영문 · 기호, 블록 종류 모두, 접힘 · 펴 보기 포함)을 저장해 저장소의 기대 파일과 바이트로 비교한다. 같은 테스트를 Node와 각 브라우저(Playwright)에서 실행한다. **실행할 때:** 모든 커밋(Node, Chromium), 출시 전(모든 브라우저와 Obsidian)
- **테스트 ID:** [[08-test-list#^t-packages-editor-src-create-editor-test-ts|T-0816]]. `packages/core/src/model/site-folded.test.ts`의 테스트 18개([[08-test-list#^t-packages-core-src-model-site-folded-test-ts|T-1324]] ~ T-1341). 인수 테스트 [[01-requirements#^at|AT-10]]([[08-test-list#^t-apps-web-e2e-acceptance-spec-ts|T-0012]])
- **위험:** Firefox와 Safari는 스파이크에서 확인하지 못했다 → [[01-architecture#8. 위험과 검증이 필요한 사항]]

### QA-04 저장 왕복 무손실

QA-03이 실행 환경 사이의 동일성이라면, 이 시나리오는 열기와 저장 사이의 동일성입니다. 파일을 열어 보기만 했을 때 파일이 변경되지 않게 해, 버전 관리 시스템을 쓰는 사용자의 커밋에 의도하지 않은 변경이 섞이지 않게 합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 작성자 |
| 자극 | 파일을 열고 아무것도 편집하지 않고 저장한다 |
| 환경 | 파일을 만든 앱과 같은 형식 버전 |
| 대상 | 파일 형식(역직렬화 → 직렬화) |
| 응답 | 원본과 같은 파일을 쓴다 |
| 응답 측정 | 골든 문서 묶음의 왕복(round-trip)에서 바이트 차이 **0건** |
| 목표의 근거 | 0건: QA-03과 같다. 열고 닫기만 했는데 diff가 생기면 안 된다 |

- **아키텍처:** 문서는 불변이고 `editor`가 갖고 있으므로, 쓰기 실패는 문서를 바꾸지 않는다. `DocumentStore`의 쓰기는 실패를 던지지 않고 값(`WriteResult`: `cancelled` · `denied` · `failed`)으로 반환한다 → [[03-editor#6. 셸과의 연결]]
- **테스트:** 실패하는 테스트 더블 `DocumentStore`로 저장하고, 문서 · "저장 안 됨" 표시 · 알림을 보는 테스트. **실행할 때:** 모든 커밋
- **테스트 ID:** 인수 테스트 [[01-requirements#^at|AT-07]]([[08-test-list#^t-apps-web-e2e-acceptance-spec-ts|T-0009]], [[08-test-list#^t-apps-web-e2e-acceptance-spec-ts|T-0023]])

### QA-18 모바일 시작 시간

웹은 설치 없이 접근하는 진입점이고, 휴대폰으로 처음 방문한 사용자는 저사양 기기와 느린 네트워크에서 앱을 처음 경험합니다. 첫 방문의 대기 시간을 제한해 편집 화면이 보이기 전에 사용자가 이탈하지 않게 합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 휴대폰으로 처음 온 사람 |
| 자극 | 웹의 주소를 연다 |
| 환경 | 캐시가 빈 브라우저. 기준: CPU 4배 느림과 "slow 4G"(왕복 150 ms, 내려받기 1.6 Mbps, Lighthouse의 모바일 측정과 같음) |
| 대상 | 웹의 첫 내려받기(HTML · JS · 화면용 블록 글꼴)와 시작 |
| 응답 | 편집 화면이 보이고, 이어서 블록 글꼴로 바뀐다 |
| 응답 측정 | 편집 화면 **3초 이하**, 블록 글꼴까지 **5초 이하** (2026-11-01에 메인테이너가 확인. 그날 측정값은 CPU 6배에서 약 1.8초와 4초) |
| 목표의 근거 | 3초: 모바일 페이지가 3초를 넘으면 떠나는 사람이 크게 는다는 조사(Google, 2016)에서 흔히 쓰는 값. 5초는 근거 없음(메인테이너가 확인한 값) |

- **아키텍처:** 편집 화면은 블록 글꼴을 기다리지 않고 그린다(텍스트 폭은 글꼴 파일이 아니라 번들한 advance 폭 테이블로 계산하므로 레이아웃은 같다). 저장용 TTF와 wasm은 첫 편집 뒤에 받는다 → [[06-web#5. 배포]], [[0026-bundled-font-metrics|ADR-0026]]
- **테스트:** E2E(Playwright, Android 폰 흉내 + CPU · 네트워크 감속). 편집 화면과 블록 글꼴이 보인 때를 재어 합격 기준과 견준다. 원인을 나눠 보는 재기 스크립트 `src/apps/web/scripts/measure-startup.mjs`. **실행할 때:** 모든 커밋(흉내), 출시 전(실제 휴대폰)
- **테스트 ID:** `apps/web/e2e/mobile.spec.ts`의 테스트 6개([[08-test-list#^t-apps-web-e2e-mobile-spec-ts|T-0287]] ~ T-0523)

### QA-19 초기화 장애 시 빈 화면 방지

웹 앱은 사용자의 브라우저와 기기 환경을 통제할 수 없어 초기화 중 저장소 응답 지연이나 스크립트 오류가 발생할 수 있습니다. 빈 화면은 사용자에게 아무 정보도 주지 못하고 결함 분석도 어렵게 하므로, 편집 화면으로 계속하거나 원인을 표시합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 브라우저 |
| 자극 | 시작하는 동안 브라우저 저장소(IndexedDB)가 응답하지 않거나, 스크립트가 오류를 낸다 |
| 환경 | 웹. 어떤 브라우저 · 기기에서든 |
| 대상 | 웹의 시작(`index.html`, `main.tsx`) |
| 응답 | 저장소가 응답하지 않으면 메모리로 대신하고 편집 화면을 띄운다. 오류면 멈춘 단계 · 오류 · 브라우저 정보를 화면에 적는다 |
| 응답 측정 | 저장소가 응답하지 않을 때 편집 화면까지 **3초 + 시작 시간 이하**. 빈 화면으로 남는 경우 **0번**(어떤 경우든 15초 안에 편집 화면이나 이유가 보인다) |
| 목표의 근거 | 3초는 저장소 열기의 시간 제한([[06-web#2. 로컬 백업과 자동 저장]])이다. 15초는 근거 없음(제안값) |

- **아키텍처:** 저장소 열기의 시간 제한(3초)과 메모리 대체, 시작 화면과 시작 단계(`data-boot-step`) → [[06-web#2. 로컬 백업과 자동 저장]], [[06-web#7. 웹에서의 화면]]
- **테스트:** E2E(응답하지 않는 `indexedDB.open`, 시작 중 오류를 흉내). **실행할 때:** 모든 커밋
- **테스트 ID:** `apps/web/e2e/boot.spec.ts`의 테스트 2개([[08-test-list#^t-apps-web-e2e-boot-spec-ts|T-0278]] ~ T-0279)

### QA-20 모바일 사용성

웹은 휴대폰 브라우저에서도 접근할 수 있으므로, 데스크톱을 전제로 한 화면 배치와 포인터 조작만으로는 부족합니다. 좁은 화면과 터치 입력에서도 문서를 열고 기본 편집을 수행할 수 있게 합니다.

### QA-21 비신뢰 공유 링크 입력 처리

공유 링크는 문서 내용을 URL에 담으므로, 링크를 여는 것은 누구나 만들 수 있는 외부 입력을 처리하는 일입니다. 손상되거나 악의적으로 구성한 링크로부터 편집기와 사용자가 작업 중인 문서를 보호합니다.

| 부분 | 내용 |
| --- | --- |
| 자극원 | 링크를 만든 누구나(꾸민 사람도) |
| 자극 | 잘리거나 바뀐 공유 링크, 아주 긴 링크, 작게 꾸렸지만 풀면 아주 커지는 링크(zip bomb), 모델이 파일의 규칙을 어기는 링크를 연다 |
| 환경 | 웹. 페이지를 처음 열 때나, 열린 탭의 주소창에 붙여 넣을 때 |
| 대상 | 웹 셸의 공유 링크 읽기(`apps/web/src/files/share-link.ts`)와 모델 파서 |
| 응답 | 링크를 열지 않고 이유(손상 · 너무 큼 · 더 새 버전 · 이 브라우저가 풀 수 없음)를 알린 뒤 평소처럼 시작한다. 지금 문서는 바뀌지 않는다 |
| 응답 측정 | 편집기가 죽는 경우 **0번**. 1 MB가 넘는 링크는 **풀지 않음**. 푼 크기가 16 MB를 넘는 순간 **멈춤** |
| 목표의 근거 | 1 MB는 브라우저가 주소로 받는 한도(Chromium 2 MB, 다른 브라우저는 더 작은 경우가 있음)의 안쪽이다([[06-web#3. 공유 URL과 보기 모드]]). 16 MB는 근거 없음(제안값: 링크가 메모리를 다 쓰지 않게 하는 상한) |

- **아키텍처:** 길이를 먼저 보고, 스트림으로 풀며 크기를 세고, 모델은 파일과 같은 검증 파서를 거친다 → [[0043-share-link-in-fragment|ADR-0043]], [[06-web#3. 공유 URL과 보기 모드]]
- **테스트:** 단위 테스트(잘린 · 바뀐 · 긴 링크, zip bomb, 봉투가 틀린 JSON, 모델 검증 실패)와 E2E(손상된 링크로 페이지를 엶). **실행할 때:** 모든 커밋
- **테스트 ID:** [[08-test-list#^t-apps-web-src-files-share-link-test-ts|T-1140]]
