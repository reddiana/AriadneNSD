# 유즈케이스

사용자가 **무엇을 이루려고** AriadneNSD를 쓰는지를 유즈케이스로 적습니다. [[01-requirements|요구사항 명세]]가 기능의 목록이라면, 이 문서는 그 기능들이 이어지는 **흐름**입니다. 흐름은 그대로 인수 시험의 시나리오가 됩니다.

> [!info] 읽는 법
> - 유즈케이스는 사용자 목표 수준으로, 기본 흐름과 예외 흐름 몇 줄로 씁니다. 실패가 비싼 흐름(UC-02 열기, UC-06 저장, UC-07 노트에 넣어 보이기)만 최소 보장 · 성공 보장 · 확장까지 갖춘 자세한 형식(Cockburn의 fully dressed)으로 씁니다([[dr-0014-light-use-cases|DR-0014]]). 세부 규칙(어떤 키, 어떤 모습)은 UX 설계([[02-interaction-rules]])에 있고 여기서는 되풀이하지 않습니다.
> - 각 유즈케이스 끝의 "요구사항"은 그 흐름이 기대는 요구사항의 ID입니다. 우선순위(`P0` …)는 요구사항 쪽에 있습니다.
> - 흐름의 번호에 붙은 `a`, `b`는 그 단계에서 갈라지는 예외 흐름(자세한 형식에서는 "확장")입니다(예: 3a는 3단계의 예외). `'`가 붙은 것은 같은 단계를 다른 수단으로 하는 기술 변형입니다.

## 1. 액터

| 액터 | 누구 | 하는 일 |
| --- | --- | --- |
| 작성자 | 설계 문서를 쓰는 실무자([[01-requirements#1. 핵심 원칙]]) | 다이어그램을 만들고 고치고 저장하고 공유한다 |
| 독자 | 문서 · 노트 · 저장소에서 그림을 보는 사람. AriadneNSD가 없을 수 있다 | 저장된 그림을 본다 |
| 호스트 플랫폼 | Obsidian, Google Drive, 브라우저, OS | 파일을 보관하고, 그림을 미리 보여 주고, AriadneNSD를 부른다 |

## 4. 유즈케이스

### UC-01 새 다이어그램을 만든다

- **액터:** 작성자
- **사전 조건:** AriadneNSD를 열 수 있다(웹 페이지, 데스크톱 앱, Obsidian 플러그인, Drive 연동 가운데 하나)

**기본 흐름**

1. 작성자가 새 다이어그램을 만든다.
2. 편집기가 다이어그램 하나와 빈 블록 하나가 든 새 문서를 연다.
3. 작성자가 블록을 편집한다 → UC-03

**예외 흐름**

- 1a. Obsidian에서 노트 안에 바로 넣으려면 → UC-07
- 1b. Obsidian 파일 탐색기의 우클릭 메뉴에서 만들면 노트에 넣지 않고 파일만 생긴다
- 1c. Google Drive의 "새로 만들기"에서 만들면 Drive에 파일이 생긴다

**요구사항:** [[01-requirements#^r-obs-2|R-OBS-08]], [[01-requirements#^r-gd|R-GD-02]], [[01-requirements#^r-nfr|R-NFR-01]]

### UC-02 다이어그램을 연다

> [!abstract] 자세한 형식
> 실패가 비싼 흐름이라 자세한 형식으로 씁니다([[dr-0014-light-use-cases|DR-0014]]).

| 항목 | 내용 |
| --- | --- |
| 범위 | AriadneNSD (모든 배포 대상) |
| 수준 | 사용자 목표 |
| 주 액터 | 작성자 |
| 보조 액터 | 호스트 플랫폼 (디스크, 볼트, Drive, 브라우저) |
| 이해관계자와 관심 | **작성자**: 저장할 때의 모습 그대로 이어서 편집한다. 다른 배포 대상에서 만든 파일도 열린다. **파일의 주인(작성자, 팀의 저장소)**: 열기만 해서는 파일이 바뀌지 않는다 |
| 사전 조건 | AriadneNSD가 저장한 파일(`.ns` 또는 `.ns.svg`)이나 공유 URL이 있다 |
| 최소 보장 | 열다가 실패해도 원본 파일은 바뀌지 않는다. 실패한 까닭을 알린다 |
| 성공 보장 | 편집기에 저장할 때와 같은 내용과 보기 상태(접힘, 펴 보인 호출 블록)가 보인다. 그림은 파일의 그림 부분이 아니라 모델에서 다시 그린 것이다 |
| 트리거 | 작성자가 파일을 연다 |

**기본 성공 시나리오**

1. 작성자가 파일을 고른다.
2. 호스트 플랫폼이 파일의 내용을 편집기에 건넨다.
3. 편집기가 파일 안의 모델만 읽는다.
4. 편집기가 모델에서 그림을 다시 그리고, 저장할 때의 보기 상태대로 보인다.
5. 작성자가 블록을 편집한다 → UC-03

**확장**

- 1a. Obsidian에서 일반 `.svg`를 열면 AriadneNSD가 아니라 Obsidian의 기본 동작으로 열린다
- 1b. Obsidian에서 이름이 바뀌어 `.ns`가 빠진 파일도 모델이 들어 있으면 편집 메뉴가 생긴다
- 1c. 공유 URL을 열면 보기 모드로 시작하고, 버튼 하나로 편집으로 넘어간다
- 1d. 같은 파일이 이미 다른 창이나 탭에 열려 있다: 미결정(6장)
- 3a. 모델이 없거나 깨진 파일: 편집할 수 없다고 알리고 끝난다. 그림을 거꾸로 읽어 모델을 만들지 않는다
- 3b. 옛 형식 버전의 파일: 지금 형식으로 바꿔 읽는다. 원본이 언제 새 형식이 되는지는 미결정(6장). 프로토타입이 저장한 `version: 0` 파일은 바꿔 읽지 않고 3a와 같이 다룬다 → [[0035-model-namespace-and-v0|ADR-0035]]
- 3c. 지금보다 새 형식 버전의 파일: 편집할 수 없다고 알리고 앱 업데이트를 안내한다
- 3d. 다른 도구로 그림 부분만 고친 파일: 그림이 모델과 달라졌다고 알린다
- 4a. 다른 문서의 Method를 부르는 호출 블록이 있는데 그 파일을 읽지 못한다: 그 호출 블록은 "이어진 곳 없음"으로 보인다

**기술 변형**

- 1'. 웹 · 데스크톱은 파일 열기, Obsidian은 파일 탐색기, Drive는 "AriadneNSD로 열기", 데스크톱은 `.ns` 더블클릭으로도

**빈도:** 편집을 시작할 때마다

**요구사항:** [[01-requirements#^r-web|R-WEB-02]], [[01-requirements#^r-dsk|R-DSK-01]], [[01-requirements#^r-dsk|R-DSK-02]], [[01-requirements#^r-dsk|R-DSK-03]], [[01-requirements#^r-dsk|R-DSK-04]], [[01-requirements#^r-obs-2|R-OBS-05]], [[01-requirements#^r-obs-2|R-OBS-06]], [[01-requirements#^r-obs-2|R-OBS-09]], [[01-requirements#^r-gd|R-GD-01]], [[01-requirements#^r-web|R-WEB-05]], [[01-requirements#^r-web|R-WEB-06]], [[01-requirements#^r-fmt|R-FMT-02]], [[01-requirements#^r-fmt|R-FMT-05]], [[01-requirements#^r-fmt|R-FMT-06]], [[01-requirements#^r-fmt|R-FMT-09]], [[01-requirements#^r-blk|R-BLK-09]], [[01-requirements#^r-nfr|R-NFR-02]]

### UC-03 블록을 편집한다

- **액터:** 작성자
- **사전 조건:** 다이어그램이 편집기에 열려 있다(UC-01, UC-02)

**기본 흐름**

1. 작성자가 블록을 하나 또는 여럿 고른다.
2. 작성자가 블록을 넣거나, 지우거나, 글자를 고치거나, 제어 블록으로 감싸거나 푼다.
3. 편집기가 그림을 다시 그린다. 블록의 크기와 갈래의 너비는 글자에 맞춰 저절로 정해진다.
4. 작성자가 마음에 들지 않으면 실행 취소한다.

**예외 흐름**

- 1a. 다른 깊이의 블록을 함께 고르면, 둘을 함께 품는 가장 가까운 범위로 넓혀 고른다
- 2a. 구조가 깨지는 편집(예: 반복의 본문을 비우기)은 일어나지 않는다. 빈 갈래는 빈 블록으로 채워진다
- 2b. 키보드만으로도 1~4를 모두 할 수 있다
- 2c. 끌어 놓기, 복사 · 붙여넣기로 블록을 옮긴다
- 2d. If의 갈래를 바꾸거나, Case의 갈래를 더하고 빼고 순서를 바꾼다

### UC-04 구조를 나눈다

- **액터:** 작성자
- **사전 조건:** 다이어그램이 편집기에 열려 있다

**기본 흐름**

1. 작성자가 따로 떼어 낼 블록들을 고른다.
2. 작성자가 "새 Method로 빼기"를 한다.
3. 고른 블록들이 새 Method 다이어그램이 되고, 그 자리에는 그 Method를 부르는 호출 블록이 남는다.
4. 작성자가 Method 머리의 이름을 고치면, 그 Method를 부르는 호출 블록이 모두 따라 바뀐다.

**예외 흐름**

- 1a. 처음부터 Event나 Method 다이어그램을 새로 만들어 나란히 둔다
- 2a. 거꾸로, 호출 블록을 풀어 Method의 블록들로 바꾼다
- 3a. 부를 것이 문서에 없으면(라이브러리 함수 등) 이름을 적어 부른다
- 4a. 호출 블록이 부르던 Method를 지우면 그 호출 블록은 "이어진 곳 없음"이 된다
- 4b. 다른 문서의 Method를 부른다(`P2`)

**요구사항:** [[01-requirements#^r-edit|R-EDIT-18]], [[01-requirements#^r-edit|R-EDIT-19]], [[01-requirements#^r-edit|R-EDIT-08]], [[01-requirements#^r-blk|R-BLK-10]], [[01-requirements#^r-blk|R-BLK-11]], [[01-requirements#^r-blk|R-BLK-07]], [[01-requirements#^r-blk|R-BLK-08]], [[01-requirements#^r-blk|R-BLK-09]]

### UC-05 큰 다이어그램을 훑어본다

- **액터:** 작성자
- **사전 조건:** 한 화면에 다 보이지 않는 다이어그램이 열려 있다

**기본 흐름**

1. 작성자가 확대 · 축소하고 화면을 옮긴다.
2. 작성자가 지금 보지 않을 제어 블록이나 갈래를 접는다.
3. 작성자가 여러 블록을 묶어 이름을 붙인 접기 영역으로 접는다.
4. 작성자가 호출 블록을 펴서 그 자리에서 Method의 블록을 본다.

**예외 흐름**

- 2a. 모두 접기 · 모두 펴기 · 깊이 n까지 펴기(`P2`)
- 4a. 펴 보인 호출 블록 안에서도 접기 영역을 만든다. 그 자리에만 있고 Method에는 없다

**요구사항:** [[01-requirements#^r-lay|R-LAY-03]], [[01-requirements#^r-edit|R-EDIT-13]], [[01-requirements#^r-edit|R-EDIT-14]], [[01-requirements#^r-edit|R-EDIT-15]], [[01-requirements#^r-edit|R-EDIT-16]], [[01-requirements#^r-edit|R-EDIT-17]]

> [!abstract] 자세한 형식

| 항목 | 내용 |

| 범위 | AriadneNSD (모든 배포 대상) |
| 수준 | 사용자 목표 |

| 보조 액터 | 호스트 플랫폼 (디스크, 볼트, Drive, 브라우저) |
| 이해관계자와 관심 | **작성자**: 편집한 것을 잃지 않는다. **독자**: AriadneNSD 없이도 어디서나 그림이 보인다. **팀의 저장소(git)**: 같은 내용이면 같은 파일이라 쓸데없는 diff가 생기지 않는다 |

**기본 성공 시나리오**

1. 작성자가 저장한다.
2. 편집기가 모델과 보기 상태로 그림을 다시 그리고, 모델과 그림과 글꼴 서브셋을 SVG 파일 하나로 만든다.
3. 호스트 플랫폼이 원래 파일에 쓴다.
4. 편집기가 "저장 안 됨" 표시를 지운다.

**확장**

- 1a. 다른 이름으로 저장한다: 3에서 새 파일에 쓴다
- 1b. 웹에서는 저장하기 전에도 작성 중인 내용이 브라우저에 임시로 남아, 새로고침해도 되살아난다
- 2a. 블록 글자에 어떤 문자가 있어도(`]]>` 포함) 파일이 깨지지 않는다
- 3a. 원래 파일에 덮어쓰지 못하는 브라우저 → [[06-web]]에서 정함
- 3b. 쓰기에 실패한다(권한, 디스크, 네트워크): 실패했다고 알린다. 다시 시도하게 하는지, 다른 이름으로 저장하게 하는지는 미결정(6장)
- 3c. 연 뒤에 파일이 다른 곳에서 바뀌었다(다른 창, Obsidian 동기화, Drive의 다른 사용자): 미결정(6장)

**기술 변형**

- 3'. 웹 · 데스크톱은 디스크, Obsidian은 볼트, Drive는 Drive의 원래 파일

**빈도:** 편집하는 동안 자주. 자동 저장이 있어 더 자주

**요구사항:** [[01-requirements#^r-fmt|R-FMT-01]], [[01-requirements#^r-fmt|R-FMT-02]], [[01-requirements#^r-fmt|R-FMT-03]], [[01-requirements#^r-fmt|R-FMT-04]], [[01-requirements#^r-fmt|R-FMT-07]], [[01-requirements#^r-fmt|R-FMT-08]], [[01-requirements#^r-web|R-WEB-02]], [[01-requirements#^r-dsk|R-DSK-01]], [[01-requirements#^r-gd|R-GD-03]], [[01-requirements#^r-web|R-WEB-03]], [[01-requirements#^r-exp|R-EXP-04]], [[01-requirements#^r-nfr|R-NFR-02]]

### UC-07 노트에 다이어그램을 넣어 보인다

> [!abstract] 자세한 형식
> 실패가 비싼 흐름이라 자세한 형식으로 씁니다([[dr-0014-light-use-cases|DR-0014]]).

| 항목 | 내용 |
| --- | --- |
| 범위 | AriadneNSD Obsidian 플러그인 |
| 수준 | 사용자 목표 |
| 주 액터 | 작성자 |
| 보조 액터 | 독자, 호스트 플랫폼 (Obsidian) |
| 이해관계자와 관심 | **작성자**: 노트를 쓰는 흐름을 끊지 않고 그림을 넣고 고친다. **독자**: 플러그인 없이 그림을 본다. **팀의 저장소(git)**: 같은 내용이면 같은 파일이다 |
| 사전 조건 | 볼트에 플러그인이 켜져 있다 |
| 최소 보장 | 노트의 다른 글과 볼트의 다른 파일은 바뀌지 않는다. 편집 중 오류가 나면 이미 있던 그림 파일이 그대로 남는지는 미결정(6장) |
| 성공 보장 | 볼트에 유효한 `.ns.svg`가 있고, 노트에 그 파일을 가리키는 `![[…]]`가 있으며, 노트에 그 그림이 보인다 |
| 트리거 | 작성자가 노트 편집 화면의 우클릭 메뉴에서 "Insert new NS diagram"을 고른다 |

**기본 성공 시나리오**

1. 플러그인이 볼트에 새 다이어그램 파일을 만든다. 파일의 이름과 폴더는 미결정(6장)
2. 플러그인이 노트의 커서 자리에 그 파일을 넣는 `![[…]]`를 넣는다.
3. 플러그인이 편집 탭을 연다.
4. 작성자가 블록을 편집한다 → UC-03
5. 작성자가 저장한다 → UC-06
6. 플러그인이 노트의 그림을 새 그림으로 바꾼다.
7. 독자가 노트를 열어 그림을 본다.

**확장**

- 1a. 같은 이름의 파일이 있다: 미결정(6장)
- 4a. 작성자가 아무것도 그리지 않고 탭을 닫는다: 미결정(6장)
- 6a. 노트가 이미 열려 있으면 다시 열지 않고 그림만 바뀐다. 같은 그림을 넣은 다른 노트도 같다
- 7a. 독자에게 플러그인이 없어도 그림은 보인다(편집 메뉴만 없다)

**기술 변형**

- 트리거'. 명령 팔레트에서 실행한다
- 3'. 이미 넣은 그림의 우클릭 메뉴에서 "Edit NS diagram"을 고르면 3부터 시작한다

**빈도:** 노트에 알고리즘을 설명할 때마다

**요구사항:** [[01-requirements#^r-obs|R-OBS-01]], [[01-requirements#^r-obs|R-OBS-03]], [[01-requirements#^r-obs|R-OBS-02]], [[01-requirements#^r-obs|R-OBS-04]], [[01-requirements#^r-obs-2|R-OBS-07]], [[01-requirements#^r-obs-3|R-OBS-10]], [[01-requirements#^r-fmt|R-FMT-07]]

### UC-08 공유하고 내보낸다

- **액터:** 작성자, 독자
- **사전 조건:** 다이어그램이 편집기에 열려 있다

**기본 흐름**

1. 작성자가 내보낼 형식을 고른다: PNG(배율), 모델을 뺀 SVG, PDF.
2. 편집기가 그 파일을 만든다.
3. 작성자가 그 파일을 문서 · 슬라이드 · 이슈에 붙인다. 독자는 그 파일을 본다.

**예외 흐름**

- 1a. 공유 URL을 만든다. 다이어그램 전체가 URL에 담기고, 독자는 링크만으로 연다(보기 모드)
- 1b. 인쇄한다. 큰 다이어그램은 여러 페이지로 나뉜다
- 3a. 저장 파일(`.ns.svg`) 그대로 GitHub · Drive · 문서 도구에 두어도 그림으로 보인다 → UC-06
- 3b. 다른 뷰어에서도 글꼴이 똑같이 보이게 글자를 외곽선으로 바꿔 저장한다(`P1`)

### UC-09 그림의 모양을 정한다

- **액터:** 작성자
- **사전 조건:** 다이어그램이 편집기에 열려 있다

**기본 흐름**

1. 작성자가 문서의 테마(그림의 색 묶음)를 고른다.
2. 작성자가 블록 글자의 종류(문장 / C / Java / Python / Bash 등)를 고르면, 블록 글자가 그 문법으로 강조된다.
3. 작성자가 Event · Method 머리의 모양을 고른다.
4. 고른 것은 문서에 저장되어, 누가 어디서 열어도 같은 모양이다.

**예외 흐름**

- 1a. 편집 화면의 밝기(밝음 · 어두움)는 문서의 테마와 따로다. 저장되는 그림은 문서의 테마를 따른다
- 1b. 화면의 언어는 사용자의 설정이다. 그림에 적히는 글자("참", "거짓" 등)는 저장할 때의 언어를 따른다
