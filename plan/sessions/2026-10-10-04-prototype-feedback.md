# 2026-10-10 프로토타입 피드백

같은 날 네 번째 세션이다 (← [[2026-10-10-03-inbox-review]]). 세션 중에 쓰는 기록이며, 마무리할 때 채운다.

## inbox 원문 (지운 항목)

### 1. 일하는 방식

- 아직 승인되지 않은 ADR은 수정할 수 있지 않나요?
- 승인된 ADR이 이후 작업에서 관련 내용이 변경된다면 승인된 ADR에 "참고사항" 또는 "이후 변경/추가 사항"으로 언급하는 것이 repo 방문자에게 혼란을 덜어 줄 것 같아요. (예를들어 배포 유형이 늘어난다든지하면 [[0011-development-order]]이나 [[0002-three-targets-shared-core]]에)
- 이 문서에서 2, 3Level 제목이더라도 최근 함께 해왔던 작업에 비추어 내가 계속 쓸 것 같으면, 처리해서 내용을 지우더라도 그 제목을 남겨주세요. 더이상 안 쓸 것 같으면 지우시구요.
- [[0011-development-order]]에 최근에 추가된 배포 방식에 대한 내용이 `추가`로 언급되어있지 않습니다. ADR을 보는 사람들이 우리가 논의한 히스토리를 전부 알거라고 기대할 수 없습니다. ADR을 보는 사람이 "이 ADR이 작성될 당시에는 이랬지만, 현재의 모습과 다른 모습을 기반으로 논의한 이유는, 이 이후에 추가/변경된 사항이 있어서 그랬구나"하는 것을 쉽게 이해할 수 있어야합니다.
- ADR의 `이후 변경`은 문서 맨 앞에 `> [!NOTE]`로 해주세요.

### 3. 기능

#### 프로토타입 > 추가/변경 요건

- `E`: 
	- 이벤트 없는 경우 이벤트 머리달기
	- 이벤트 있는 경우 뭘 할지 물어보기
		- 새로운 빈 다이어그램을 만들고 이벤트를 달지
		- 선택된 영역을 새로운 다이어그램으로 만들고 이벤트를 달고
			- 현재 선택된 영역은 그 이벤트를 발생하는 처리 블록으로 치환
- Block 하나만 선택할 경우 접기 안 하게 해주세요
	- (세션 중 덧붙인 말) "제어블록 내부더라도 블록 하나는 접을 필요 없습니다." / "IF나 CASE는 브랜치별로 접습니다." / "접힌 갈래로도 방향키가 들어가면 좋겠습니다."
- Block 또는 선택영역 잘라내기/복사 기능. 이후 붙여넣기 하면 현재 선택된 Block 또는 선택영역 이후에 삽입되게 해주세요.
	- (세션 중 덧붙인 말) "고른 것이 없이 붙이기 하면 아무것도 하지 마세요"
- If나 Case 처럼 나란히 lane이 있는 경우 좌우 방향키로 건너편 lane 첫번째 block으로 건너가게 해주세요.
	- 가장 왼쪽 첫번째 block에서 좌방향키 클릭하면 위쪽 바같 블록으로
	- 가장 오른쪽 마지막 block에서 우방향키 클릭하면 아래쪽 바같 블록으로
- `O`의 사용법이 혼란스럽습니다. 지금 넣을 위치가 `뒤`인지, `앞`인지, `안쪽`인지 알 수가 없어요. `안쪽`이고 처리블록이 선택되었을 때 `P`하면 동작이 없는 것 같아요. 사용하면서 혼란스럽습니다.
- 선택영역 + `E`는 추가 선택없이 "고른 블록을 새 다이어그램으로 빼고 이벤트 달기(그 자리에는 호출 블록)"으로 동작
	- (세션 중 덧붙인 말) "머리가 없는 다이어그램에서도 이벤트 빼기로 합시다. 머리 달리기는 다른 단축키를 씁시다." → 머리 달기는 M
- 접기 상태를 더블클릭하면 펼치기
- 좌우방향키로는 다이어그램간 이동 하면 안됨: 
	- 헤드에서라면 지금처럼 가능
	- Ctrl + Shift + 좌우방향키로 이동 가능하게 할 것
- Ctrl + 상하방향키: 
	- 컨트롤 블록 내부라면 컨트롤 블록의 위아래 블록으로 이동
	- 일반 블록이라면 그냥 위아래 블록으로 이동
	- (세션 중 덧붙인 말) "다시 정의할께요. Ctrl+상하방향키는 제어블록을 내부까지 포함해서 하나의 블록으로 취급합니다. 제어블록 바로 아래 블록에서 Ctrl+위방향키 하면 그 제어블록 전체가 선택되는 식입니다."
- Ctrl + 좌우방향키: 
	- IF나 Case 내부라면 좌우 옆 브랜치로
	- 일반 블록이라면 그냥 위아래 블록으로 이동
- 호출 블록을 다른 이벤트/메소드를 호출하는 것으로 변경하는 방법 필요
	- 호출 블록에서의 수정은 이벤트 이름바꾸기가 아니라 호출할 이벤트 선택이 편할 것 같음
- 이벤트 헤드에 같은 이름 불가하게 해야함
	- (세션 중 덧붙인 말) "빈 이름을 허용하지 않게 해주세요."
- 캔버스 전체가 선택된 것처럼 파란 굵은 선이 되는데 어떤 의미인가요? 필요한 것인가요?
	- (세션 중 덧붙인 말) "캔버스에 들어오면 첫 블록을 자동으로 고릅시다"
- `U` 단축키 사용법이 혼란스럽습니다. 어쩔때는 동작하고 어쩔때는 아니에요. 접힌 상태에서는 동작하는데 펴기 상태에서는 동작을 안 합니다. 선택영역에 포함되는 모든 접기펴기 영역을 상태에 상관 없이 접기펴기 영역 해제해주세요.
	- (세션 중 덧붙인 말) "이름 붙은 영역보기가 안됩니다. 안 보여요" / "강조영역 기능 요구사항을 없앱시다. 혼란스럽네요. 지금은 접기/펼치기에 집중하겠습니다."
	- (세션 중 덧붙인 말) "\"이름 붙은 영역\" = \"접기펴기 영역\" 인가요? 용어를 정의한 적이 있나요?" → "\"접기 영역\"으로 통일합시다" / "현재는 접기영역 전체를 선택해야 `F`가 동작하는데 접기영역의 일부만 선택하더라고 동작하게 해주세요."
	- (세션 중 덧붙인 말) "접기 영역은 중첩이 되면 좋겠어요"
	- (세션 중 덧붙인 말) "Shift+F: 접기영역 설정, Ctrl+Shift+F 또는 U: 선택 영역을 온전히 다 포함하는 제일 작은 범위의 접기영역 해제, F: 선택영역을 온전히 다 포함하는 제일 작은 범위의 접기영역 접기/펴기"
	- (세션 중 덧붙인 말) "1: `U`는 제어블록 풀기로만 씁시다 / 2: 제어블록 선택 했을 땔 `F`는 좀더 정의를 구체화해야겠어요. 일단 오류입니다: IF제어블록의 한 브랜치 전체를 접기영역으로 만들면 그 영역을 접기펴기하지 못하고 마치 제어블록 전체를 접기한 것처럼 동작합니다."
	- (세션 중 덧붙인 말) "제어블록 `F`시에 접히는 부분들의 이름을 정할 수 있으면 좋겠어요. 실제로 접기 영역을 정한 것은 아니지만 접혔을 때 뭐하는 부분인지는 알 수 있어야죠."
	- (세션 중 덧붙인 말) "복잡해졌네요. 문제를 간단하게 풉시다. 제어블록 선택하고 `F`하면 내부 브랜치의 시퀀스블록을 각각 접기 영역으로 만듭니다. 이렇게하면 제어블록 `F`시 예외케이스가 줄을것 같아요."
	- (세션 중 덧붙인 말) "접기영역의 설명이 원래 코드식을 침범하는 경우가 있습니다. 좋은 방식을 제안해주세요." → 표시 방식 시안 네 가지를 프로토타입에 넣음
	- (세션 중 덧붙인 말) "이름 띠가 좋습니다. 이름 띠를 더불클릭하면 접기도 해주세요."
	- (세션 중 덧붙인 말) "저장되는 그림은 현재 보이는 상태대로 저장하면 좋겠어요" → ADR-0018 제안
	- (세션 중 덧붙인 말) "제어블록 `F`는 예전 방식대로 합시다. 접기영역을 만들지 마세요."
	- (세션 중 덧붙인 말) "더 예전 방식이요. 이름 지정하지 않고 블록n개 표시만 나오는거요."
	- (세션 중 덧붙인 말) "맞습니다만 여기부터 다시 구체화하겠습니다. 제어블록의 브랜치 시퀀스블록 모두가 접기영역으로 되어있다면 제어블록 접었을 때 그 접기영역이 접힌 것으로 해주세요."
