# 요구사항과 UX 규칙 검토

[[01-requirements]]를 처음부터 다시 읽고, **같은 일을 곳마다 다르게 다루는 곳**을 모았습니다. 메인테이너의 요청(2026-10-11)에서 시작했습니다.

> 지금까지의 요구사항과 UX규칙을 검토해봅시다. 사용자 경험이 일관성이 있다면 단순하게 정리가 될 것 같아요.

> `docs/01-requirements`도 우리의 작품입니다. 단순하고 합리적이며 우리가 원하는 결과를 만들고 평가하기에 부족함이 없어야합니다.

> [!info] 읽는 법
> - **1장**이 답하실 곳입니다. 물음마다 "지금 → 장면 → 고를 것 → 추천" 순서로 적었습니다. `Q3: 1`처럼 번호로 답하시면 됩니다. "추천대로"라고만 하셔도 됩니다.
> - **2장**은 새 기능(호출 블록 펴 보기, 치환)입니다.
> - **3장**은 문서의 짜임새입니다.
> - **4장**은 묻지 않고 고칠 것, **5장**은 요구사항에 빠져 있는 것입니다.
> - 이 문서에서는 **어떤 키를 쓸지는 정하지 않습니다.** 명령과 규칙을 먼저 정하고, 키는 그다음(단축키 다시 설계)에 한꺼번에 정합니다. 지금 키를 적은 곳은 "지금 프로토타입이 이렇다"는 뜻입니다.

## 0. 먼저 결론

지금 요구사항의 편집 규칙은 60개쯤이고, 대부분 블록 종류마다 따로 적혀 있습니다. 아래 **공통 규칙 일곱 개**를 받아들이면 그 가운데 절반쯤이 "공통 규칙을 따른다" 한 줄로 줄어듭니다.

| # | 공통 규칙 | 한 줄 | 물음 |
| --- | --- | --- | --- |
| R1 | **고치기** | 글자가 있는 것은 모두 같은 방법으로 고치기 시작하고 끝낸다 | Q1, Q2 |
| R2 | **빈 글자** | 비울 수 없는 칸을 비우면 어디서나 같은 일이 일어난다 | Q3, Q4 |
| R3 | **넣는 자리** | 새로 생기는 것은 고른 것 뒤에, `Shift`는 앞에 | Q5 |

## 1. 물음

### Q1. 고치기를 시작하는 방법 (R1)

**지금.** 글자가 있는 것마다 적힌 방법이 다릅니다.

| 무엇 | 요구사항에 적힌 방법 |
| --- | --- |
| 블록 글자 | 더블클릭, `F2` |
| 호출 블록의 인자와 결과 | `Enter`, `F2`, 더블클릭 |
| 접기 영역의 이름 (접힌 칸, 이름 띠) | `Enter`, `F2` |
| Case 갈래의 이름 | 더블클릭, "단축키"(프로토타입은 `L`) |
| 머리의 이름 | 적혀 있지 않음 |

프로토타입은 이미 블록 글자도 `Enter`로 고칩니다. 요구사항이 뒤처진 것입니다.

**고를 것.**

1. **글자가 있는 것은 모두 `Enter` · `F2` · 더블클릭으로 고친다.** Case 갈래의 이름만 예외로 남는다(갈래 이름은 고를 수 없는 것이라서. → Q10)
2. 지금처럼 곳마다 적는다

**추천: 1.**

### Q2. 더블클릭의 뜻 (R1)

**지금.** 더블클릭은 곳에 따라 뜻이 셋입니다.

| 더블클릭한 곳 | 일어나는 일 | 같은 곳에서 `Enter` |
| --- | --- | --- |
| 블록, 머리, 호출 블록 | 글자 고치기 | 글자 고치기 |
| 접힌 칸 (접힌 접기 영역) | **펼치기** | 이름 고치기 |
| 접힌 줄 ("⋯ 블록 n개") | **펼치기** | (고칠 글자가 없음) |
| 이름 띠 (펴진 접기 영역) | **접기** | 이름 고치기 |

**장면.** 접힌 칸에 "입력 검사"라고 적혀 있습니다. 이름을 "입력값 검사"로 고치려고 더블클릭하면 펼쳐집니다. 블록에서는 더블클릭이 고치기였으므로 놀랍니다.

**고를 것.**

1. **더블클릭은 어디서나 `Enter`와 같다(고치기).** 접고 펴는 것은 접기 · 펴기 명령과, 접힌 칸 · 이름 띠 · 접힌 줄의 왼쪽 끝에 붙는 작은 세모(▸ 접힘, ▾ 펴짐)를 한 번 눌러서 한다. 접힌 줄은 고칠 글자가 없으므로 더블클릭해도 아무 일도 없다
2. 지금대로 둔다. "접힌 것과 이름 띠에서는 더블클릭이 접기 · 펴기"라는 예외를 하나 적는다

**추천: 1.** 세모는 코드 편집기에서 익숙한 모양이고, 접을 수 있는 곳이 어디인지도 눈에 보이게 됩니다. 다만 저장되는 그림에 세모가 들어가는지를 정해야 합니다(추천: 들어가지 않음. 선택 테두리처럼 편집 중에만 뜨는 표시로 봄). 2를 고르셔도 규칙은 서고, 예외가 하나 남을 뿐입니다.

### Q3. `Esc`의 뜻 (R1)

**지금.** 새 머리와 새 접기 영역의 이름을 적을 때 "`Enter`나 `Esc`를 누르면 기본 이름 그대로 둔다"고 적혀 있습니다. 두 키가 같은 뜻입니다. 다른 곳에서 `Esc`가 무슨 뜻인지는 적혀 있지 않습니다.

**고를 것.**

1. **`Enter`는 적은 대로 받아들이고, `Esc`는 고치기 전의 글자로 되돌린다. 어디서나 같다.** 새로 만든 것의 이름을 묻는 자리에서는 "고치기 전의 글자"가 곧 기본 이름이므로, 지금 동작과 결과가 같다. `Esc`는 만든 것 자체를 없애지 않는다(없애려면 실행 취소)
2. 새로 만든 것의 이름을 묻는 자리에서 `Esc`는 만들기까지 취소한다

**추천: 1.** 지금 동작이 바뀌지 않으면서, 예외 문장 둘이 공통 규칙 하나로 줄어듭니다. 고치는 중에 다른 곳을 누르면 `Enter`와 같다(받아들임)는 것도 함께 적겠습니다.

### Q4. 비울 수 없는 칸을 비웠을 때 (R2)

**지금.** 세 곳이 세 가지로 다릅니다.

| 무엇 | 비우고 `Enter`를 누르면 |
| --- | --- |
| 머리의 이름 | 받아들이지 않고 고치던 칸을 다시 연다 |
| 호출 블록의 인자 (받는 것이 있는 Method) | 머리의 괄호 안 글자가 다시 들어간다 |
| 접기 영역의 이름 | 이름이 없는 것으로 보고 "첫 블록 글자 외 n개"를 보여 준다 |
| 처리 블록 · 조건 | 비워 둘 수 있다 (빈 블록) |

머리의 이름은 **겹칠 때도** 받아들이지 않고 칸을 다시 엽니다.

**장면.** 머리 `sort(a)`를 고치다가 다 지우고 `Enter`를 눌렀습니다. 칸이 다시 열립니다. `Esc`를 눌러야 빠져나옵니다. 호출 블록에서 같은 일을 하면 조용히 원래 글자가 들어갑니다.

**고를 것.**

1. **비울 수 없는 칸을 비우면 그 칸의 기본 글자가 들어간다. 칸을 다시 열지 않는다.** 기본 글자는 칸마다 하나씩 정해 둔다: 머리는 고치기 전의 이름, 호출 블록의 인자는 머리의 괄호 안 글자(지금대로), 접기 영역의 이름은 "첫 블록 글자 외 n개"(지금대로). 머리의 이름이 **겹칠 때만** 칸을 다시 열고 겹친다고 알린다
2. 지금대로 둔다

**추천: 1.** 바뀌는 것은 "머리의 이름을 비웠을 때" 하나뿐입니다.

> [!question]- 더 줄일 수도 있습니다: 겹친 이름도 받아들이기 (Q4-b)
> 지금도 이름이 겹친 파일은 "그대로 열고, 겹친 머리에 표시를 붙여 알린다"고 정해져 있습니다. 편집 중에 겹친 이름을 적었을 때도 **받아들이고 같은 표시를 붙이면**, "받아들이지 않고 칸을 다시 연다"는 규칙이 통째로 없어집니다. 편집기에 "입력을 막는 자리"가 하나도 남지 않습니다.
> 걸리는 것: 호출 블록의 목록에 같은 이름이 둘 보입니다. 호출 블록이 Method를 이름이 아닌 것(id)으로 가리킨다면 동작은 문제없습니다(이것은 아직 쓰지 않은 ADR의 일입니다).
> **추천: 지금은 하지 않음.** 2026-10-10에 "겹칠 수 없다"로 확인하신 것이고, 가리키는 방식이 정해진 뒤에 다시 볼 수 있습니다. 하고 싶으시면 `Q4-b: 한다`로 답해 주세요.

### Q5. 새로 생기는 것의 자리 (R3)

**지금.**

| 무엇 | 자리 |
| --- | --- |
| 새 블록 | 고른 블록 뒤. `Shift`는 앞 |
| 붙여넣기 | 고른 블록 뒤 (앞에 붙이는 방법 없음) |
| 새 Case 갈래 | 지금 갈래 뒤 (앞에 넣는 방법 없음. 첫 갈래 앞에는 넣을 수 없음) |
| 새 다이어그램 | 그 종류의 맨 뒤 |
| 감싼 제어 블록, 빼고 남은 호출 블록 | 고른 것이 있던 자리 |

**고를 것.**

1. **새로 생기는 것은 고른 것 뒤에 놓인다. `Shift`를 함께 누르면 앞에 놓인다. 블록 · 붙여넣기 · 갈래 모두 같다.** 고른 것을 바꿔 놓는 명령(감싸기, 빼기)은 고른 것이 있던 자리에 놓인다. 새 다이어그램은 지금대로 그 종류의 맨 뒤(다이어그램은 "고른 것"이 블록일 때가 많아서 뒤 · 앞을 말하기 어렵다)
2. 지금대로 둔다

**추천: 1.** inbox에 적으신 Vim의 `p`(뒤에 붙이기) · `P`(앞에 붙이기)가 바로 이 규칙입니다. 키를 정할 때 그대로 들어맞습니다.

### Q6. 순서 바꾸기를 명령 하나로 (R4)

**지금.** 순서를 바꾸는 일이 넷인데 방법이 제각각이고, 둘은 방법이 정해지지 않았습니다.

| 무엇 | 지금 |
| --- | --- |
| 블록 (하나, 선택 영역) | 드래그만. **키보드로 옮기는 방법이 없음** |
| If의 참 · 거짓 | "갈래 바꾸기" 명령 |
| Case의 갈래 | "옆 갈래와 맞바꾸기". 방법 미정 |
| 다이어그램 | "순서를 바꿀 수 있다". 방법 미정 |

4장의 접근성 요구사항은 "키보드 전용 조작"인데, 블록을 키보드로 옮길 수 없습니다(잘라내고 붙이면 되기는 합니다).

**고를 것.**

1. **"옮기기" 명령 하나를 둔다: 위로 · 아래로 · 왼쪽으로 · 오른쪽으로.** 고른 것에 따라 듣는다.
	- 블록이나 선택 영역을 골랐으면: 위 · 아래로 옮기면 같은 줄의 앞 · 뒤 블록과 자리를 바꾼다. 줄의 끝에서 더 옮기면 담고 있는 제어 블록의 밖으로 나온다
	- If · Case 안에서 왼쪽 · 오른쪽으로 옮기면: 지금 갈래를 옆 갈래와 통째로 맞바꾼다. If의 "참 · 거짓 바꾸기"는 이것과 같은 일이 된다. default는 지금대로 움직이지 않는다
	- 머리를 골랐으면: 그 다이어그램의 순서를 앞 · 뒤로 바꾼다(같은 종류 안에서)
	- 드래그는 같은 일을 마우스로 하는 방법이다
2. 블록은 드래그와 잘라내기 · 붙이기로만 옮긴다. 갈래와 다이어그램의 순서만 명령을 둔다
3. 시안으로 본 뒤 정한다

**추천: 1.** 부채에 있던 "순서를 바꾸는 방법"이 여기서 함께 풀립니다. 블록을 옆 제어 블록 **안으로** 옮겨 넣는 것은 이 명령에 넣지 않았습니다(드래그나 잘라내기 · 붙이기로). 넣으면 "위로 한 번"의 결과를 내다보기 어려워집니다.

### Q7. 푸는 명령을 하나로 (R5)

**지금.** 블록들을 묶는 명령이 셋이고, 푸는 명령이 둘이며, 하나는 짝이 없습니다.

| 묶기 | 풀기 |
| --- | --- |
| 감싸기: 블록들 → 제어 블록 | 제어 블록 풀기 (`U`) |
| 접기 영역 만들기: 블록들 → 접기 영역 (`Shift`+`F`) | 접기 영역 풀기 (`Ctrl`+`Shift`+`F`) |
| Method로 빼기: 블록들 → Method와 호출 블록 (`M`) | **없음** ← inbox의 "CallBlock을 호출되는 다이어그램으로 치환하는 기능" |

inbox에 적으신 치환이 바로 빠져 있던 셋째 짝입니다.

**고를 것.**

1. **"풀기" 명령 하나를 둔다. 고른 것에 따라 듣는다.**
	- 제어 블록을 골랐으면: 제어 블록만 없애고 안의 블록을 남긴다 (지금대로)
	- 접기 영역을 골랐으면(접힌 칸이나 이름 띠): 영역과 이름만 없애고 블록을 남긴다
	- 호출 블록을 골랐으면: 호출 블록을 부르던 Method의 블록들로 바꾼다 (새 기능. 세부는 2.2)
	- 그 밖의 것을 골랐으면 아무 일도 하지 않는다
2. 지금처럼 푸는 명령을 따로 둔다 (치환을 넣으면 셋이 됨)

**추천: 1.** 달라지는 것이 하나 있습니다. 지금 접기 영역 풀기는 "고른 것을 담는 가장 작은 접기 영역"에 듣습니다(안쪽 블록 하나만 골라도 됨). 1에서는 **접힌 칸이나 이름 띠를 골라야** 풀립니다. 내용을 바꾸는 명령이 고르지 않은 것에 듣지 않게 하려는 것입니다(→ Q8).

### Q8. 고른 것이 명령의 대상이 아닐 때 (R6)

**지금.** 명령마다 다릅니다.

- 접기 · 펴기: 고른 것이 접을 수 있는 것이 아니면 "고른 것을 담는 가장 작은 접기 영역"을 찾아 올라간다
- 접기 영역 풀기: 마찬가지로 찾아 올라간다
- 제어 블록 풀기, 호출 블록의 명령(부를 Method 바꾸기, 따라가기): 고른 것에만 듣는다
- 붙여넣기: 고른 것이 없으면 붙이지 않는다

**고를 것.**

1. **보기만 바꾸는 명령(접기 · 펴기)은 고른 것을 담는 가장 가까운 대상을 찾아 올라간다. 내용을 바꾸는 명령은 고른 것에만 듣고, 대상이 아니면 아무 일도 하지 않는다**
2. 모든 명령이 고른 것에만 듣는다 (접기 · 펴기도 접힌 칸 · 이름 띠 · 제어 블록을 골라야 함)
3. 지금대로 둔다

**추천: 1.** 접기 · 펴기는 잘못 눌러도 한 번 더 누르면 돌아오므로 너그러워도 됩니다. 내용을 바꾸는 명령이 고르지 않은 것을 바꾸면 놀랍니다.

### Q9. 실행 취소의 대상 (R7)

**지금.** "접고 펴기는 대상이 아니다, 접기 영역을 만들고 푸는 것은 대상이다"만 적혀 있습니다. 나머지는 적혀 있지 않습니다.

**고를 것.**

1. **파일의 내용(블록, 글자, 구조, 접기 영역과 그 이름, 머리와 종류, 다이어그램의 순서)을 바꾸면 실행 취소의 대상이다. 보기 상태를 바꾸면 대상이 아니다.** 보기 상태는 접힘 · 펴짐, 호출 블록 펴 보기(2.1), 이름 띠 켜고 끄기, 결과 기호(`←` / `=`), 확대와 화면 이동이다
2. 결과 기호는 내용으로 본다 (대상)

**추천: 1.** 결과 기호는 "같은 내용을 어떻게 보여 주는가"이고 설정 화면에서 바꾸는 것이라 보기 상태 쪽에 넣었습니다. 이 구분은 ADR-0018이 이미 파일 안에서 나눠 둔 "내용"과 "보기 상태"와 같은 금입니다.

### Q10. 고를 수 있는 것의 목록

**지금.** 무엇을 고를 수 있는지가 한곳에 적혀 있지 않습니다. 흩어진 문장을 모으면 이렇습니다.

| 고를 수 있는 것 | 여럿을 함께 | 적힌 곳 |
| --- | --- | --- |
| 블록 (빈 블록 포함) | 됨 (선택 영역) | 3.2 |
| 머리 | 안 됨 | 3.2 여기저기 |
| 접힌 칸 (접힌 접기 영역) | 블록 하나처럼 | 접기 |
| 접힌 줄 ("⋯ 블록 n개") | 블록 하나처럼 | 접기 |
| 이름 띠 | 고르면 접기 영역 전체가 골라짐 | 접기 |
| **Case 갈래의 이름, 갈래** | **고를 수 없음** | — |
| **다이어그램** | **고를 수 없음** (머리로 대신함) | — |

갈래를 고를 수 없어서 갈래에 듣는 명령(넣기, 빼기, 이름 고치기, 순서 바꾸기)은 모두 "지금 갈래"(고른 블록이 든 갈래)에 듣고, 키도 따로 씁니다(`+` `-` `L`). 머리가 없는 다이어그램은 지우거나 순서를 바꿀 때 가리킬 것이 없습니다.

**고를 것.**

1. **목록을 요구사항에 표로 적는다. 갈래는 지금처럼 고를 수 없는 것으로 두고, "지금 갈래 = 고른 블록이 든 갈래"라고 한 번 정의한다.** 머리가 없는 다이어그램에서는 "첫 블록을 고른 것"이 머리를 고른 것을 대신한다고 적는다
2. 갈래의 이름도 고를 수 있게 한다 (방향키가 갈래 이름에 멈추고, `Enter`로 고치고, 지우기 · 옮기기가 갈래에 듣는다). 갈래 전용 키 셋(`+` `-` `L`)이 없어진다
3. 2를 시안으로 본 뒤 정한다

**추천: 1.** 2는 규칙으로는 가장 깔끔하지만, 방향키가 멈추는 곳이 늘어 If · Case를 지나가기가 번거로워집니다. If의 "참" · "거짓"에도 멈춰야 하는지도 새로 정해야 합니다.

### Q11. 좌우 이동을 한 겹 줄이기

**지금.** 좌우로 가는 키가 세 겹입니다.

| 키 | 하는 일 |
| --- | --- |
| `←` `→` | 옆 갈래의 첫 블록으로. 맨 왼쪽 갈래에서 `←`는 그 제어 블록으로, 맨 오른쪽 갈래에서 `→`는 제어 블록의 다음 블록으로. 머리에서는 옆 다이어그램으로 |
| `Ctrl`+`←` `→` | 옆 갈래의 첫 블록으로. 갈래가 더 없으면 **한 겹 바깥** If · Case의 옆 갈래로. If · Case 밖에서는 위 · 아래 블록으로 |
| `Ctrl`+`Shift`+`←` `→` | 옆 다이어그램으로 |

`←` `→`와 `Ctrl`+`←` `→`는 갈래의 끝에서만 다릅니다. 그리고 If · Case 밖에서 `←` `→`가 무엇을 하는지는 요구사항에 없습니다.

**고를 것.**

1. **`Ctrl`+`←` `→`를 없앤다.** `←` `→`는 지금대로 두고, If · Case 밖에서는 아무 일도 하지 않는다고 적는다. 좌우 키는 두 겹이 된다: 갈래를 건너기, 다이어그램을 건너기
2. 지금대로 세 겹을 둔다. If · Case 밖에서의 `←` `→`만 적는다
3. 한 겹으로 줄인다: `←` `→`는 옆 갈래로, 갈래가 더 없으면 바깥의 옆 갈래로, 그것도 없으면 옆 다이어그램으로 간다

**추천: 1.** 2026-10-10에 프로토타입을 써 보시며 하나씩 정하신 것이라, 써 보신 느낌이 저의 추천보다 무겁습니다. `Ctrl`+`←` `→`를 실제로 쓰셨다면 2를 고르세요. `Ctrl`+`↑` `↓`(제어 블록을 한 덩어리로 건너뛰기)는 그대로 둡니다.

### Q12. "빼기"라는 말

**지금.** "빼기"가 두 가지 뜻으로 쓰입니다: **갈래 빼기**(갈래를 안의 블록과 함께 지움)와 **Method로 빼기**(블록을 새 Method로 옮기고 호출 블록을 남김). 지우는 말도 셋입니다: 지우기, 빼기, 떼기(머리).

**고를 것.**

1. **"갈래 빼기"를 "갈래 지우기"로 바꾼다.** "빼기"는 Method로 빼기에만 쓴다. "머리 떼기"는 그대로 둔다(머리만 없어지고 다이어그램은 남으므로 지우기와 다름)
2. 지금대로 둔다

**추천: 1.**

## 2. 새 기능: 호출 블록

inbox에 적으신 두 가지입니다. 둘 다 위의 공통 규칙에 들어맞습니다.

### 2.1 호출 블록 펴 보기 (R6)

> CallBlock은 지금처럼 호출명을 보여주는 모드와, 호출되는 다이어그램을 치환해서 보여주는 모드(실제로 치환되는 것은 아님)가 있어 마치 접기 영역 펼지고 접듯이 보여줄 수 있다.

접기 · 펴기 명령이 듣는 것에 호출 블록을 더하면 됩니다. 접을 수 있는 것이 셋이 됩니다: 제어 블록의 안쪽, 접기 영역, **호출 블록**. 호출 블록은 처음에 접힌 모습(지금 모습)이고, 펴면 부르는 Method의 블록들이 그 자리에 보입니다.

공통 규칙에서 저절로 정해지는 것:

- 펴고 접는 것은 보기 상태다. 실행 취소의 대상이 아니다 (R7)
- 저장되는 그림은 화면 그대로이므로 펴진 채로 저장된다. 펴짐 상태도 파일에 저장된다 (ADR-0018)
- 접기 · 펴기 명령과, Q2에서 1을 고르면 세모로 펴고 접는다

정해야 할 것은 시안으로 보여 드리겠습니다. 말로는 견주기 어렵습니다.

- **Q13. 펴 보인 블록을 고칠 수 있는가.** 추천: **고칠 수 없다.** 고르면 Method의 원래 블록으로 따라갈 수 있을 뿐이다. 여기서 고치면 그 Method를 부르는 모든 곳이 함께 바뀌는데, 그것이 화면에서 보이지 않는다
- **Q14. 재귀.** 퀵소트는 자기를 부른다. 펴 보인 안쪽의 호출 블록은 접힌 모습(지금 모습)으로 보이고, 그것도 펼 수 있는지. 추천: **한 겹만.** 펴 보인 안쪽의 호출 블록은 펼 수 없다. 깊이마다 펴짐 상태를 기억하는 일이 없어진다
- **Q15. 펴 보인 모습.** 호출 블록의 이중선 테두리 안에 Method의 블록들을 넣고, 맨 위에 `p ← partition(a, lo, hi)` 줄을 남기는 모양을 생각하고 있습니다. 시안에서 두세 가지를 견주겠습니다

### 2.2 호출 블록을 Method의 블록들로 바꾸기 (R5)

> CallBlock을 호출되는 다이어그램으로 치환하는 기능.

Q7의 "풀기"가 호출 블록에 듣는 경우입니다. Method로 빼기의 반대입니다.

- 호출 블록이 있던 자리에 Method의 블록들이 **복사되어** 들어간다. Method는 그대로 남는다(다른 곳에서 부를 수 있으므로). 부르는 곳이 없어져도 저절로 지우지 않는다
- 실행 취소 한 번으로 되돌린다 (R7)
- **Q16. 인자와 결과.** `p ← partition(a, lo, mid)`를 풀면, Method 안의 글자는 머리에 적힌 이름(`a, lo, hi`)으로 되어 있습니다. 편집기는 글자 안을 검사하지 않으므로(ADR-0022) 바꿔 적을 수 없습니다. 추천: **글자는 그대로 복사한다.** 호출 블록에 적혀 있던 인자와 결과는 사라진다. 사용자가 손으로 맞춘다
- **Q17. 이어진 곳이 없는 호출 블록.** 추천: 풀 수 없다(아무 일도 하지 않는다)

## 3. 문서의 짜임새

지금 [[01-requirements]]는 결정이 날 때마다 그 자리에 문장을 덧붙여 왔습니다. 그래서 규칙을 찾기 어렵고, 시험을 쓰려면 여러 곳을 맞춰 읽어야 합니다.

**보이는 문제.**

- **규칙이 엉뚱한 항목 아래에 있다.** "새 Method로 빼기"(`^edit-extract`) 아래에 새 빈 다이어그램 만들기, 머리 달기, 종류 바꾸기, `E` · `M` 키가 달려 있다. Event 머리(`^blk-event`) 아래에 Method의 이름 규칙이 있다
- **키가 규칙 문장에 섞여 있다.** 어떤 명령은 키가 적혀 있고(`F`, `U`, `E`, `M`, `Tab`, `Ctrl`+방향키), 어떤 명령은 없다(블록 넣기, 호출, 감싸기, 갈래). 키를 다시 설계하면 문서 곳곳을 고쳐야 한다
- **명령이 어떻게 실행되는지가 감싸기에만 적혀 있다.** "단축키, 우클릭 메뉴, 도구 모음 모두 지원"
- **블록 종류 표의 블록 가운데 규칙이 없는 것이 있다.** For, 탈출, 병렬, 주석
- **평가할 기준이 없는 문장.** "편집을 방해하지 않는 자리", "옆으로 긴 띠가 되지 않도록", "16 : 10에 가까워지게"

**제안하는 짜임 (Q18).** 3장 "기능 요구사항"의 3.1과 3.2를 아래 순서로 다시 짭니다. 2장(배포 대상), 3.3 뒤(레이아웃, 파일 형식, 내보내기), 4장 뒤는 손대지 않습니다.

| 절 | 담는 것 |
| --- | --- |
| 개념 | 문서 · 다이어그램 · 머리 · 블록 · 갈래 · 빈 블록. 고를 수 있는 것의 표 (Q10) |
| 공통 규칙 | R1~R7. 규칙마다 블록 ID. 예외는 그 규칙 아래에 모두 적는다 |
| 블록 | 블록 종류마다 "모양, 글자, 이 블록에만 있는 규칙". 공통 규칙과 같은 것은 적지 않는다 |
| 명령 | 명령마다 "무엇을 골랐을 때 듣는가 → 무슨 일이 일어나는가 → 끝난 뒤 무엇이 골라져 있는가". 표로 |
| 이동과 선택 | 방향키, 여러 블록 선택 |
| 단축키 | 명령과 키의 표 **하나**. 키는 여기에만 적는다 |

- **기존 블록 ID(`^edit-wrap` 등)는 그대로 둡니다.** 승인된 ADR이 이 ID로 가리키고 있고, 승인된 ADR의 본문은 고치지 않기 때문입니다. 같은 까닭으로 파일을 여럿으로 쪼개지 않고 `01-requirements.md` 하나로 둡니다
- **까다로운 규칙에는 장면을 하나씩 붙입니다** ("이것을 고르고 → 이 명령을 하면 → 이렇게 된다"). 시험 설계가 이 장면에서 바로 시작할 수 있습니다

**고를 것 (Q18).** 1. 이 짜임으로 다시 짠다 / 2. 지금 짜임을 두고 문장만 고친다. **추천: 1.**
