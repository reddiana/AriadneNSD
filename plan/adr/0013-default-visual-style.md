# ADR-0013: 기본 시각 스타일은 차분한 바탕 + 옅은 색조, 색은 테마로 분리

## 배경

블록에 색을 넣어 다이어그램을 아름답고 읽기 쉽게 만들고 싶다. 사용자가 이상향으로 꼽은 [EasyCODE](https://www.easycode.de/)는 블록을 옅은 단색으로 두고, 색은 글자(키워드, 주석)에 쓴다. ([[01-requirements#3.3 레이아웃 · 렌더링]])

같은 NS 차트를 세 가지 시안으로 그려 비교했다. → [시안 페이지](https://claude.ai/artifact/XVzT38DvGVir97z9j47Aaj), 사본 `journal/assets/2026-10-09-ns-color-study.html`

## 결정 기준

- 로직(조건, 실행 내용)이 상자보다 먼저 읽혀야 한다.
- 반복, 분기, 호출을 한눈에 구분할 수 있어야 한다.
- 흑백으로 인쇄해도 읽혀야 한다.
- 나중에 색을 바꿀 수 있어야 한다.

## 검토한 대안

### A. 종류별 진한 색 + 깊이별 명도 + 그라디언트 (Scratch식)

- 장점: 반복, 분기, 호출이 색으로 바로 구분됨. 중첩 깊이가 보임
- 단점: 글자보다 상자가 먼저 보임. 흑백 인쇄에서 구분이 사라짐

### B. 옅은 단색 바탕 + 가는 파랑 선 + 구문 강조 (EasyCODE식)

- 장점: 내용이 먼저 읽힘. 차분하고 흑백 인쇄에 강함
- 단점: 반복과 분기의 구분이 선 모양에만 기댐

### C. B의 바탕 + 반복·분기·호출 머리에 옅은 색조

- 장점: B의 차분함을 유지하면서 구조도 은은하게 구분됨
- 단점: 색조가 옅어서 모니터에 따라 차이가 약하게 보일 수 있음

## 결정

**C를 기본 스타일로 한다.** 색은 렌더러에 박아 넣지 않고 **테마**로 분리한다. 기본 스타일도 테마 하나로 구현한다.
- 테마는 블록 종류별 배경색, 선 색과 굵기, 글자 색(기본, 키워드, 주석), `then`/`else` 표시 색, 글꼴을 정한다.
- 블록의 모양과 크기는 테마와 무관하다. 테마를 바꿔도 레이아웃은 그대로다.

## 결과

- 좋아지는 점: A 같은 화려한 스타일이나 사용자 정의 색은 테마를 추가하는 것으로 해결된다.
- 감수하는 점: 처음부터 색을 테마 값으로 다뤄야 해서 렌더러 설계가 조금 복잡해진다.
- 후속 작업: 구문 강조의 범위 결정([[01-requirements#6. 미결정 사항]]), 저장된 SVG의 색을 고정할지 보는 환경 테마를 따를지 결정, 설계 문서 [[02-layout]]에 테마 구조 추가
