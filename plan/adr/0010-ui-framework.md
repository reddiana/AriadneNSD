# ADR-0010: UI 프레임워크

## 배경

`packages/editor`(편집 UI)를 만들 방식을 정해야 한다. 편집 화면의 중심은 SVG로 그린 다이어그램이고, 그 주변에 도구 모음·메뉴·텍스트 편집 입력창이 있다.

## 결정 기준

- Obsidian 플러그인 번들 크기 (가벼울수록 좋음)
- 블록 500개 규모에서 편집 반응 100ms 이내 ([[01-requirements#^nfr-perf]])
- 세 셸 모두에 같은 방식으로 붙일 수 있어야 함
- 학습·유지보수 비용

## 검토한 대안

### 프레임워크 없음 (순수 TypeScript + DOM)

- 장점: 의존성 없음, 번들 최소. 다이어그램은 어차피 렌더러가 SVG를 만들므로 프레임워크 이점이 작음
- 단점: 도구 모음·메뉴·대화상자 같은 일반 UI를 직접 관리해야 함

### Svelte

- 장점: 컴파일 결과가 작음, Obsidian 플러그인 사례가 많음 (공식 문서에도 사용법 안내)
- 단점: 빌드 설정 추가

### React

- 장점: 생태계가 가장 큼
- 단점: 런타임 크기가 큼, 대규모 SVG 갱신에는 추가 최적화 필요

## 결정

미정.
