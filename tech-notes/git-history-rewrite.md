# git 기록에서 파일 지우기

## 한 줄 요약

파일을 지우고 커밋해도 **예전 커밋에는 그 파일이 그대로 남습니다.** 기록에서까지 없애려면 기록을 고쳐 쓰고 강제로 push해야 하고, 그러면 커밋 해시가 바뀝니다.

## 백엔드로 비유하면

- **커밋 기록** = 덧붙이기만 하는 감사 로그(append-only log). "지웠다"는 것도 한 줄의 새 기록일 뿐, 앞의 기록은 그대로입니다. 그래서 누구나 예전 커밋을 열어 지운 파일을 볼 수 있습니다.
- **커밋 해시** = 내용과 부모 해시로 계산한 체크섬. 블록체인처럼 앞의 커밋이 바뀌면 그 뒤의 모든 커밋 해시가 달라집니다.
- **기록 고쳐 쓰기**(`git filter-branch`, `git filter-repo`) = 로그를 처음부터 다시 재생하면서 특정 행만 빼고 새 로그를 만드는 일. 결과는 "같은 내용, 다른 해시"의 새 기록입니다.
- **강제 push**(`git push --force-with-lease`) = 서버의 테이블을 통째로 바꿔치기. 보통의 push는 덧붙이기만 허용하므로, 고쳐 쓴 기록은 강제로만 올릴 수 있습니다. `--force-with-lease`는 "내가 마지막으로 본 뒤에 남이 올린 것이 없을 때만"이라는 낙관적 잠금입니다.
- **GitHub에 남는 흔적** = 지운 행이 가비지 컬렉션 전까지 디스크에 남는 것. 강제 push 뒤에도 옛 커밋은 해시를 아는 사람이 한동안 직접 열 수 있습니다. 완전히 없애려면 GitHub 지원에 요청합니다.

비밀번호나 키가 올라갔을 때도 같은 방법을 쓰지만, 그때는 기록을 지우는 것보다 **그 비밀번호를 바꾸는 것이 먼저**입니다. 이미 누가 봤을 수 있기 때문입니다.

## AriadneNSD에서 어디에 쓰나

- 2026-10-10에 inbox에 붙여 넣은 참고 사진 9장이 커밋되어 GitHub에 올라갔습니다. 출처를 모르는 사진이라 2026-10-11에 저장소에서 지웠고, 메인테이너가 기록에서도 지우기로 정했습니다.
- 지우는 스크립트는 `plan/rewrite-history.sh`에 있습니다. 백업 만들기, 기록에서 빼기, 지금의 로고 그림 다시 넣기, 남은 것이 없는지 확인하기, 강제 push의 순서입니다.
- Claude Code는 Claude가 기록을 고쳐 쓰는 명령을 실행하지 못하게 막습니다. 되돌릴 수 없는 일이라 사람이 직접 실행하게 한 것입니다.
- 실행하면 inbox 보존 커밋부터 뒤의 해시가 모두 바뀌어, 세션 기록에 적힌 그 뒤의 해시는 찾을 수 없게 됩니다.
