M30 · 파일 형식의 이름

MVP 전에 정할 것 가운데 "파일에 남아 나중에 바꾸기 어려운 것"의 마지막입니다. 저장되는 .ns.svg 파일 안에서 우리 모델이 든 요소는 네임스페이스 URI라는 이름으로 다른 프로그램의 데이터와 갈립니다. 이 이름은 모든 파일에 영원히 남습니다. 각 물음의 1번이 Claude의 추천입니다. 노랗게 칠한 곳이 안마다 달라지는 부분입니다.

N1

N1. 네임스페이스 URI를 무엇으로 할까

결정함 (2026-10-25): 3번 저장소 주소 그대로(메인테이너가 고름). 접두어는 ans입니다. → ADR-0035

URI는 주소처럼 생긴 이름입니다. 그 주소가 실제로 열릴 필요는 없고, 다른 누구의 이름과 겹치지만 않으면 됩니다. 그래서 보통 자기가 가진 주소를 바탕으로 짓습니다(Inkscape는 http://www.inkscape.org/namespaces/inkscape). 판 번호는 넣지 않습니다. 판은 version 속성이 따로 나르고, 판마다 이름을 바꾸면 옛 파일을 못 알아봅니다.

N1 · 1번

펴낸 사이트의 주소

Claude의 추천
<metadata>
  <ans:document version="1"
    xmlns:ans="https://reddiana.github.io/AriadneNSD/ns">
    <![CDATA[{ "format": "ariadne-nsd", … }]]>
  </ans:document>
</metadata>
  • 이미 가진 주소입니다(GitHub Pages, DR-0013). 돈이 들지 않습니다.
  • 그 주소에 "이 파일 형식은 무엇인가"를 알리는 짧은 페이지를 두어, 파일을 연 사람이 따라와 명세를 읽게 할 수 있습니다.
  • 계정 이름 reddiana가 들어갑니다. 나중에 저장소를 옮기거나 도메인을 사도 이 이름은 그대로 둡니다(이름일 뿐이라 동작에는 문제가 없습니다).
N1 · 2번

도메인을 사서

<ans:document version="1"
  xmlns:ans="https://ariadnensd.com/ns">
  • 가장 깔끔하고, 계정 이름과 상관없습니다.
  • 해마다 돈이 듭니다(.com 10~11달러). 갱신하지 않으면 남이 그 주소를 가져가, 파일 속 이름이 남의 사이트를 가리키게 됩니다.
  • 도메인은 아직 사지 않았습니다(등록 기록만 조회함, 2026-10-10).
N1 · 3번

저장소 주소 그대로

<ans:document version="1"
  xmlns:ans="https://github.com/reddiana/AriadneNSD">
  • 지금 가진 주소입니다.
  • 그 주소는 저장소의 첫 화면이지 형식을 알리는 곳이 아닙니다. 1번과 같은 계정 이름 문제도 있습니다.
N1 · 4번

주소가 아닌 이름 (URN)

<ans:document version="1"
  xmlns:ans="urn:ariadne-nsd:model">
  • 어느 주소에도 매이지 않습니다.
  • URN은 IANA에 등록한 이름공간만 정식입니다. ariadne-nsd는 등록되지 않아 규칙에 맞지 않습니다. 따라올 페이지도 둘 수 없습니다.
N2

N2. 프로토타입이 저장한 파일을 열까

결정함 (2026-10-25): 1번 열지 않는다. → ADR-0035

프로토타입은 버리는 코드이고, 그 파일(version: 0)은 이 형식의 v1이 아닙니다. 모델이 네임스페이스 없이 <metadata id="ariadne-nsd-model">에 바로 들어 있고, 접기 영역 · 갈래 이름 · 머리의 짜임도 다릅니다(파일 형식 명세 7장).

N2 · 1번

열지 않는다

Claude의 추천
<metadata id="ariadne-nsd-model">{ "version": 0, … }</metadata>

→ "AriadneNSD 형식이 아닙니다. 편집할 수 없습니다."
  (그림은 그대로 보이고, 파일은 건드리지 않음)
  • v0을 읽는 코드와 시험을 제품에 영원히 지고 가지 않습니다.
  • 프로토타입 파일은 메인테이너가 리뷰하며 만든 것뿐입니다. 그림으로는 어디서나 그대로 보입니다.
  • 프로토타입으로 그려 둔 것을 제품에서 이어 고치려면 다시 그려야 합니다.
N2 · 2번

열어서 v1로 바꾼다

v0 → v1 마이그레이션 함수
  metadata#ariadne-nsd-model → ans:document
  range 노드 → 줄에 붙은 마커
  yes/no/c0 → 갈래 id …
  • 프로토타입으로 그린 것을 그대로 이어 고칩니다.
  • 프로토타입은 아직 바뀌는 중이라, 판마다 달라진 v0을 모두 맞춰야 합니다. 이 코드와 시험이 제품에 남습니다.
N2 · 3번

따로 바꾸는 스크립트만

node convert-v0.mjs 옛그림.ns.svg
→ 옛그림.v1.ns.svg
  • 제품은 열지 않고, 필요한 사람만 저장소의 스크립트로 한 번 바꿉니다.
  • 스크립트도 프로토타입이 바뀔 때마다 맞춰야 합니다. 쓰는 사람이 사실상 메인테이너 한 사람입니다.

답하실 것

  1. N1, N2를 하나씩, 번호 또는 고칠 점.
  2. 모델 요소의 이름(ans:document)과 JSON의 필드 이름은 모델 설계를 굳히며 Claude가 정하고 확인받습니다.
  3. 정하면 파일 형식 명세(2장의 예시, 6장 미결정, 7장)와 결정 기록에 옮깁니다.
