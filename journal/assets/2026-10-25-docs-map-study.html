M31 · 문서 지도

inbox 요청: "docs/README#문서 지도를 구조를 이해하기 쉽게 만들어 주세요." 지금 지도는 열한 줄짜리 표 하나라서 폴더 여섯(01~06)이 보이지 않고, "요구사항이 UX 설계와 아키텍처의 입력"이라는 흐름이 글로만 있습니다. 상세 설계는 아래에 따로 표가 있습니다. 세 가지 모양을 실제 문서 내용으로 그렸습니다. 1번이 Claude의 추천입니다.

D1

D1. 지도를 어떤 모양으로 할까

결정함 (2026-10-25): 1번 흐름 그림 + 폴더별 표(메인테이너가 고름). 표의 열은 문서 · 답하는 질문 · 상태 · 바뀌는 때입니다.

세 안 모두 Obsidian과 펴낸 사이트에서 그대로 그려지는 것(Mermaid, 표, 목록)만 씁니다. 미리보기는 문서에 들어갈 모습입니다.

03 아키텍처, 05 명세, 06 용어집도 같은 모양
  • 그림으로 순서와 입력 관계를 한눈에 보고, 표에서 문서를 찾습니다.
  • 폴더 번호(01~06)가 제목에 그대로 나와 GitHub 폴더 목록과 맞습니다.
  • 따로 있던 상세 설계 표가 지도 안으로 들어와 한 곳이 됩니다.
  • 표가 여섯 개라 지금보다 깁니다.

질문과 상태는 그림 아래 짧은 목록으로
  • 구조 전체가 그림 한 장입니다.
  • 펴낸 사이트에서는 그림 속 이름을 눌러 문서로 갈 수 없습니다(Obsidian은 설정하면 됨). 결국 링크 목록을 또 둬야 합니다.
  • 문서가 늘수록 그림이 커지고, 휴대폰 폭에서는 글자가 작아집니다.
어느 안이든

어느 안을 골라도 함께 고칠 것

  • 문서 이름의 말머리를 뺍니다: "UX 설계: 조작 규칙" → "조작 규칙"(CLAUDE.md의 이름 규칙). 폴더 이름이 그 자리를 맡습니다.
  • 낡은 상태를 바로잡습니다: 모델은 "작성 전"이 아니라 작성 중(2026-10-18 초안), 파일 형식 명세는 초안.
  • "문서를 쓸 때의 원칙" 콜아웃은 지도 아래에 그대로 둡니다.
