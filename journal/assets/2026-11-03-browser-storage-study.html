M55 브라우저 안의 문서 시안

새 요구사항 R-WEB-09(P1, 웹 베타의 문턱): 파일 없이 문서에 이름을 붙여 그 브라우저에 저장하고, 목록에서 열고 지운다. 브라우저 데이터를 지우면 함께 지워진다는 것을 화면에 알리고, 파일로 내보낼 길을 둔다. 본보기는 SequenceDiagram.org의 "Web Storage (localStorage)"입니다. 저장소는 IndexedDB입니다. localStorage는 5 MB쯤에서 막히고, 로컬 백업과 최근 파일이 이미 IndexedDB를 씁니다(상세 설계 웹 1.1, 2).

물음은 BS1~BS4 넷입니다. 선택지마다 번호 딱지가 있고 ★가 Claude의 추천입니다. 그림의 1 같은 작은 딱지는 그 그림에서 새로 생기는 자리입니다. 앱 화면의 그림은 앱의 화면 색을 따른 HTML 모형이라, 글꼴과 아이콘은 실제와 조금 다릅니다.

다른 도구는 어떻게 하나

SequenceDiagram.org

  • 저장 창 · 열기 창에 저장소마다 한 칸씩: File System · Google Drive · OneDrive · Web Storage (localStorage) · Download Folder.
  • Web Storage의 열기 창은 표 하나: 모두 고르기 체크박스, Name · Modified · Size 열, 버튼 Cancel · Delete · Open. 여러 개를 골라 한꺼번에 지웁니다.
  • 설정 "Default (Ctrl+S / Ctrl+O) Storage"에서 기본 저장소를 고릅니다. "Autosave every 10 min", "Alert for unsaved changes", "Synchronize filename with title in diagram"도 있습니다.
  • Web Storage에는 이름 바꾸기 · 모두 내보내기 · 가져오기가 없고, 브라우저 데이터를 지우면 사라진다는 경고도 화면에 없습니다.

draw.io · Excalidraw

  • draw.io: 처음 화면에서 저장 위치를 고르고 그중 하나가 "Browser"입니다. 마지막에 쓴 위치를 기억하고, 브라우저였으면 마지막 문서를 바로 엽니다. "나중에 정하기"를 고르면 브라우저에 남지만 "영구히 저장되지 않을 수 있다"고 안내합니다.
  • Excalidraw: 문서 하나가 늘 브라우저에 자동 저장되고, 이름 붙인 목록은 없습니다. 브라우저 데이터가 지워져 그림을 잃었다는 사용자 글이 있고, 목록 · 내보내기를 더하는 확장 프로그램(ExcaliKeep, Excalisave)이 따로 나와 있습니다.
  • 배울 점: 목록이 없으면 사용자가 따로 만들어 씁니다. 잃는 위험은 화면에 적어 두어야 합니다.

이미 정해져 있는 것

  • 우선순위 P1, 웹 베타 전에 만듭니다(2026-11-03, 메인테이너).
  • 저장소는 IndexedDB이고, 로컬 백업 · 최근 파일과 같은 데이터베이스에 저장소(store)를 하나 더 둡니다.
  • 브라우저 데이터를 지우면 함께 지워진다는 것을 화면에 알리고, 파일로 내보낼 길을 둡니다.
  • 저장되는 텍스트는 파일 저장과 같은 SVG 문자열입니다(같은 모델이면 같은 텍스트). 그래서 내보낸 파일은 .ns.svg 그대로 열립니다.
  • 목록은 그 브라우저에만 있습니다. 다른 기기 · 다른 브라우저와 나누지 않습니다(최근 파일과 같음).

브라우저에 둔 문서에서 Ctrl+S는 어디에 저장할까요?

지금은 "원래 파일"이 하나 있고, Ctrl+S와 자동 저장(Chromium, 편집하고 2초 뒤)은 그 파일에 씁니다. 로컬 백업은 이와 따로, 저장 안 된 편집을 늘 브라우저에 둡니다.

물음의 추천을 고른다고 보고 정해 둔 것입니다. 다르게 하고 싶은 것만 알려 주세요.

무엇정해 둔 것
이름저장 창의 이름 칸은 첫 다이어그램의 헤더 이름(없으면 "제목 없음")으로 채워 둡니다. 화면 문구는 "브라우저에 저장…" · "브라우저의 문서…", 영어 화면은 "Save in Browser…" · "Documents in This Browser…".
같은 이름이미 있는 이름이면 "“병합 정렬”이 이미 있습니다. 바꿀까요?"를 묻습니다(바꾸기 · 취소). 이름은 대소문자 · 앞뒤 공백을 무시하고 견줍니다.
로컬 백업과의 관계브라우저 문서도 1장의 문서 키를 씁니다. 브라우저 문서에 저장되면 파일 저장 때처럼 그 문서의 로컬 백업 칸을 지웁니다. 로컬 백업은 여전히 "저장 안 된 편집"만 맡습니다.
자동 저장BS2의 1번이면, 브라우저 문서는 모든 브라우저에서 편집하고 2초 뒤 자동 저장합니다(설정의 자동 저장 켬/끔을 따름).
최근 파일브라우저 문서도 최근 파일 ▸에 "브라우저" 딱지를 달고 보입니다. 목록에서 지우면 최근 파일에서도 빠집니다.
한 번도 저장하지 않은 새 문서 (US1)다른 문서를 열기 전에 묻는 모달의 버튼을 "버리고 열기 · 취소 · 브라우저에 저장 · 저장"으로 넷으로 합니다. Firefox · Safari에서는 "저장"이 내려받기라, 브라우저 쪽이 더 가볍습니다.
다른 이름으로 저장…브라우저 문서에서 고르면 파일로 저장하고, 그 뒤로 원래 자리는 그 파일입니다. 브라우저의 문서는 목록에 그대로 남습니다.
브라우저가 비우지 않게처음 브라우저에 저장할 때 navigator.storage.persist()를 요청합니다(저장 공간이 모자랄 때 브라우저가 이 사이트의 데이터를 먼저 지우지 않게). 허락되지 않아도 저장은 하고, 경고 문구는 그대로입니다.
저장 공간이 모자랄 때저장이 실패하면 "브라우저의 저장 공간이 모자라 저장하지 못했습니다. 파일로 저장해 주세요."를 알리고 저장 안 됨(●)으로 둡니다.
두 탭같은 브라우저 문서를 두 탭에서 열면 파일과 같은 규칙(나중 탭은 보기만, BroadcastChannel)입니다.
지우기"“병합 정렬”을 이 브라우저에서 지울까요? 되돌릴 수 없습니다."(지우기 · 취소). 지금 연 문서를 지우면 편집 화면은 그대로 두고 저장 안 된 새 문서가 됩니다.
휴대폰목록 모달은 화면 폭에 맞추고, 크기 열은 감춥니다. 버튼은 두 줄로 접힙니다.
