M26 · 유즈케이스 형식

요구사항에 유즈케이스를 들일지, 들이면 어떤 형식으로 쓸지 고르는 시안입니다(2026-10-22, 메인테이너 inbox: "유즈케이스나 사용자스토리를 도입하는 것을 검토하고 의견 주세요").

같은 유즈케이스 하나, "UC-07 노트에 다이어그램을 넣어 보인다"를 세 형식으로 썼습니다. 내용은 지금의 요구사항(^obs-insert, ^obs-edit-embed, ^obs-embed 등)에서 옮겼습니다. 주황 바탕은 그 형식으로 쓰다가 드러난 요구사항의 빈 곳입니다.

기본 흐름

  1. 작성자가 노트 편집 화면의 우클릭 메뉴에서 "Insert new NS diagram"을 고른다
  2. 볼트에 .ns.svg 파일이 생기고 노트의 커서 자리에 ![[…]]가 들어간다
  3. 편집 탭이 열린다 → UC-03 블록을 편집한다
  4. 작성자가 저장한다 → UC-06
  5. 노트의 그림이 새 그림으로 바뀐다
  6. 독자가 노트를 열면 그림이 보인다

예외 흐름

  • 1a. 명령 팔레트에서 실행해도 같다
  • 5a. 노트가 이미 열려 있으면 다시 열지 않고 그림만 바뀐다
  • 6a. 독자에게 플러그인이 없어도 그림은 보인다(편집 메뉴만 없다)
요구사항
^obs-insert ^obs-insert-command ^obs-edit-embed ^obs-embed ^fmt-text
  • 흩어진 요구사항이 하나의 흐름으로 이어진다. 흐름이 그대로 인수 시험의 시나리오
  • 10개 쓰는 데 한 세션이면 된다. 요구사항이 바뀌어도 고칠 곳이 적다
  • "실패하면 무엇이 지켜지나"는 적지 않아 빈 곳이 덜 드러난다

기본 성공 시나리오

  1. 플러그인이 새 파일 이름을 정하고 볼트에 빈 다이어그램 파일을 만든다 파일 이름과 폴더는? (요구사항에 없음)
  2. 플러그인이 노트의 커서 자리에 ![[…]]를 넣는다
  3. 플러그인이 편집 탭을 연다
  4. 작성자가 블록을 편집한다 (UC-03 포함)
  5. 작성자가 저장한다 (UC-06 포함)
  6. 플러그인이 노트의 그림을 새 그림으로 바꾼다
  7. 독자가 노트를 열어 그림을 본다

확장

  • 1a. 같은 이름의 파일이 있다: 번호를 붙이나, 묻나? (요구사항에 없음)
  • 4a. 작성자가 아무것도 그리지 않고 탭을 닫는다: 빈 파일과 ![[…]]를 남기나, 지우나? (요구사항에 없음)
  • 6a. 노트가 이미 열려 있다: 다시 열지 않고 그림만 바꾼다
  • 7a. 독자에게 플러그인이 없다: 그림은 보이고 편집 메뉴만 없다

3사용자 스토리

"~로서 ~하고 싶다, 그래서 ~" + 인수 기준(Given / When / Then). 스토리 하나에 10줄 안팎

노트에 다이어그램 넣기

작성자로서, 노트를 쓰다가 그 자리에 NS 다이어그램을 넣고 싶다. 그래서 알고리즘 설명을 노트의 흐름 안에서 끝낼 수 있다.

인수 기준

Given 플러그인이 켜진 볼트의 노트에서 When 우클릭 메뉴의 "Insert new NS diagram"을 고르면 Then 커서 자리에 ![[…]]가 들어가고 편집 탭이 열린다
Given 노트가 열려 있고 그 그림을 편집 중일 때 When 저장하면 Then 노트를 다시 열지 않아도 새 그림이 보인다
Given 플러그인이 없는 볼트에서 When 그 노트를 열면 Then 그림이 보인다
  • 인수 기준이 곧 자동 시험(BDD)으로 옮기기 쉽다
  • 스토리는 일을 쪼개는 단위라, 흐름 전체(만들기 → 편집 → 저장 → 보기)가 여러 스토리로 흩어진다. 기능 목록인 지금 요구사항과 크게 다르지 않다
  • 팀이 백로그를 스프린트로 나눌 때 쓸모가 크다. 혼자 하는 지금은 얻을 것이 적다
