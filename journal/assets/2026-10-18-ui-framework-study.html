M22 · UI 프레임워크

편집기(packages/editor)의 화면 부품을 무엇으로 짤지 고르는 시안입니다(ADR-0010, 2026-10-07부터 "제안됨"). 2026-10-17의 결정(ADR-0030)으로 다이어그램은 렌더러가 그리므로, 프레임워크가 맡는 곳은 도구 모음 · 메뉴 · 설정 창 같은 둘레뿐입니다. 같은 도구 모음을 넷으로 실제로 짜서 빌드하고 크기를 쟀습니다(2026-10-18).

배경

프레임워크가 맡는 곳과 맡지 않는 곳

어느 것을 골라도 다이어그램, 고른 표시, 키 입력(Vim 키, 한글 입력), 블록 위의 글자 칸은 프레임워크 없이 TypeScript로 짭니다. 가장 까다로운 곳이 프레임워크 밖에 있어서, 프레임워크를 고르는 일의 무게가 2026-10-07보다 작아졌습니다.

U1

U1. 둘레의 화면 부품을 무엇으로 짤까

아래 넷은 모두 같은 도구 모음입니다: 실행 취소 · 다시 실행(할 것이 없으면 흐리게), 블록 글자의 종류 고르기, 설정 단추를 누르면 열리는 언어 고르기(영어 ↔ 한국어로 글자가 바뀜). 편집기 본체의 흉내(editor-stub.js)는 넷이 함께 씁니다. 크기는 그 도구 모음과 프레임워크를 함께 빌드해 줄인 것입니다.

프레임워크 없음 (TypeScript + DOM)

줄인 크기 1.9 KB · 웹으로 보낼 때(gzip) 0.9 KB
// 1번: 프레임워크 없음 (TypeScript + DOM). 바뀔 때마다 무엇을 고칠지 손으로 적는다.
import { T, KINDS, createEditor } from './editor-stub.js';
export function mountToolbar(root, ed) {
  root.innerHTML = `
    <button data-a="undo"></button><button data-a="redo"></button>
    <label><span data-t="kind"></span> <select>${KINDS.map((k) => `<option>${k}</option>`).join('')}</select></label>
    <button data-a="settings"></button>
    <div class="panel" hidden><span data-t="lang"></span>
      <label><input type="radio" name="lang" value="en">English</label>
      <label><input type="radio" name="lang" value="ko">한국어</label></div>`;
  const $ = (s) => root.querySelector(s);
  const undo = $('[data-a=undo]'), redo = $('[data-a=redo]'), settings = $('[data-a=settings]');
  const select = $('select'), panel = $('.panel');
  undo.onclick = () => ed.undo();
  redo.onclick = () => ed.redo();
  select.onchange = () => ed.setKind(select.value);
  settings.onclick = () => { panel.hidden = !panel.hidden; };
  root.querySelectorAll('input[name=lang]').forEach((r) => (r.onchange = () => ed.setLang(r.value)));
  return ed.subscribe((s) => {
    const t = T[s.lang];
    undo.textContent = t.undo; undo.disabled = !s.past.length;
    redo.textContent = t.redo; redo.disabled = !s.future.length;
    settings.textContent = t.settings;
    $('[data-t=kind]').textContent = t.kind; $('[data-t=lang]').textContent = t.lang;
    select.value = s.kind;
    root.querySelector(`input[value=${s.lang}]`).checked = true;
  });
}
mountToolbar(document.getElementById('app'), createEditor());
  • 무엇이 바뀌면 어느 글자를 고칠지 손으로 적습니다(맨 아래 subscribe 안). 화면 부품이 늘면 이 목록도 늘고, 하나를 빠뜨리면 그 자리만 옛 글자로 남습니다.
  • 더 실리는 것이 없습니다. 프로토타입(M01)이 이렇게 짜여 있습니다.
  • AI 대화창처럼 목록이 늘고 줄어드는 화면은 손이 많이 갑니다.

<!-- 2번: Svelte 5. HTML에 값을 적어 두면, 값이 바뀔 때 그 자리만 고쳐진다. -->
<script>
  import { T, KINDS } from './editor-stub.js';
  let { ed } = $props();
  let s = $state.raw(ed.get());
  $effect(() => ed.subscribe((v) => (s = v)));
  let open = $state(false);
  let t = $derived(T[s.lang]);
</script>

<button onclick={() => ed.undo()} disabled={!s.past.length}>{t.undo}</button>
<button onclick={() => ed.redo()} disabled={!s.future.length}>{t.redo}</button>
<label>{t.kind}
  <select value={s.kind} onchange={(e) => ed.setKind(e.target.value)}>
    {#each KINDS as k}<option>{k}</option>{/each}
  </select>
</label>
<button onclick={() => (open = !open)}>{t.settings}</button>
{#if open}
  <div class="panel">{t.lang}
    <label><input type="radio" checked={s.lang === 'en'} onchange={() => ed.setLang('en')}>English</label>
    <label><input type="radio" checked={s.lang === 'ko'} onchange={() => ed.setLang('ko')}>한국어</label>
  </div>
{/if}
  • HTML에 값을 적어 두면 값이 바뀔 때 그 자리만 고쳐집니다. 고칠 곳의 목록을 손으로 적지 않습니다.
  • 생김새가 HTML과 가까워 읽기 쉽습니다. Obsidian 공식 문서에 플러그인에서 쓰는 법이 있습니다.
  • 빌드할 때 컴파일하는 단계가 하나 더 있습니다. 2024년의 5판에서 쓰는 법이 크게 바뀌어, 인터넷의 옛 예제는 다르게 생겼습니다.

// 3번: React. 값이 바뀌면 함수 전체를 다시 부르고, 앞의 결과와 견주어 다른 곳만 고친다.
import { useState, useSyncExternalStore } from 'react';
import { createRoot } from 'react-dom/client';
import { T, KINDS, createEditor } from './editor-stub.js';
function Toolbar({ ed }) {
  const s = useSyncExternalStore(ed.subscribe, ed.get);
  const [open, setOpen] = useState(false);
  const t = T[s.lang];
  return (
    <>
      <button onClick={() => ed.undo()} disabled={!s.past.length}>{t.undo}</button>
      <button onClick={() => ed.redo()} disabled={!s.future.length}>{t.redo}</button>
      <label>{t.kind}{' '}
        <select value={s.kind} onChange={(e) => ed.setKind(e.target.value)}>
          {KINDS.map((k) => <option key={k}>{k}</option>)}
        </select>
      </label>
      <button onClick={() => setOpen(!open)}>{t.settings}</button>
      {open && (
        <div className="panel">{t.lang}
          <label><input type="radio" checked={s.lang === 'en'} onChange={() => ed.setLang('en')} />English</label>
          <label><input type="radio" checked={s.lang === 'ko'} onChange={() => ed.setLang('ko')} />한국어</label>
        </div>
      )}
    </>
  );
}
createRoot(document.getElementById('app')).render(<Toolbar ed={createEditor()} />);
  • 값이 바뀌면 함수 전체를 다시 부르고, 앞의 결과와 견주어 다른 곳만 고칩니다. 불변 문서(ADR-0029)와 잘 맞습니다.
  • 자료와 사례, 부품 라이브러리가 가장 많습니다. Obsidian 공식 문서에도 쓰는 법이 있습니다.
  • 넷 가운데 가장 큽니다. "다시 부른다"는 생각과 훅의 규칙(useState, useEffect를 부르는 순서)을 익혀야 읽힙니다.

// 4번: Preact. React와 같은 쓰는 법, 작은 몸집.
import { useState, useEffect } from 'preact/hooks';
import { render } from 'preact';
import { T, KINDS, createEditor } from './editor-stub.js';
function Toolbar({ ed }) {
  const [s, setS] = useState(ed.get()); useEffect(() => ed.subscribe(setS), []);
  const [open, setOpen] = useState(false);
  const t = T[s.lang];
  return (
    <>
      <button onClick={() => ed.undo()} disabled={!s.past.length}>{t.undo}</button>
      <button onClick={() => ed.redo()} disabled={!s.future.length}>{t.redo}</button>
      <label>{t.kind}{' '}
        <select value={s.kind} onChange={(e) => ed.setKind(e.target.value)}>
          {KINDS.map((k) => <option key={k}>{k}</option>)}
        </select>
      </label>
      <button onClick={() => setOpen(!open)}>{t.settings}</button>
      {open && (
        <div className="panel">{t.lang}
          <label><input type="radio" checked={s.lang === 'en'} onChange={() => ed.setLang('en')} />English</label>
          <label><input type="radio" checked={s.lang === 'ko'} onChange={() => ed.setLang('ko')} />한국어</label>
        </div>
      )}
    </>
  );
}
render(<Toolbar ed={createEditor()} />, document.getElementById('app'));
  • React와 쓰는 법이 같고 몸집은 Svelte보다 작습니다.
  • React의 부품 라이브러리는 대개 그대로 쓸 수 있지만, 가끔 맞지 않는 것이 있습니다.
  • 읽기 위해 익힐 것은 React와 같습니다.
