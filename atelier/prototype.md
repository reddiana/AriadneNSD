# 프로토타입

> [!abstract] 이 문서는
> 요구사항 리뷰용 **프로토타입이 지금 어떤 상태인지**를 모은 문서입니다. 어느 판까지 나왔는지, 리뷰를 어떤 순서로 하는지, 정해 놓고 아직 넣지 못한 것, 알려진 구멍, 시험해 본 곳과 못 한 곳이 있습니다. 시안 페이지를 어디까지 확인했는지도 여기에 둡니다.
> - 프로토타입은 요구사항이 맞는지 확인하려고 만들고 버리는 것입니다(→ [[spike-prototype-mvp]]). 프로토타입을 버릴 때 이 문서도 닫습니다.
> - 주소는 [[status#바로 가기]]에 있습니다. 저장소의 사본은 `journal/assets/2026-10-10-ns-prototype.html`, 시험은 `journal/assets/2026-10-11-ns-prototype-test.mjs`입니다.
> - 프로토타입을 만들며 Claude가 정해 놓고 확인받지 못한 것은 [[debt]]에 있습니다.
> - 2026-10-12에 `status`와 `debt`에 흩어져 있던 것을 모아 만들었습니다. 문장은 그대로 옮겼습니다.

## 만든 목적과 범위

- **요구사항 리뷰용 프로토타입을 만든다. 코드는 버린다.** 남은 기능 후보(Scratch 이벤트, 강조)가 요구사항에 들어간 직후, 아키텍처 설계 전에 만든다.
	- 넣음: 웹 페이지 하나. 블록 4종(처리, If, While, Do-While), 선택·감싸기·풀기·Undo, 자동 레이아웃, 기본 스타일(시안 C), `.ns.svg` 다운로드
	- 더 넣음 (2026-10-10): 접기(처음 접을 때 칸 안에서 이름 묻기), 강조 영역(굵은 테두리, 겹치면 넓히기, 맞닿으면 따로), 이벤트 머리 블록, 블록 글자 예제 두 가지(코드식·문장식. "블록 글자는 코드인가 문장인가"를 보고 정하려고)
	- 뺌: Obsidian, 데스크톱, Drive, 테마, 내보내기, 정확한 텍스트 폭
	- 방법: Claude가 Artifact(웹 페이지 하나)로 만든다. 만들기 1~2세션 + 써 보기 1주

## 알려진 구멍

- [ ] 40번째 판의 Vim 키에서 알려진 구멍 (보고: 2026-10-13): 갈래 이름 고치기는 키가 없다(더블클릭). 영역 고르기(`v`) 중에는 `j` `k`만 넓히고 `h` `l` · `gg` · `G`는 영역을 끝낸다. 다시 하기(`U`) 뒤에는 고른 것이 남지 않는다(`Ctrl`+`Y`도 같음). 화면이 고른 블록을 따라 움직이지 않는다(원래 있던 것). 안내 패널의 "앞서 바뀐 것"과 "만들며 생긴 질문"은 옛 키로 적혀 있다(그때의 기록이라고 그 위에 적어 둠). `Ctrl`+`Shift`+`F`(접기 영역 풀기)는 지우지 않아 아직 듣는다

- [ ] 프로토타입 36번째 판의 알려진 구멍 (보고: 2026-10-11): Event를 Method로 바꿀 때 이름 겹침을 다시 보지 않음(Event `sort(a)`와 Method `sort(b)`가 겹친 채 Method가 될 수 있음). 예전 파일을 읽을 때 Method 이름이 `sort`이면 `quicksort(a)` 안의 `sort`도 이름으로 봄. 끊긴 호출 블록은 인자가 비어 있으면 빈 괄호를 잃음(`reset()` → `? reset`)
- [ ] 프로토타입에서 보였지만 고치지 않은 것 (2026-10-11): 도움말의 `G` 설명에 "펴 보인 블록에서는 원래 블록으로"가 없음. "SVG 보기" 창의 안내 글이 펴짐을 말하지 않음. 이 브라우저에 남는 접힘 · 펴짐 목록이 문서와 따로 저장되어, 블록 id가 같은 다른 문서로 바뀌면 엉뚱한 곳이 접히거나 펴져 보일 수 있음(접힘에 원래 있던 문제)

## 시험한 곳과 못 한 곳

- [ ] 프로토타입 40번째 판은 헤드리스 Chrome 시험 110개를 통과함(기존 70개는 새 키로 고쳐 씀 + Vim 키 32개 + inbox의 넷 8개). 화면은 퀵소트를 편 모습 한 장만 봄: 오른쪽 키 표의 설명 칸이 좁아서 표의 폭을 고쳤고, **고친 뒤로는 다시 보지 않음**. 한글 입력 상태에서 `j`, `dd`, `zf`가 듣는 것은 메인테이너가 확인함(2026-10-13, 브라우저). 확인하지 못한 곳: 위·아래 이동의 새 규칙은 코드식 예제의 If 둘에서만 눌러 봄(Case, 접힌 갈래, 펴 보인 호출 블록 안의 If에서는 눌러 보지 않음), 한글을 적다가 누른 `Esc`가 한 번에 받아들이는지, 오른쪽 클릭 메뉴의 키 표시, `ac`(호출 넣기)와 `r`, `{` `}`, 상태 줄의 `-- 영역 --` 표시가 보이는 모습, claude.ai 안에서의 동작. 이 컴퓨터의 헤드리스 Chrome은 웹 글꼴(Google Fonts)을 기다리다 페이지 스크립트가 돌지 않아서, 글꼴 줄을 뺀 사본으로 시험했다 (보고: 2026-10-13)

- [ ] 프로토타입 37번째 판은 헤드리스 Chrome 시험 70개를 통과함(기존 36개 + 새 34개). 화면은 퀵소트에서 호출 블록 둘과 접기 영역 하나를 편 모습 한 장만 봄. 눌러 보지 못한 곳: 오른쪽 클릭 메뉴의 "펴 보기 / 접기", 실제 마우스 더블클릭, `Shift`+클릭으로 펴 보인 블록과 보통 블록을 함께 고르기, Case가 든 Method를 펴 보기, Raft 예제에서 펴 보기, 확대 · 축소한 상태, claude.ai 안에서의 "받기" (보고: 2026-10-11)
- [ ] 프로토타입 36번째 판은 헤드리스 Chrome 시험 36개를 통과함(`journal/assets/2026-10-11-ns-prototype-test.mjs`). 눌러 보지 못한 곳: 더블클릭으로 호출 블록 고치기, 오른쪽 클릭 메뉴의 "인자와 결과 고치기", 도구 모음의 호출 · Event · Method 단추, 한글 입력기로 호출 블록 고치기, `.ns.svg`로 저장했다 다시 열기, 고정폭 글꼴을 끈 상태의 굵은 이름 폭, claude.ai 안에서의 동작(로컬 파일로만 돌림). 화면은 퀵소트만 눈으로 봄 (보고: 2026-10-11)
