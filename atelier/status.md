## 지금 단계

**프로토타입으로 UX 규칙을 한 묶음씩 리뷰하는 중.** 2026-10-11 셋째 세션에서 요구사항과 UX 규칙을 검토해 공통 규칙 일곱 개와 물음 23개를 냈고([[02-ux-design]]), 메인테이너가 호출 블록 펴 보기에 대한 물음에 답한 뒤 "너무 많은 결정들이 있었습니다. 프로토타입을 통해 하나씩 리뷰합시다."라고 했습니다(→ [[2026-10-11-03-ux-review]]). 프로토타입 37번째 판(1판: 펴진 접기 영역의 왼쪽 막대, 호출 블록 펴 보기)이 게시되어 있고, 메인테이너가 써 볼 차례입니다. 검토 문서의 남은 물음은 판마다 다시 묻습니다. 요구사항 3.1 · 3.2를 다시 짜는 일과 단축키 다시 설계는 리뷰가 끝난 뒤에 합니다. 2026-10-11 둘째 세션에서 밀린 확인 서른 가지쯤을 하나씩 답했습니다(→ [[2026-10-11-02-confirmations]]): 호출 블록의 이름은 Method의 머리를 따르고 인자와 결과만 적으며([[0022-call-name-follows-head|ADR-0022]], 오전의 A1을 바꿈), 다이어그램은 Event를 왼쪽 · Method를 오른쪽에 놓고, 코드는 Apache-2.0 · 글은 CC BY 4.0으로 공개합니다([[0023-license|ADR-0023]], [[0024-license-scope|ADR-0024]]). 프로토타입(36번째 판)은 그 뒤에 정한 다섯 가지가 아직 들어 있지 않습니다. 같은 날 첫 세션에서는 Event와 Method를 구분하기로 했고(→ [[0021-event-and-method|ADR-0021]]), 프로토타입에 퀵소트와 Raft 예제를 넣었으며, 문자 로고를 어느 바탕에서나 읽히는 파일 하나로 바꿨습니다(→ [[2026-10-11-01-inbox-samples]]). 2026-10-10에 제품 이름을 `NSDrawing`에서 `AriadneNSD`로 바꿨습니다(→ [[0019-product-name|ADR-0019]], [[2026-10-10-05-product-name]]). 같은 날 GitHub 저장소와 로컬 폴더 이름도 `ariadne-nsd`로 바꿨고, 로고 시안(크노소스 벽화의 여인, 주홍 바탕)을 만들어 저장소 맨 위 `README.md`에 넣었습니다(→ [[2026-10-10-06-logo]]). 2026-10-11에 로고를 확정했습니다(→ [[0020-logo|ADR-0020]]). 2026-10-10에 요구사항 리뷰용 프로토타입을 만들었고(→ [[2026-10-10-02-prototype]]), 같은 날 메인테이너가 써 보면서 하나씩 확인해 요구사항을 많이 바꿨습니다(→ [[2026-10-10-04-prototype-feedback]]): 한 문서에 다이어그램 여러 개, 호출 블록, Case 블록, 접기 영역(강조 영역은 없앰), 저장되는 그림은 화면 그대로([[0018-save-as-shown|ADR-0018]]). 모델이 하루에 많이 달라져서, 아키텍처 설계를 시작할 조건 3번은 아직 맞지 않습니다. 요구사항과 아키텍처 결정(승인 ADR 0001~0008, 0011~0014, 0017~0024. 0015는 폐기, 0016은 0018로 대체)을 정리했습니다. 2026-10-09에 Google Drive 연동과 기본 시각 스타일을 더했고, 2026-10-10에 inbox를 모두 처리했습니다(접기, 강조 영역, 이벤트 머리, 공유 URL 등). Obsidian 스파이크로 `.ns.svg` 방식이 된다는 것도 확인했습니다.

앞으로의 큰 순서(메인테이너가 inbox 1-4~1-6에서 밝힌 방향): 요구사항을 최대한 더 모음 → 요구사항 리뷰용 프로토타입 → 아키텍처 설계 → **테스트 설계와 테스트 코드 작성** → 개발 → MVP(첫 출시, [[01-requirements#5. MVP 범위]]). 프로토타입과 아키텍처 시작 시점은 아래와 같이 정했습니다 (2026-10-10).

> [!note] 용어
> **프로토타입**은 요구사항이 맞는지 확인하려고 만들고 버리는 것, **MVP**는 개발을 거쳐 처음 내놓는 제품입니다. → [[spike-prototype-mvp]]

- **요구사항 리뷰용 프로토타입을 만든다. 코드는 버린다.** 남은 기능 후보(Scratch 이벤트, 강조)가 요구사항에 들어간 직후, 아키텍처 설계 전에 만든다.
	- 넣음: 웹 페이지 하나. 블록 4종(처리, If, While, Do-While), 선택·감싸기·풀기·Undo, 자동 레이아웃, 기본 스타일(시안 C), `.ns.svg` 다운로드
	- 더 넣음 (2026-10-10): 접기(처음 접을 때 칸 안에서 이름 묻기), 강조 영역(굵은 테두리, 겹치면 넓히기, 맞닿으면 따로), 이벤트 머리 블록, 블록 글자 예제 두 가지(코드식·문장식. "블록 글자는 코드인가 문장인가"를 보고 정하려고)
	- 뺌: Obsidian, 데스크톱, Drive, 테마, 내보내기, 정확한 텍스트 폭
	- 방법: Claude가 Artifact(웹 페이지 하나)로 만든다. 만들기 1~2세션 + 써 보기 1주
- **아키텍처 설계는 세 조건이 모두 맞으면 시작한다.**
	1. inbox의 기능 후보가 모두 요구사항에 들어가고 우선순위가 붙었다.
	2. 아키텍처를 가르는 열린 질문에 답이 났다: 블록 글자는 코드인가 문장인가, 저장 SVG의 색, 주 사용자, 확장자(스파이크로 `.ns.svg` 확인함).
	3. 프로토타입을 써 본 뒤 나온 새 요구사항이 모델(블록 종류, 트리 구조)과 파일 형식을 바꾸지 않는다.
