# ADR-0041: 그림의 고정 문구는 문서의 언어를 따른다

## 배경

그림 안에는 사용자가 적지 않은 글이 있습니다. If 갈래의 처음 이름 "참" · "거짓", 접힌 분기의 "⋯ 블록 n개", Case의 `default`, 이름 없는 호출 블록의 "(이름 없음)"입니다. 지금은 이 고정 문구를 **저장할 때의 화면 언어**로 그립니다([[ux-decisions#Q24. If 갈래의 이름|Q24]], [[01-file-format]]의 "같은 모델이면 같은 파일"의 예외).

그래서 같은 모델이라도 한국어 화면에서 저장한 파일과 영어 화면에서 저장한 파일은 그림 부분의 바이트가 다릅니다. 화면 언어가 다른 두 사람이 git으로 같은 파일을 고치면, 저장할 때마다 손대지 않은 If의 갈래 글자까지 diff에 나옵니다. 배포 대상에는 팀이 함께 쓰는 곳(IDE 플러그인, Confluence)이 있고, [[01-requirements#^r-fmt|R-FMT-03]]은 같은 모델이면 같은 파일을 요구합니다.

파일 형식은 웹 1.0 전이라 지금은 바꿀 수 있습니다 → [[dr-0018-release-stages|DR-0018]]

## 결정 기준

- 같은 모델이면 누가 어느 화면 언어로 저장해도 같은 바이트([[01-requirements#^r-fmt|R-FMT-03]])
- 읽는 사람에게 고정 문구가 바로 읽힐 것(기호가 아니라 말)
- 화면의 메뉴 · 알림은 각자의 화면 언어 그대로([[01-requirements#^r-nfr|R-NFR-04]])

## 검토한 대안

### 대안 A: 저장할 때의 화면 언어 (지금)

- 장점: 각자 늘 자기 언어로 봅니다. 파일에 필드가 늘지 않습니다.
- 단점: 화면 언어가 다르면 바이트가 달라집니다. R-FMT-03에 예외가 생깁니다.

### 대안 B: 문서에 그림의 언어를 둔다

- 장점: 바이트가 늘 같습니다. 화면과 저장 파일 · 인쇄 · PNG가 같은 글입니다.
- 단점: 영어 화면의 사람이 한국어로 만든 문서를 열면 갈래에 "참" · "거짓"이 보입니다. 파일 형식에 필드가 하나 늡니다.

### 대안 C: 언어에 매이지 않는 기호(✓ · ✗)

- 장점: 바이트가 늘 같고 설정도 없습니다.
- 단점: "참" · "거짓"처럼 바로 읽히지 않고, 도안 작품의 관례와 다릅니다.

## 결정

**대안 B.** 메인테이너가 2026-11-03에 골랐습니다(고르는 창의 세 안 가운데 추천안).

- 문서 설정에 그림의 언어 `locale`(`"en"` \| `"ko"`, 화면 언어의 목록과 같음)을 둡니다.
- 새 문서는 만든 사람의 화면 언어로 시작합니다. 문서 설정에서 바꿀 수 있습니다.
- 고정 문구는 화면에서도, 저장 파일 · PNG에서도 이 언어로 그립니다. 메뉴 · 알림 · 상태 표시줄은 각자의 화면 언어 그대로입니다.
- `locale`이 없는 파일(지금까지 저장한 파일)은 연 사람의 화면 언어로 열고, 다음에 저장할 때 그 값을 적습니다.
- 편집한 갈래 이름은 지금처럼 적은 그대로입니다. 비우면 문서의 언어로 된 처음 이름으로 돌아갑니다.

## 결과

- 좋아지는 점: [[01-file-format]]의 "같은 모델이면 같은 파일"에서 예외가 사라집니다. git diff에 손대지 않은 그림이 섞이지 않습니다.
- 감수하는 점: 다른 언어의 문서를 열면 그림의 고정 문구가 내 화면 언어와 다를 수 있습니다.
- 후속 작업: 모델 · 파일 형식([[01-file-format]] 3장의 `settings`)과 Q24의 문구, 문서 설정 화면, 렌더러가 화면 언어 대신 문서 설정을 읽게 하기, 골든 파일. → [[backlog]]
