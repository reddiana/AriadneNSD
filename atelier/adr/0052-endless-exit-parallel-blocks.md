# ADR-0052: 무한 반복 · 탈출 · 병렬 처리를 블록 종류로 더한다

## 배경

블록 종류는 처리 · If · Case · While · Do-While · For · 호출이었다([[01-model#1.4 블록]]의 그때 모습). 메인테이너가 "block 유형 중 Parallel이 없습니다. 우리가 놓친게 또 뭐 있지요?"라고 물어, DIN 66261과 Structorizer에 견주어 빠진 것을 찾았다. 요구사항에 있던 탈출([[01-requirements#^r-blk|R-BLK-12]])과 병렬 처리([[01-requirements#^r-blk|R-BLK-13]])에 무한 반복([[01-requirements#^r-blk|R-BLK-15]])을 더해 셋 모두 `P1`이 되었다(과정은 [[2026-11-28-02-blocks-wording-german]]).

모양과 조작은 시안에서 메인테이너가 정했다: 무한 반복 M79([[ux-decisions#EL1. 무한 반복 블록|EL1]]), 탈출 M80([[ux-decisions#XB1. 탈출 블록|XB1]]), 병렬 처리 M81([[ux-decisions#PB1. 병렬 처리 블록|PB1]]), 구현 전의 물음 M84([[ux-decisions#BI1. 블록 셋 구현의 세부|BI1]]). 남은 것은 모델 · 파일 형식에 어떻게 담는가다.

- 무한 반복은 텍스트가 없고 본문만 있다.
- 탈출은 텍스트 하나다. 어디에 놓였는지는 검사하지 않는다.
- 병렬 처리는 위 띠의 텍스트(비울 수 있음)와 분기 여럿이다. 분기에는 라벨이 없다. 편집할 때는 분기가 둘 이상이다.

## 결정 기준

- 예전 파일이 그대로 열리고, 열고 바로 저장하면 같은 바이트다([[03-quality-attribute-scenarios#QA-04 저장 왕복 무손실|QA-04]]).
- 블록 종류를 더할 때 바뀌는 곳이 `core`와 키 표에 머문다([[03-quality-attribute-scenarios#QA-12 블록 종류 추가|QA-12]]).
- 텍스트 편집 · 접기 · 복사 · 이동 같은 명령이 종류마다 새 경로를 만들지 않게, 이미 있는 짜임(`text`, `body: Seq`, `Branch`)을 다시 쓴다.
- 코드에서 가져온 그림(Claude skill, 리버스 엔지니어링)이 편집 명령의 사전 조건보다 넓은 모양도 담을 수 있다(Case에서 default가 없는 것과 같은 원칙 → [[01-model#1.4 블록]]).

## 검토한 대안

### 대안 A: 새 `kind` 셋 (선택)

`endless`(본문만) · `exit`(텍스트 하나) · `parallel`(텍스트와 분기 배열)을 판별 유니온에 더한다.

- 장점: 종류마다 필드가 딱 맞다. 파서 · 스키마가 모르는 필드를 거부하는 규칙 그대로다.
- 단점: 레이아웃 · 렌더링 · 명령의 `switch`마다 갈래가 셋씩 는다.

### 대안 B: 있는 종류에 표시를 단다

무한 반복은 텍스트 없는 While(`text: ""` + 표시), 탈출은 처리 블록 + `exit: true`, 병렬 처리는 Case + `parallel: true`.

- 장점: 종류의 수가 그대로다.
- 단점: 모양이 다른 것을 같은 종류로 두면 그리기 · 감싸기 · 분기 조작이 표시마다 갈라진다. Case의 분기 라벨 · default처럼 병렬 처리에 없는 필드를 비워 두어야 하고, 불변식이 복잡해진다.

## 결정

**대안 A.** 시안 M84의 D1(`kind` 이름 `endless` · `exit` · `parallel`)을 메인테이너가 그대로 받아들였다.

- **무한 반복** `{ id, kind: 'endless', body: Seq }`. `text`가 없다. 반복 블록처럼 본문이 접히고(`view.folded`에 블록 id), 본문 줄의 접기 영역은 `folds`에 둔다.
- **탈출** `{ id, kind: 'exit', text }`. 처리 블록과 필드가 같다. 위치는 불변식으로 검사하지 않는다(반복 밖에도 놓일 수 있다). 안에 블록이 없어 감싸기의 종류(`WrapKind`)에 들지 않는다.
- **병렬 처리** `{ id, kind: 'parallel', text, branches: Branch[] }`. `text`는 위 띠의 텍스트이고 언제나 기록한다(비면 `""`). 분기는 If의 분기 · default 분기와 같은 `Branch`를 다시 쓰되 `label`을 두지 않는다. 파일의 분기 객체는 `id` · `body` · `folds`만 받고 `label`이 있으면 깨진 파일이다. 분기가 접히는 것도 If · Case의 분기와 같다(`view.folded`에 분기 id).
- **모델은 편집 명령보다 넓다.** 불변식 4는 병렬 처리에 분기가 **하나 이상**이기만 요구한다. 편집 명령은 둘 이상을 지킨다: 새로 넣으면 빈 분기 둘, 감싸면 고른 블록이 첫 분기이고 둘째는 빈 분기, 분기가 둘뿐이면 분기 삭제를 거절한다(`lastParallelBranches`).
- **형식 버전은 그대로 1이다.** 예전 파일에는 새 종류가 없어 그대로 열린다. 블록의 필드 순서는 `id` · `kind` 다음 위와 같다([[01-file-format#3.3 노드별 필드]]). JSON Schema(`model.schema.json`)와 그 생성 문서([[02-model-schema]])에 세 종류를 더했다.
- 그림 문구 `endless.name`("(무한 반복)" · "(endless loop)" · "(Endlosschleife)")을 `core`의 카탈로그에 더했다. 무한 반복에는 텍스트가 없어서, 접기 영역의 기본 이름과 텍스트로 복사할 때 그 자리에 쓴다.

## 결과

- 좋아지는 점: DIN 66261의 블록을 모두 그린다. 코드의 `while (true)` · `break` · `continue` · 중간 `return` · `Promise.all`을 처리 블록에 글로 적지 않고 모양으로 옮긴다(갤러리 · 예제 14곳을 고침).
- 감수하는 점: 새 블록이 든 파일을 이 결정 전의 앱에서 열면 모르는 `kind`라 깨진 파일로 거부한다. 웹 1.0 전(베타)이라 버전을 올리지 않았다 → [[dr-0018-release-stages|DR-0018]]
- 감수하는 점: 분기가 하나인 병렬 처리(손으로 고친 파일, 코드에서 가져온 것)도 그대로 그린다. 편집으로 그 분기를 지울 수는 없다.
- 후속 작업: 블록마다의 주석을 어떻게 둘지는 따로 정한다([[02-interaction-rules#블록마다의 주석]]).
