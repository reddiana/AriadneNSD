## 배경

NS 차트 편집기를 Obsidian 안에서도, 단독 데스크톱 앱으로도, 설치 없이 웹에서도 쓰고 싶다. ([[01-requirements#2. 배포 대상]])

## 결정 기준

- 세 대상에서 편집 동작과 결과 파일이 같아야 한다. ([[01-requirements#^nfr-compat]])
- 같은 기능을 세 번 구현하지 않아야 한다.
- 대상별로 다른 부분(파일 입출력, 창, 테마 연동)만 따로 구현해야 한다.

## 검토한 대안

### 대상별로 따로 구현

- 장점: 대상마다 가장 알맞은 기술 사용 가능
- 단점: 기능을 세 번 구현, 동작 차이로 파일 호환성이 깨지기 쉬움

### 공유 코어 + 대상별 셸 (모노레포)

- 장점: 핵심 로직과 편집 UI를 한 번만 구현, 호환성이 구조적으로 보장됨
- 단점: 세 대상 모두에서 돌아가는 기술로 제한됨, 모노레포 빌드 설정 필요

## 결정

세 대상 모두 배포하며, 하나의 저장소에서 공유 패키지와 대상별 셸로 나눈다.

```
packages/core     모델 · 편집 명령 · 레이아웃 · 렌더러 · 파일 형식 (DOM 의존 없음)
packages/editor   편집 UI
apps/obsidian     Obsidian 플러그인 셸
apps/desktop      데스크톱 셸
apps/web          웹 셸
```

대상마다 다른 기능(파일 입출력, 텍스트 폭 측정)은 인터페이스로 정의하고 셸이 구현을 주입한다.

## 결과

- 좋아지는 점: 기능 추가가 세 대상에 동시에 반영된다. `core`를 화면 없이 테스트할 수 있다.
- 감수하는 점: 세 환경 모두에서 돌아가는 웹 기술로 제한된다. → [[0003-typescript|ADR-0003]]
- 후속 작업: 모노레포 도구(pnpm workspaces 등) 선택, 개발 순서 결정 → [[0011-development-order|ADR-0011]]
