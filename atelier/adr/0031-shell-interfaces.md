# ADR-0031: 셸은 문서 파일(다른 문서 읽기 포함)과 설정 보관, 두 인터페이스를 구현한다

> [!NOTE] 이후 변경
> - 2026-10-18: 반대 방향이 더해졌다. 편집기가 셸에게 명령의 목록과 설정의 목록을 내놓고, 셸은 그것을 자기 메뉴나 그 프로그램(Obsidian, IDE)의 메뉴 · 설정 화면에 올린다 → [[0033-command-list-for-shells|ADR-0033]]

## 배경

같은 편집기(`editor` + `core`)를 배포 대상마다의 셸이 감싼다([[0002-three-targets-shared-core|ADR-0002]]). 셸은 웹 · Obsidian · 데스크톱에서 그치지 않는다. 웹 위에 얹는 Google Drive, 나중의 Confluence, IDE 플러그인(VSCode, 그다음 IntelliJ)도 셸이다([[03-architecture#6. 배포 구성]]). 그래서 "셸이 무엇을 구현하면 붙는가"를 인터페이스로 적어 두어야 한다.

[[03-architecture]]의 초안(2026-10-13)에 Claude는 "셸의 인터페이스는 파일 입출력 하나(이 문서를 읽기 · 쓰기 · 다른 이름으로 쓰기)"라고 적었다. 글자 폭 측정과 편집기 상태 저장소가 그날의 결정으로 필요 없어져서다. 시안 M20을 만들며(2026-10-17) 둘이 빠진 것을 찾았다.

- 다른 문서의 Method 부르기([[01-requirements#^blk-call-external]])는 지금 연 문서가 아닌 다른 파일을 읽어야 한다.
- 사용자의 설정(화면의 언어, 화면 색)은 문서 파일 밖 어딘가에 보관해야 한다.

## 결정 기준

- 새 셸을 붙이는 사람이 무엇을 짜야 하는지 인터페이스만 보고 안다
- 같은 일을 셸마다 인터페이스 밖에서 제각각 짜지 않는다
- 문서의 상태는 파일 안에만 둔다(편집기 상태 저장소는 두지 않는다)

## 검토한 대안

그림은 시안 M20의 A6에 있다: https://claude.ai/artifact/R8RJxg8V1qweiMfusMKk87

### 대안 A: 두 인터페이스. 문서 파일(+ 다른 문서 읽기)과 설정 보관

- 장점: 셸이 구현할 것이 인터페이스 둘로 다 드러난다
- 단점: 인터페이스가 조금 커진다. 다른 문서를 읽지 못하는 셸(웹)의 경우를 `editor`가 다뤄야 한다

### 대안 B: 처음 제안대로 파일 입출력 하나

- 장점: 인터페이스가 가장 작다
- 단점: 다른 문서 읽기와 설정 보관을 셸마다 인터페이스 밖에서 따로 짠다. 새 셸을 붙일 때 그것을 짜야 한다는 것이 드러나지 않는다

## 결정

**대안 A.** 메인테이너: "추천 수용." (2026-10-18)

`editor`가 두 인터페이스를 정의하고, 셸이 구현을 넣는다.

1. **문서 파일**: 이 문서를 읽는다 · 쓴다 · 다른 이름으로 쓴다, **다른 문서를 읽는다**(경로로). 읽지 못하면 "없음"을 돌려준다.
2. **설정 보관**: 사용자의 설정(화면의 언어, 화면 색)을 읽고 쓴다.

셸마다의 구현은 다음과 같다(뒤에 붙는 셸은 그 셸을 설계할 때 정한다).

| 셸 | 다른 문서 읽기 | 설정 보관 |
| --- | --- | --- |
| 웹 | 사용자가 고른 파일이나 폴더 안에서만 | 그 브라우저 |
| Obsidian | 볼트에서 | 플러그인 설정 |
| 데스크톱 | 디스크에서 | 설정 파일 |

다른 문서를 읽지 못하면 그 호출 블록은 "이어진 곳 없음"으로 보인다. 웹에서는 사용자가 그 파일을 고르지 않았으면 늘 그렇다.

## 결과

- 좋아지는 점: 새 셸(Confluence, IDE 플러그인)을 붙일 때 짤 것이 두 인터페이스로 정해진다.
- 감수하는 점: 웹에서는 다른 문서를 부르는 호출 블록이 끊겨 보이기 쉽다.
- 남은 것: IDE 플러그인은 원본이 `.ns` 파일이 아니라 소스 코드라서, 이 둘만으로는 모자랄 수 있다(코드와 모델을 오가는 자리) → [[03-architecture#6. 배포 구성]]
- 후속 작업: 인터페이스의 메서드 모양 → [[03-editor#5. 셸과의 연결]], 웹에서 다른 문서를 어떻게 고르게 할지 → [[06-web]]
