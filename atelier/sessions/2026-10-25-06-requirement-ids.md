# 2026-10-25 요구사항 ID를 R- 체계로: 표, 우선순위 칸, 링크의 글자, 요구사항 변경 기록

(← [[2026-10-25-05-site-journal-explorer]]) 같은 날 여섯 번째 세션이다(마무리는 자정을 넘겨 2026-10-26). 메인테이너: "inbox 체크해주세요."

## inbox

새 항목 하나를 함께 검토했다. 원문:

> # 1. 일하는 방식
> - 요구사항에 대한 링크를 `^web-file` 처럼 만드니, 정작 [[01-requirements]]에서 찾아보기 힘듭니다. 특히 publish 됐을 때 그렇습니다. ID로 관리하는 것은 어떨까요?

처리 방향에 합의했고, 마무리 때 "원문을 세션 기록으로 옮기고 지움"을 골랐다.

## 논의 흐름

1. **원인.** 블록 ID(`^web-file`)는 Obsidian 읽기 화면과 펴낸 사이트 모두에서 숨겨진다. 링크에서 본 글자를 요구사항 문서에서 찾을 수 없었다.
2. **첫 물음은 되물음으로.** Claude가 고르는 창으로 방법 셋(지금 ID를 줄 앞에 보이게(추천) / 번호 ID / 사이트에서만)을 물었으나, 메인테이너는 창을 닫았다. 이어 "번호ID로 만들고 표로 만들어주세요. 우선순위는 오른쪽 컬럼으로 빼구요."
3. **두 번째 물음도 되물음으로.** Claude가 "Obsidian은 표의 한 줄을 가리키지 못한다"와 "승인 ADR의 옛 링크"를 물었고, 메인테이너는 창을 닫고 답했다: "앵커도 id로 해주세요. 독자는 링크를 거는 문서에서 링크의 문자열을 요구사항 문서에서 찾을 것입니다. 요구사항에서 못 찾으니 당혹스러웠어요."
4. **첫 판.** 요구사항 101개에 `WEB-02` 같은 ID를 매기고 절마다 표로. 링크는 `[[01-requirements#WEB-02]]`, 사이트는 빌드가 표의 줄마다 앵커를 단다. 옛 링크 약 480곳을 스크립트로 바꿈(승인 ADR · DR과 세션 기록 포함, 링크의 주소만 고치는 것은 본문 고침이 아니라는 예외를 CLAUDE.md에).
5. **메인테이너가 Obsidian에서 보고 넷을 더 요청.** 원문:
	> - [[03-architecture]]에 [01-requirements > FMT-03](app://obsidian.md/01-requirements#FMT-03) 링크가 있지만 연결되지 않습니다.
	> - 요구사항 ID는 `R-`로 시작해주세요.
	> - [[01-requirements]]에 요구사항은 모두 ID 채번해주세요.
	> - 채번된 요구사항ID는 불변이고 철회된 것은 요구사항 변경 기록으로 별도 문서로 남기고 [[01-requirements]]에서는 삭제해주세요.
6. **고르는 창 둘.** Obsidian에서 링크가 듣게 하는 법: "표를 가리키고 글자는 ID (추천)". 변경 기록의 자리: "atelier/" (Claude의 추천은 `docs/`였다).
7. **둘째 판.** `R-` ID, ID가 없던 요구사항 27개에도 매김(128개), 표마다 블록 ID(`^r-web`), 링크는 `[[01-requirements#^r-web|R-WEB-02]]`. 사이트는 빌드가 그 줄의 앵커(`#r-web-02`)로 돌린다. [[requirement-changes|요구사항 변경 기록]]을 만들고 ID 전에 없앤 둘(`edit-region`, `exp-png-folded`)을 옮김.
8. **메인테이너: "03-quality-attribute-scenarios에는 요구사항으로의 링크가 없습니다. 요구사항 ID만 있습니다."** 코드 표기로만 적은 ID를 13개 문서에서 링크로 바꿈. 이때 첫 스크립트가 inbox의 원문(`^web-file`)까지 바꿔 놓았던 것을 찾아 되돌림.

## 결정

- [[dr-0016-requirement-ids|DR-0016]]: 요구사항은 모두 `R-` ID를 받아 표에 두고, 링크는 표로 가며 글자는 ID, ID는 불변, 철회한 것은 변경 기록으로. 같은 세션에서 다듬어 push 전에 고쳐 썼다(새 DR을 따로 만들지 않음).
- CLAUDE.md의 규칙: ID와 표, 링크의 모양, 글에 ID를 적을 때는 언제나 링크로, ID는 불변, 철회는 변경 기록으로, 링크의 주소만 고치는 것은 승인 ADR의 본문 고침이 아님. 저장소 구성 표에 `requirement-changes.md`.

## 발견한 위험과 실수

- **Obsidian은 표의 한 줄을 가리키지 못한다.** 블록 ID는 표 전체에만 붙는다. 없는 제목을 가리키는 `[[문서#ID]]`는 Obsidian에서 듣지 않는다. 첫 판에서 Claude는 "첫머리가 열린다"고 짐작했으나 메인테이너가 확인해 보니 링크가 듣지 않았다. Obsidian에서 직접 볼 수 없는 동작은 짐작으로 말하지 않는다.
- **Windows의 Python은 파일을 CRLF로 쓴다.** `write_text`에 `newline="\n"`을 주어야 한다. 한 번 CRLF로 썼다가 LF로 되돌림.
- **Bash 도구를 거치면 heredoc 안의 `\\`가 `\` 하나로 줄 수 있다.** 정규식이 든 스크립트는 Write 도구로 파일에 쓴다.
- **일괄 바꾸기가 메인테이너의 원문까지 바꿨다.** inbox의 원문을 바꿔 놓았다가 되돌림. 일괄 바꾸기는 inbox와 인용한 원문을 빼고 돌린다.

## 마무리 뒤 (2026-10-26)

메인테이너가 사이트와 문서를 보고 셋을 더 짚었다.

1. **"01-requirements#r-edit-05 01-requirements#r-edit-06의 (아래 ..)에 있는 링크가 github page에서는 없어졌어요."** Quartz v4.5.2는 표 안에서 같은 문서의 제목으로 가는 위키링크(`[[#감싸기 · 풀기]]`)를 글자 없이, 앵커를 바꾸지 않은 채로 만든다. 목록을 표로 바꾸면서 생겼다. 배포 대상 표의 `2.1` … 링크도 주소가 틀렸었다. 빌드(`site/prepare-content.mjs`)가 이런 링크를 마크다운 링크로 바꾸고 앵커를 Quartz가 제목에 다는 모양으로 만들게 함. 메인테이너가 Obsidian에서 표의 칸 너비를 맞춰 ID 칸 뒤에 빈칸이 여럿 생겨, 줄 앵커의 정규식도 고침.
2. **"여러 블록 선택 규칙, 감싸기 · 풀기 등은 요구사항인데 ID가 없습니다."** 3.2의 하위 절 셋은 이미 ID가 있는 요구사항을 풀어 쓰고 설계로 이어 주는 글이었다. 절을 없애고 내용을 [[01-requirements#^r-edit|R-EDIT-05]] · [[01-requirements#^r-edit|R-EDIT-06]] · [[01-requirements#^r-edit|R-EDIT-13]] · [[01-requirements#^r-edit|R-EDIT-14]] 줄로 옮김(새 ID 없음). 그 절로 가던 링크 8개 문서를 ID로 돌림. 표 밖에 남은 글을 모두 훑어 요구사항 문장이 더 없음을 확인함(문제 알리기 절의 첫 문장만 확인을 부탁함 → [[outbox]]). 스크립트 `site/tools/req-subsections-to-rows.py`.
3. **"3.1 블록 종류에서 DIN 66261 / 원 논문 링크로 논문을 연결해주세요."** 원 논문(Nassi · Shneiderman, SIGPLAN Notices 8(8), 1973)은 Shneiderman의 NSD 페이지에 있는 PDF와 ACM DOI로, DIN 66261은 DIN Media의 판매 페이지로 링크. 참고 자료에도 더함. PDF는 스캔본이라 내용을 읽어 확인하지 못했다(쪽수는 논문과 맞음).

**규칙을 어김:** 1번 고침을 마무리가 아닌데 바로 push했다. 2 · 3번은 커밋만 하고 물었고, 메인테이너의 "push"로 올렸다.
