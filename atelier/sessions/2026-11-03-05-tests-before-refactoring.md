## 리팩토링을 하기에 테스트가 충분한가

메인테이너: "MVP 후반부에 리팩토링을 할 것입니다. 테스트가 부족하다면 리팩토링하는 것은 매우 위험하지요. 우리의 테스트코드는 리팩토링을 하기에 충분한가요?"

- 단위 커버리지를 재어 답함: `core` 94% · `fonts` 97%는 충분(속성 기반 테스트와 골든 파일도 있음), `editor` 79%는 구멍이 있음(캔버스 · 끌어 놓기 · 클립보드), `apps/web` 45%는 부족
- 추천한 차례: 1 E2E 커버리지도 재어 합친 빈 곳을 찾음 → 2 빈 곳에 지금 동작을 적는 테스트(characterization test)를 더함 → 3 패키지마다 커버리지 하한을 CI에 걸기. 고르는 창에서 이 차례로 진행함
- 1단계: `pnpm coverage`. 단위는 Vitest V8 커버리지, E2E는 `E2E_COVERAGE`를 켜면 fixture가 Chromium JS 커버리지를 모아 소스맵 빌드(포트 4175)로 원래 소스에 대어 봄(monocart-coverage-reports). 둘을 줄마다 합침. 합친 값 `core` 94.6% · `editor` 84.3% · `fonts` 96.8% · `web` 65.0%. 커밋 `5487fb3`
- 2단계(메인테이너: "진행하세요"): 겹치지 않는 세 영역을 에이전트 셋에 맡김(캔버스 · 끌어 놓기 · 클립보드 / 웹 셸 / 편집 명령 · 세션). 규칙: 제품 코드는 고치지 않음, 버그로 보이면 고치지 않고 보고만, 내부 함수가 아니라 겉으로 보이는 동작을 확인. 웹 셸 에이전트는 앞 프로세스가 끝나며 끊겼으나 남긴 테스트가 통과함. 번역 271개는 번역 에이전트가 채움
- 결과: 테스트 255개(ID T-0542 ~ T-0796), 합친 커버리지 `editor` 95.5% · `web` 89.8% · `core` 94.4% · `fonts` 96.8% → [[07-testing#6. 지금의 커버리지]]. 커버리지를 켜면 속성 기반 테스트가 5초를 넘어 `coverage.mjs`의 시간 한도를 60초로
- 다음 세션이 `pnpm check`(단위 · 통합 1,157번 실행, 테스트 목록 최신)를 돌려 통과를 확인하고 커밋 `7e81be0`

## 테스트를 더하다 찾은 버그 후보

에이전트들이 고치지 않고 지금 동작대로 테스트에 적은 것. 고칠지 메인테이너가 정한다 → [[outbox#정해 주세요]]

1. 빈 default 칸에서 복사 · 잘라내기를 하면 "삭제할 default 분기가 없습니다"라고 알림(`editor-commands.ts`의 공통 검사 `blocksOnly`). UX CD1은 삭제만 아무 일도 하지 않는다고 함
2. 같은 거절에 다른 까닭: 헤더에서 붙여넣기 · 감싸기는 "먼저 블록을 선택하세요", 복사 · 잘라내기는 "헤더에서는 안 됨". 분기 라벨에서 풀기는 "먼저 블록을 선택하세요"
3. 분기 라벨이나 빈 default 칸에서 `Ctrl`+`←` / `Ctrl`+`→`가 분기가 아니라 If · Case 블록에서 출발(`navigate.ts`). If의 오른쪽(거짓) 라벨에서 `Ctrl`+`→`가 왼쪽(참) 분기의 첫 블록으로 감. [[03-editor]] 2.2는 "가장 가까운 If · Case의 옆 분기"
4. 호출 블록을 텍스트로 복사하면 Method 이름이 빠짐(`ys xs`처럼 결과 · 인자만, 인자 · 결과가 없으면 빈 줄). [[03-editor]] 3.3은 의사 코드처럼 읽히는 줄
5. 상태 표시줄의 질문에서 고르는 키가 아닌 키는 질문을 닫고 제 일도 함(`j`면 선택이 움직임). 뜻한 것일 수 있음
6. 끌어 놓기로 제자리에 놓으면 "문서가 바뀜"(`true`)을 돌려주지만 바뀐 것도 실행 취소 단계도 없음. 화면에는 영향 없음. 함수 주석이 틀림
7. 인라인 편집 중에 밖에서 캔버스에 포커스를 주면 글자가 확정됨. 뜻한 것으로 보이나, 셸 코드가 캔버스에 포커스를 주면 편집이 확정된다는 뜻

## 작업 목록의 Needs input

이 세션이 일하는 동안 작업 목록에 "Needs input … 테스트를 더하다 찾은 것 가운데 버그로 보고 고칠 것을 골라 주세요"가 떴다. 실제로는 아직 묻지 않은 물음(에이전트가 끝나면 물을 예정)을 목록의 요약이 이미 물은 것처럼 적은 것이다. 메인테이너가 다른 세션에서 "답변을 기다린다고 하지만 질문이 보이지 않습니다", "화면에 달님의 출력이 제대로 안 보입니다"라고 했고, 그 세션들은 이 세션의 대화를 볼 수 없어 질문을 찾지 못했다. 이 세션은 그 사이 끊겼다.

- 다음부터: 질문은 outbox에 적고 커밋해 두면, 세션이 끊겨도 다음 세션이 그대로 보인다. 긴 일 중에 물을 것이 생기면 먼저 outbox에 적는다
