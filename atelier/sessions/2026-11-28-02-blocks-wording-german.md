# 2026-11-28 빠진 블록, 앞 · 뒤의 이름, 독일어

## 흐름

1. **빠진 블록.** "block 유형 중 Parallel이 없습니다. 우리가 놓친게 또 뭐 있지요?" → Parallel은 요구사항(R-BLK-13, `P2`)에 있었고 만들지 않았을 뿐. DIN 66261(de.wikipedia의 기호 목록)과 Structorizer에 견주어 요구사항에도 없는 것으로 무한 반복(Endlosschleife)과 예외 처리(Try, 표준 밖)를 찾음
2. **무한 반복.** "무한 반복은 R-BLK-15로 더하고, 모양 시안을 보여 주세요" → DIN 그림(Wikimedia, public domain)을 확인해 M79. "E1 채택" → DIN 그대로(위 · 왼쪽 · 아래 빈 띠)
3. **P2 블록의 때.** "p2에 있는 블록들은 언제 하나요?" → 계획은 1.0 뒤. 고르는 창에서 메인테이너가 "넷 모두 P1로"(탈출 · 병렬 · 주석 · 무한 반복)
4. **시안 셋.** "탈출 시안부터 만들어 주세요. 나머지 시안도 연달아" → 한 생성 스크립트로 M80 탈출 · M81 병렬 처리 · M82 주석. M80은 "모두 추천 수용", M81은 "P1: 1, P2: 2, P3: 1"
5. **주석 철회.** "R-BLK-14 근거를 알려주세요" → 첫날 초안에 Claude가 설명 없이 넣은 줄, DIN에도 없음. "R-BLK-14 요구사항을 철회합니다. 다만 각 블록들에서 주석을 어떻게 처리할 지 결정을 백로그에 넣어주세요." → 철회 기록, backlog, M82는 답하기 전에 닫음
6. **앞 · 뒤의 이름.** inbox의 세 물음 → 코드에서 까닭 셋(표시가 한쪽에만, 메뉴는 표준 키 `Ctrl`+`V`만 보여 `p`와 이름이 달라 보임, 앞 · 뒤는 화면의 방향이 아님)을 찾아 M83. "W1 1번" → 위 · 아래, 왼쪽 · 오른쪽(에이전트 `d3cfe48`). 로컬 앱에서 보고 "위에/아래에 쌍은 메뉴에서 이름대로" → `13c3c75`
7. **독일어.** "inbox의 독일어 항목도 검토합시다" → 범위는 앱 + 그림 글자 + 사용법 · 갤러리, 때는 "지금 바로(베타 중)". de.wikipedia의 DIN 그림을 보고 If 갈래를 "ja · nein"으로. 그사이 inbox에 결함("환경설정의 언어와 실제 앱에 적용된 언어가 맞지 않는 경우가 많습니다.")과 물음("다국어 지원함에 따라 구조를 합리적으로 변경할 여지가 생겼나요?")이 더해짐 → 언어를 정하는 곳이 웹 셸과 편집기 둘이라는 것을 찾아 하나로 모으기를 추천, 결함의 재현 조건을 물음(답은 아직)
8. **매듭 제안.** "앞으로 적절한 시점에 매듭이나 clear를 제안해주세요." → 메모리에 적고 바로 매듭을 제안. "매듭"
