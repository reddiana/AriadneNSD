# 2026-11-28 갤러리 그림의 선 굵기

허브가 연 분신(서브 세션), worktree 브랜치 `claude/gallery-line-width-c35c3b`. 지적: "알고리즘 갤러리의 캡처에서 선들의 굵기가 제각각입니다."

## 흐름

1. **원인.** 갤러리 그림(`.ns.svg`)의 선은 모두 1px로 고르다(100%에서 모두 화면 픽셀 1칸). 화면 배율 125 · 150 · 175%에서는 `crispEdges` 사각형이 놓인 자리에 따라 1칸 · 2칸으로 반올림되고, 호출 블록의 막대 같은 경로 선은 번진 2칸이 된다. 편집기는 `crisp-lines.ts`로 화면에서 맞추지만 갤러리는 파일을 `<img>`로 보여 줘 맞추지 못함. 원본 그림이 아니라 보여 주는 쪽의 문제
2. **시안 M88.** 첫 판은 선택지 ① 갤러리에서 맞춤 · ② 파일 안에 배율별 CSS. "추천 안들이 이해가 안가요. 설명이 더 필요합니다." → 말의 뜻(화면 배율 · 화면 픽셀 · 번짐), 150% 캡처를 키워 A ~ D 네 선에 번호 딱지와 픽셀 단면을 단 판으로 다시 만듦. 다시 재 보니 ②의 CSS는 Chrome에서도 `<img>` 안에서 듣지 않아(앞 판의 "같은 모습"은 잘못 잼) 선택지에서 뺌
3. **결정.** "① 그렇게 고침" → 갤러리가 SVG를 받아 페이지 안에 넣고 편집기와 같은 규칙(`pages/crisp-lines.js`)으로 곧은 선을 화면 픽셀 정수 굵기로 맞춤. 배율이 바뀌면 다시 맞춤, 못 읽으면 `<img>`(`4da0ea0`). T-1630 ~ T-1632. 100 ~ 175%에서 같은 굵기, 23개 그림 모두 뜸을 브라우저로 확인
4. **테스트 목록.** lazy-locales의 테스트 ID가 next를 넘어 `test-list:check`가 실패 → next 1633(`7eb72d0`). 본체의 요청으로 main(`b83eaa4`)을 merge, 생성 문서는 생성기로 다시 만듦(`2073ddc`)
5. **깨진 그림 표시.** "선이 고르게 보이긴 하는데, 그림링크 깨짐 표시가 모든 갤러리에 있습니다." → `.pic img { display: block }`이 `hidden`을 이겨 숨긴 대체 `<img>`가 보였음. `.pic img[hidden] { display: none }`(`47b1a90`). 사이트 빌드(`SKIP_APP=1`) 통과
6. **새 규칙.** "앞으로 인사를 고할 때 머지도 합시다" → 분신의 작별 인사 = 그 브랜치의 merge 승인(메모리, 본체에 전함)

## 결정

- 갤러리는 그림을 페이지 안에 넣어 편집기와 같은 규칙으로 선을 맞춘다(M88 ①). 그림 파일 · 다운로드는 그대로

## 발견한 위험

- 갤러리 밖(GitHub README · Obsidian · 파일을 브라우저로 바로 연 때)에서는 같은 그림의 선이 지금처럼 섞여 보인다. 파일 안의 `@media (resolution)` CSS는 `<img>`에서 듣지 않음(Chrome에서 확인)
- `pages/crisp-lines.js`는 편집기 `crisp-lines.ts`의 사본. T-1630 · T-1631이 같은 경우를 검증하지만, 편집기 쪽 규칙이 바뀌면 함께 고쳐야 함
- 브라우저 확대 · 화면 이동 때 다시 맞추는 것은 자동 시험으로 확인하지 못함
