# 2026-11-03 inbox: 테스트 목록을 기능 영역으로, 아뜰리에, til의 방법론, 논리 · 물리 뷰

메인테이너: "inbox 체크해주세요". inbox에 네 항목이 있었다. Claude가 항목마다 방향을 내고, 메인테이너가 고르는 창에서 정했다.

## inbox 원문

`1. 일하는 방식`:

- [[08-test-list]]는 많은 테스트들이 단순히 열거되어 있습니다. 분류를 해야 독자에게 유용한 정보가 될 수 있습니다. 사람 독자에게 유용하지 않다면 문서화할 필요도 없지요.
- page의 "작업 공간"을 "아뜰리에"로 바꿔주세요. "아틀리에"도 모두 "아뜰리에"로.

`3. 기능`:

- IDE 플러그인을 고려할 때, ER-Win 처럼 논리적, 물리적 뷰가 도입되면 좋겠습니다. 이 부분은 아키텍처에 변경이 클까요? 그렇다면 미리 고려가 되어야하겠습니다.

`6. 기타`:

- [[two-worker-scheduling]]은 오픈소스 운영에 관한 것이 아니라 방법론(일하는 방식)입니다. til을 검토해서 방법론에 관련된 것이 있는지 찾아주세요.

## 정한 방향

| 항목 | 메인테이너가 고른 것 |
| --- | --- |
| 테스트 목록 | 기능 영역으로 묶음(Claude 추천). 영역마다 한 줄 설명, 파일 → 영역의 표는 생성 스크립트에 |
| 아뜰리에 | "작업 공간" · "아틀리에"를 모두 "아뜰리에"로. 승인된 DR은 링크 글자만(Claude 추천), 세션 기록 · 연표는 그대로 |
| 논리 · 물리 뷰 | 뜻 A: 블록 하나를 설명 문장(논리)과 코드(물리)의 두 얼굴로 봄 |
| til의 방법론 | 새 주제 "방법론"(메인테이너: "1로 하되 일하는 방식 -> 방법론으로")에 two-worker-scheduling · spike-prototype-mvp, "오픈소스 운영"에 잘못 든 셋은 "테스트와 빌드"로 |
