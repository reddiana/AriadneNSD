# 2026-10-10 요구사항 리뷰용 프로토타입

메인테이너가 "프로토타입을 만들어주세요. 프로토타입을 보고 요구사항을 점검해봅시다."라고 요청하며 시작한 짧은 세션입니다. inbox는 비어 있었습니다. Claude가 프로토타입을 만들어 Artifact로 올렸고, 메인테이너는 다음 세션에서 써 보고 점검하기로 했습니다.

## 흐름

1. 세션 시작 요약: inbox 비어 있음, 부채 11건
2. 프로토타입 제작: 범위는 [[status]]의 "넣음"·"더 넣음" 그대로
3. Artifact 게시 → 받기(다운로드)가 claude.ai 안에서 막힌다는 경고 → `downloads` 기능을 선언해 다시 게시
4. 메인테이너: 세션 시작 요약을 저장해 다음 세션 시작 때 보여 달라고 요청 → [[status#다음 세션 시작 때 보여 줄 것]]

## 만든 것

- **프로토타입:** https://claude.ai/artifact/RuUjpc7YmCcbJXAdCeQiRG
- 사본: `journal/assets/2026-10-10-ns-prototype.html` (브라우저로 직접 열어도 동작)
- 들어간 것
	- 블록 4종(처리, If, While, Do-While), 선택(Shift+클릭 자동 확장, Shift+↑↓), 키보드 이동, 넣기·지우기·글자 고치기
	- 감싸기·풀기, 되돌리기·다시
	- 자동 레이아웃, 기본 스타일 C
	- 접기: 제어 블록 접기("⋯ 블록 n개"), 범위 접기(처음 접을 때 칸 안에서 이름 묻기)
	- 강조 영역: 굵은 테두리, 넓히기·합치기, 맞닿으면 따로, 중첩 거절
	- 이벤트 머리
	- 블록 글자 예제 두 가지: 같은 로직(TIM2 인터럽트 처리기)을 코드식·문장식으로
	- `.ns.svg` 받기·열기, "SVG 보기"(그림은 펼친 모양, 모델은 `<metadata>` 안)
- 프로토타입에서 모델은 범위(접기 이름, 강조 영역)를 블록 트리 안의 `range` 노드로 표현했습니다. 같은 부모 아래 연속 범위라는 규칙이 저절로 지켜집니다. 아키텍처 설계 때 참고할 만합니다.

## 만들며 생긴 질문 (메인테이너의 답을 기다림)

프로토타입 오른쪽 패널에 같은 목록이 있습니다. 요구사항에 답이 없어서 프로토타입에서 임시로 정한 것들입니다.

1. **펼친 뒤에도 이름 붙은 범위가 남는다.** 이름을 모델에 두니([[0017-fold-name-in-model|ADR-0017]]) 펼쳐도 범위가 보이지 않게 남는다. "이름 붙은 범위 보기"로 점선 표시. 평소에도 보여야 하나? 지우는 방법은 "풀기"로 임시 처리. [[01-requirements#^edit-fold-range]]
2. **기본 이름을 고른 경우.** 처음 접을 때 기본 이름을 고르면 "이미 물어봤음"을 파일에 남겨야 다음에 묻지 않는다. 그래서 이름 없는 범위도 저장된다.
3. **안쪽 깊은 곳에 강조 영역이 있으면?** 그 바깥을 강조하면 넓힐 수도(부모가 다름) 새로 만들 수도(중첩 금지) 없다. 지금은 거절. [[01-requirements#^edit-region]]
4. **짧은 갈래의 빈 공간.** If 두 갈래 높이가 다르면 짧은 쪽 마지막 블록을 늘려 채움. 빈 칸을 따로 그리는 방법도 있음. [[01-requirements#^lay-branch-width]]
5. **넣기 단축키.** 위치(뒤·앞·안쪽)는 도구 모음에서 고름. 브라우저가 Alt·Ctrl 조합을 많이 가져가서 감싸기는 `S` 다음 `W`/`D`/`I`. [[01-requirements#^edit-keyboard]]
6. **고른 상태에서 바로 타자를 치면** 엑셀처럼 글자 고치기로 들어갈까? 지금은 단축키라서 아무 일 없음. [[01-requirements#^edit-basic]]
7. **처리 블록 하나 접기.** 블록 하나짜리 범위가 생긴다. 막을까?
8. **접기는 되돌리기 대상이 아님.** 접힘은 보기 상태([[0016-fold-state-outside-file|ADR-0016]]). 처음 접을 때 범위가 생기는 것만 되돌림. [[01-requirements#^edit-undo]]
9. **이벤트 머리.** 맨 위 하나뿐이라 고르고 지울 수만 있고, 옮기거나 감쌀 수 없음. 머리 "뒤에" 넣으면 본문 맨 앞에 들어감. [[01-requirements#^blk-event]]
10. **블록 글자: 코드인가 문장인가.** 예제 두 개로 비교. 문장식에서는 구문 강조가 거의 하는 일이 없음. [[01-requirements#6. 미결정 사항]]
