# 2026-11-27 리팩토링 R1 ~ R5, 바뀐 블록만 DOM 반영, 문서 현행화, 영어 /about

## 흐름

1. **리팩토링은 언제.** 메인테이너: "우리가 리팩토링을 해본 적이 한 번도 없지요? 언제쯤 하면 좋을까요?" → 11-03의 준비(지금 동작을 적는 테스트 255개, 커버리지 하한)와 크고 자주 바뀌는 파일을 재어 답함. 시안 M77(파일 지도, 나눌 곳 R1 ~ R5, 물음 Q1 ~ Q4). Q2 그림이 "지금"을 보이지 않아 고침
2. **정함.** Q1 ①(R1 · R2 · R4) · Q2 ①(Obsidian 베타 전) · Q3 ①(공통 후보도 웹 안에서 파일만) · Q4 ①(R4 뒤 바뀐 블록만 DOM 반영). "웹베타 다듬을게 더 있나요?"에 남은 것을 셋으로 나눠 답한 뒤 "빨리 리팩토링에 진입하고 싶습니다" → 바로 시작. 도중에 "Q1을 ②로" → 다섯 모두
3. **R1 ~ R5.** 에이전트 넷이 나란히(R1 `376c964`, R2 `85b7380`, R4 `0191859`, R5 `000d015`), R3 `bddaca6`은 R2 뒤. 테스트는 고치지 않음, 공개 이름 그대로. 합친 상태로 `pnpm check` 통과, E2E는 T-0284 하나 실패 — 확대 ▾ 드롭다운을 없앤 뒤(M76) E2E를 고치지 않은 것이라 감싸기 ▾로(`17ac811`). 확대 · 축소 테스트 T-1510 ~ 1515의 번호(`next`)와 결정 ID(D3 → DD1)도 고침(`1831499`)
4. **문서 현행화.** "README의 로드맵에는 반영이 안 되어있어요" → 에이전트가 README · 요구사항 · 명세 · CONTRIBUTING을 고치고(`e16e57f` `4f9d2a2`), 판단거리 일곱을 메인테이너가 모두 고름(`362d709` `26384bd`)
5. **Q4 바뀐 블록만 DOM 반영.** 홀로 측정. 중간 보고를 받아 메인테이너에게 전함("왜 이렇게 오래 걸리지요?"). 남은 시간은 브라우저의 SVG 글자 재배치. 다음으로 메인테이너가 "명령 재계산 줄이기"를 고름(`c997f70`, 알림 구간 1 ~ 13ms). 그 측정은 PC가 바빠(Edge · Obsidian, 부하 26%) 전체 p95를 견줄 수 없었음
6. **영어 /about.** "영어 버전도 준비하는거 어떻게 생각해요?" → 앱 · 사용법 · 갤러리는 이미 영어가 기본, 소개만 영어로(`04f7d8b` `fe8a45a` `b7ac6ec`). 명세 영어판은 웹 1.0 때, 나머지는 한국어
7. **릴리스 글은 영어로.** "앞으로 github release에는 영어로 써주세요." → `src/README` 절차, v0.4.0 글을 영어로 바꿈
8. **Cloudflare Web Analytics.** 앱 안 브라우저는 Cloudflare 로그인 확인(Turnstile)을 통과하지 못함 → Claude in Chrome. 지난 7일 방문 51(직접 41, GeekNews 8), 한국 34 · 미국 9 · 중국 5, CLS의 원인 둘 → [[web-analytics#Core Web Vitals]]
9. **교사 홍보.** 독일어권은 Struktogramm(DIN 66261)이 수업 표준, 한국은 확인 못 함 → [[promotion#교사]]
10. **매듭/푸시.** 정리 에이전트가 `DocumentLayer`가 `canvas-view.ts`에 연결되지 않은 채 커밋된 것을 찾음(`20278da`에 `canvas-view.ts`가 없음). Q4의 "2/8 합격"은 main에서 재현되지 않는 숫자였음. 조용한 PC에서 E2E 87개 모두 통과(지난번 시간 테스트 실패는 PC 부하) → 연결을 다시 하고 재기로
