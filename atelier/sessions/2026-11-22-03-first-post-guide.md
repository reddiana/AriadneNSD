# 2026-11-22 처음 올리는 사람의 안내, 갤러리로 가는 링크

"GeekNews, Hacker News, Reddit에 뭘 올려본 적이 한 번도 없어요. 그리고 알고리즘에 관심있는 프로그래머라면 https://www.geeksforgeeks.org/ 에 모여있지 않을까요?"로 시작했다.

## 논의 흐름

1. **GeeksforGeeks.** 이야기를 나누는 곳이 아니라 검색해 들어와 튜토리얼을 읽는 곳이고, 기고는 편집부가 검토해 홍보 글을 받지 않는다. 올릴 곳에서 빼고, 그 독자층에게는 나중에 velog · dev.to의 "NS 차트로 보는 KMP" 같은 글로 → [[promotion#방향]]
2. **처음 올리는 사람의 단계별 안내.** 메인테이너: "네, 단계별 안내를 promotion.md에 더해 주세요". 세 곳의 안내 페이지(Show HN 규칙, GeekNews 이용법 · Show GN 안내 · 시작하기)를 읽고 계정 미리 만들기, 지킬 것, 곳마다의 차례를 적음(`9d3b2ab`) → [[promotion#처음 올리는 사람을 위한 단계별 안내]]
	- 알게 된 것: GeekNews는 타입을 Show로 고르면 제목 앞에 `Show GN:`이 저절로 붙고, 제목은 "프로젝트 이름 - 핵심 기능". 초안 1의 제목을 고침.
	- 세 곳 모두 새 계정에 제한이 있다(GeekNews는 일정 기간 글 등록 제한, HN은 2주 동안 초록 이름과 2026년 봄의 새 계정 Show HN 제한 보도, Reddit은 서브레딧마다 karma · 계정 나이). 그래서 계정은 지금 만들어 두기를 추천.
3. **promotion.md는 사이트에서 뺌.** 메인테이너: "그리고 @atelier/promotion.md 는 publishing에서 뺍시다." → 속성 `draft: true`(Quartz의 RemoveDrafts). status의 링크는 사이트에서 빈 링크로 보인다.
4. **갤러리로 가는 링크.** 메인테이너: "갤러리가 페이지의 메뉴 상단에 링크로 있으면 좋겠어요", "사용자도움말 바로 아래면 좋겠네요" → 사이트 왼쪽 메뉴(`site/patch-quartz.mjs`, `e75e0f3`), 그다음 "네, 앱 도움말 메뉴에도 넣어 주세요" → 앱 도움말 메뉴(에이전트, `82fa479`, T-1491) → [[ux-decisions#GL2. 갤러리로 가는 링크|GL2]]
	- 로컬 사이트에서 처음에 메뉴가 안 보였던 것은 브라우저에 남은 옛 스크립트 때문(새로 고침으로 보임).
	- 로컬 앱의 메뉴는 "복원" 질문 창이 떠 있어 확인하지 못함(메인테이너의 저장하지 않은 문서일 수 있어 누르지 않음).

## 결정

- GeeksforGeeks는 올릴 곳에서 뺌 → [[promotion#방향]]
- [[promotion]]은 사이트에 싣지 않음(`draft: true`)
- 갤러리 링크를 사이트 왼쪽 메뉴와 앱 도움말 메뉴의 사용자 도움말 바로 아래에 → [[ux-decisions#GL2. 갤러리로 가는 링크|GL2]], [[05-screen-layout]], [[03-editor#5.1 메뉴 구성]]
