# 2026-11-28 설계 문서에 NS 차트

[[2026-11-28-03-locale-blocks-impl|세션 03]] 뒤 이어 간 세션(독일어 · UX 그림을 에이전트에게 맡긴 채)에서 메인테이너가 갈라 낸 곁가지 세션입니다. 원래 세션의 일(독일어, UX 설계 · 사용법 그림, 동영상)은 그 세션의 기록에 적습니다.

## 흐름

1. **물음.** "설계나 아키텍처 문서에서 nsd로 그릴만한 것들이 있나요?" → `docs/03-architecture` · `04-design` · `05-spec`을 훑어, 함수 하나의 안쪽 흐름을 글이나 시퀀스 다이어그램으로만 적은 곳 여덟을 추천 순으로 보임. 데이터 흐름 · C&C · 상태 다이어그램 · 참여자가 여럿인 시퀀스 다이어그램은 NS 차트가 맞지 않아 Mermaid 그대로
2. **`extendTo`.** "그렇게 해주세요" → 실제 코드(`editor/src/state/selection.ts`)를 스킬로 옮겨 [[03-editor#2.1 범위를 넓히기 (자동 확장)]]에 넣음. 중간의 `return` 셋은 탈출 블록 → `168bbe8`
3. **그리다 본 것 둘.** 긴 조건이 If의 오른쪽 빗금에 걸림, `extendTo`의 주석이 "Shift+↑ ↓도 이 함수"라고 함(실제는 `extendBy`). "둘 다 진행하시고, 나머지 추천 둘도 해주세요" → 빗금은 결함이 아니라 [[ux-decisions#BH1. If · Case 머리의 폭과 높이|BH1]](2026-10-25 메인테이너가 정함)대로라 그대로 둠. 주석은 고침 → `1c9caa3`
4. **추천 둘.** 레이아웃의 두 단계(`layout` · `measureBlock` · `measureIf` · `placeItems` · `splitWidth`)를 [[02-layout#1.1 두 단계]]에, 파일 열기의 판별(`openSvgFile` · `parseModel`)을 [[01-file-format#5. 버전 관리]]의 시퀀스 다이어그램 아래에 → `3e7709e`
5. **폭.** "레이아웃의 nsd 가로폭을 줄여주세요" → 한 파일에 다이어그램이 여럿이면 앱이 비율 1.6에 맞춰 옆으로 늘어놓음. 다이어그램마다 한 파일(다섯)로 나누고 긴 식은 여러 줄로. 가장 넓은 `measureBlock`이 736px → `a58149f`
6. **곁가지 세션.** "곁가지 세션의 컨텍스트는 원래 세션의 컨텍스트를 상속받나요?" → 갈라진 때까지의 대화를 이어받고 그 뒤는 따로, 작업 폴더는 함께. "그렇다면 곁가지 세션은 토큰 절약과는 아무 관계가 없겠군요." → 곁가지 자체는 아끼지 못하지만 원래 세션의 맥락을 짧게 지킴. 맥락이 필요 없는 일이면 새 세션이 쌈
7. **정리.** "정리해주세요. 지금 세션에서 아뜰리에에 정리할 부분이 있지요?" → 이 기록, status · backlog · outbox · 연표 407 · 배운 것 258

## 발견한 위험

- 원래 세션의 에이전트들이 같은 폴더에서 일하는 동안 커밋하면, 그 에이전트가 고치다 만 파일이 섞일 수 있다. 이 세션은 `git commit -- 경로`로 바꾼 파일만 커밋했고, 커밋마다 `git show --stat`으로 들어간 줄을 확인했다
- 설계 문서의 NS 차트는 코드가 바뀌면 낡는다. 문서 동기 테스트가 잡지 않으므로, 그 함수를 고치는 일에서 그림도 다시 만든다(모델 JSON은 그림 파일 안에 있어 스킬의 `read`로 꺼낼 수 있음)
- `.claude/hooks/doc-check.py`에 파일 이름을 인자로 주면 입력을 기다리며 멈춘다(전체 검사는 `--all`). 이 세션에서 한 번 멈춰 껐다
