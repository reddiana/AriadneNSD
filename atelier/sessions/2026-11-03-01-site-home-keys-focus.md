# 2026-11-03 문서 사이트의 Home과 앱 열기, a p · A p, 빈 블록의 o · O, 캔버스 포커스(CF2), BUG-07 ~ 09

`/clear` 뒤의 새 세션이다. 앞 세션의 BUG-06 · TB1은 [[2026-11-02-04-font-manual-domain]]의 "매듭 뒤"에 있다. 메인테이너가 MVP와 문서 사이트를 써 보며 하나씩 말했고, 그 자리에서 고쳤다. inbox는 비어 있었다.

## 문서 사이트: Home과 앱 열기

메인테이너: "1. page에서 왼쪽 위 AriadneNSD를 클릭하면 app으로 가는데, Home으로 가게 해주세요 2. app으로 가는 링크는 별도로 탐색기 메뉴에 만들어주세요 3. 탐색기의 AriadneNSD는 Home으로 가는데, 위치도 맨 아래로 이상합니다. 빼주세요."

- 왼쪽 위 이름은 소개(`/about`)로, 탐색기 맨 위에 "앱 열기"(`/`), 탐색기에서 소개(`about`)를 뺌 → `site/patch-quartz.mjs`(Quartz의 `PageTitle.tsx` · `explorer.inline.ts`를 고침), `site/quartz.layout.ts`(`filterFn`)
- 로컬 빌드에서 확인함

## 키: a p · A p (UX KP1)

메인테이너: "`ap`를 단축키에 추가해주세요. `o`와 동일하게 처리블록이 추가됩니다." 이어서 "`a`에는 `p`가 있는데 `A`에는 없습니다." → `a p` = `o`, `A p` = `O`. 감싸기의 `s p`는 두지 않음(Claude) → [[ux-decisions#KP1. 처리 블록도 `a` + 종류 글자로|KP1]]. 키 표 문서, 사용법(한국어 · 영어), 사용법의 단축키 표(앱에서 다시 생성)를 고침.

## 빈 블록에서 o · O는 삽입 (UX KP2)

메인테이너: "빈 처리블록에서 `o`하면 앞에 블록이 삽입되지 않고 포커스 블록 편집이 됩니다." 뒤에 "내가 `O`를 `o`라고 적은 것 같아요. 앞에 삽입은 `O`지요. 미안해요". Claude가 정해 둔 규칙("빈 블록은 그 자리")이라고 알리자 메인테이너: "왜 우리가 바로 편집하게 결정을 했었지요?" Claude는 2026-10-10에 넣을 위치 모드(뒤 · 앞 · 안쪽)를 없애며 정한 기록([[2026-10-10-04-prototype-feedback]])을 찾아, 까닭이 적혀 있지 않음을 밝히고 추론(안쪽 모드의 대신, 빈 칸이 남지 않게, 제어 블록 넣기와 같게)을 보였다. 메인테이너: "oO는 편집이 아니라 삽입으로 해주세요." → [[ux-decisions#KP2. 빈 블록에서도 o · O는 삽입|KP2]]

- core `insertBlock`에 `besideEmpty`를 더하고 편집기의 `o` · `O`(와 툴바의 처리 아이콘)가 씀. 제어 블록과 끌어 놓기는 그대로 빈 블록을 바꿈. Case의 빈 default 칸에서는 블록 하나만 생김
- 인수 테스트 AT-04(키보드만으로 AT-01)가 빈 참 갈래에 `o`를 쓰고 있어 `Enter`로 바꿈

## 선택 테두리의 네 변 (BUG-07)

메인테이너: "셀렉트한 주황 테두리가 왼쪽과 오른쪽이 다릅니다. 오른쪽이 안쪽으로 더 들어가있어 보입니다." 문서 그림의 반 픽셀 밀림 때문에 오른쪽 · 아래 선이 상자 바깥 1px에 있었음. 오버레이가 그 1px까지 덮게 함 → [[defects]]

## 키 힌트를 클릭으로 닫기 (BUG-08, UX K4)

메인테이너: "`a` 메뉴나왔을 때 빈 공간을 클릭하면 메뉴가 사라져야합니다" → 캔버스를 누르거나 포커스가 캔버스를 떠나면 기다리던 첫 키를 버림 → [[ux-decisions#K4. 클릭하면 기다리던 키를 버린다|K4]]

## 캔버스의 포커스 테두리 (UX CF1 → CF2, 시안 M53)

메인테이너: "포커스가 사라지면 전체 캔버스가 굵게 셀렉트되는데, 내 기억이 이렇게 캔버스가 셀렉트 되지 않게 하기로 한 것 같아요."

- 기록: 2026-10-10에 "캔버스 포커스 선 대신 첫 블록 선택"으로 정했고, 2026-10-16 시각 디자인에서 WCAG 2.4.7로 다시 들어왔으며, OP1 뒤로 자주 보였음. 메인테이너: "접근성 때문은 무슨 말인가요?" → Claude가 WCAG 2.4.7을 설명함
- 메인테이너가 "없앰"을 고름(Claude는 1px로 줄이기를 추천) → CF1
- Claude가 "선택한 것이 없는 동안 키가 어디로 가는지 알 수 없다"는 대가를 알리자 메인테이너: "대안을 제안해주세요. 나는 사용자가 다이어그램을 검토하면서 다이어그램 자체에 집중할 수 있게 하고 싶었습니다." → 시안 M53(https://claude.ai/artifact/BrHSHnwUmVXn9MuG4hYSni)에 다섯 안. Claude의 추천은 1번(키보드로 들어오면 첫 블록 선택)
- 메인테이너: "4번 1초 뒤 사라짐으로 하고, 캔버스에 포커스 있는 동안 의미 없는 키보드 입력이 있을 때마다 1초간 테두리 하면 어떨까요?. 어떠세요? 이만하면 접근성 표준에 부합하나요?" · "아 마우스 클릭도요". Claude: 잠깐만 보이는 표시만으로는 2.4.7을 채우지 못하고, "늘 보이기" 설정이 있으면 채움 → 메인테이너가 설정도 두기를 고름 → [[ux-decisions#CF2. 캔버스의 포커스는 잠깐 보인다|CF2]]
- 메인테이너: "내가 달님의 의견을 존중한다는 점을 알아주시기 바랍니다." · "실제로 감사하고 있어요"

## 드래그할 때 글자가 선택됨 (BUG-09)

메인테이너: "블록이나 선택영역을 드래그하면 마우스 움직인 경로의 블록들의 텍스트가 하이라이트됩니다." → 캔버스에 `user-select: none`, 인라인 에디터만 글자 선택. 회귀 테스트가 고치기 전 코드에서 실패하는 것도 확인함.

## 일하는 방식: 로컬 서버로 바로 보여 주기

메인테이너: "퍼블리싱 해야 mvp를 테스트해볼 수 있는 것 같아요. 기다리는 시간이 제법 생기는데 로컬에서 바로 테스트해볼 수 있나요?" → `pnpm dev`(http://localhost:5173/). 이어서 "앞으로 app이 변경되면 로컬 서버로 실행해서 브라우저에서 보여주세요. 마무리할 때는 로컬 서버를 종료해주세요." → Claude의 기억에 적음.

## 발견한 위험

- "빈 블록은 그 자리"를 정한 까닭이 기록에 없어 추론으로 답했다. 규칙을 바꿀 때 까닭을 함께 적지 않으면 다시 같은 물음이 생긴다.
- 사용법의 그림은 다시 찍지 않았다. 선택 테두리가 1px 달라졌고, 다음에 그림을 다시 찍을 때 바뀐다 → [[backlog]]
- 캔버스 포커스 테두리의 "늘 보이기" 설정은 환경 설정 창에서 직접 보지 못했다 → [[outbox#확인해 주세요]]
