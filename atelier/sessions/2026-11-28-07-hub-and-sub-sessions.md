# 2026-11-28 허브와 서브 세션, 긴 작업 대기열, 시간 테스트

[[2026-11-28-05-blocks-rest-german-drop|세션 05]]의 매듭 뒤 `/clear`한 같은 세션(허브)입니다. 이 세션이 연 서브 세션 M86의 기록은 [[2026-11-28-06-drop-near-fold|세션 06]], M86이 연 UX 점검 서브 세션(M87)은 아직 진행 중입니다.

## 흐름

1. **이 세션과 M86의 관계.** "'선택 영역 곁의 드롭 규칙 시안 M86' 세션은 지금 세션과 어떤 관계인가요?" → `/clear` 전에 이 세션이 매듭 10번으로 연 서브 세션. worktree 없이 같은 폴더를 씀
2. **클라우드와 프로젝트(베타).** "우리가 하는 작업을 클라우드 저장소 세션으로 옮길 수 있나요?", "그럼 프로젝트(베타)는 무엇인가요?" → 옮길 수는 있으나 push 규칙 · Obsidian · localhost · 이 PC에만 있는 메모리와 부딪쳐 대화형 일은 로컬에 두기를 추천. 프로젝트는 코디네이터 + 스레드 + 루틴의 클라우드 작업 공간으로, 지금 `atelier/` 체계와 겹쳐 옮기지 않기를 추천
3. **세션 여럿 돌리기.** "세션을 여러개 돌리고 싶은데 어떤 방법을 추천하시나요?" → 백그라운드 에이전트 / 로컬 세션 + worktree / 클라우드 세션을 견주고, 허브는 대화 · `atelier/`, 구현은 worktree 세션을 추천
4. **3단 구조.** M86이 UX 점검 세션을 스스로 엶 → "지금 세션의 서브세션에서 다시 서브세션이 실행됐습니다. 구조가 이건 좀 아니다 싶네요." → 고르는 창에서 "허브 하나만 세션을 엶" → CLAUDE.md · how-we-work, 두 서브 세션에 알림. UX 점검 세션은 스스로 맨 위로 떼어 냄(detach)
5. **이름.** "허브 세션에서 서브 세션들을 컨트롤하는 구조가 흔히 쓰이는 방법인가요? 이름이 따로 있나요?" → orchestrator-workers · supervisor · hub-and-spoke, 계층형 → [[orchestrator-and-sub-sessions]]
6. **긴 작업 통제.** "앞으로 푸시나 e2e 테스트 등 시간이 오래 걸리는 작업은 허브 세션이 통제를 합니다. …" → 보완 넷(허락할 목록, 요청 · 답의 꼴, 대기열은 `status.md`에, worktree 브랜치는 merge 뒤)과 함께 적기로. "근데 대기열은 push만 기록하나요?" → 이름을 "긴 작업 대기열"로
7. **주제마다 서브 세션.** "서브 세션은 주제별로 실행하겠습니다. 에이전트가 돌고있는 세션을 매듭지을 수 없고, 시간이 아까워 계속 진도 나가면 세션이 여러 주제로 뒤죽박죽되는 것 때문에 서브 세션을 쓰려는 것입니다."
8. **세션 기록은 누가.** 고르는 창에서 "서브 세션이 직접"
9. **M86 마침.** M86이 N3까지 구현하고 문서 정리(`844f3ce`) · 세션 기록 06(`66cb5d5`)을 보냄 → 허브가 `status.md` · 세션 목록에 반영. M86 보관은 그 전에 메인테이너가 닫아 목록에 없었음
10. **정리해서 기록.** "서브 세션 운영하는 방식을 정리해서 기록해주세요." → [[dr-0023-hub-and-side-sessions|DR-0023]], [[how-we-work#본체와 분신]](시퀀스 그림 · 역할 표), TIL
11. **상태를 모르면.** 허브가 "그 세션에서 보세요"라고 미룸 → "서브세션의 상태를 아는데 한계가 있나요? 이런거 잘 모르면 컨트롤을 어떻게 하지요?" → 알 수 있는 수단 표(자동 보고 · 목록 · 대화 기록 · git · 메시지), 서브 세션은 턴마다 상태 한 줄, 허브는 먼저 확인
12. **M87 진행.** UX 점검 세션이 Q1(원칙 열 개) · F2 ~ F8을 정하고(`774085d`) 문서 정리(`fd4d58b`, DR-0024)를 보냄 → `status.md`에 반영. F2 · F3 · F4 · F7 구현은 그 세션의 에이전트가 진행 중
13. **시간 테스트.** "성능테스트 같이 로컬pc 상태에 영향을 받는 부분만 클라우드에서 실행하는 것은 어떨까요?" → Claude 클라우드 세션은 한 번에 수만 토큰 · 보고 없음 · VM도 흔들림. CI(GitHub Actions)가 이미 push마다 `pnpm check`를 돌림. 14. **어설픈 번역.** "어설픈 한국어 번역은 오히려 혼란스럽습니다. pc 메모리와 repo 메모리에 모두 명심하도록 기록해주세요." → CLAUDE.md · how-we-work · 메모리. 지어 쓴 "곁 세션"도 메인테이너의 말 "서브 세션"으로(DR-0023 본문 포함, "오늘 쓴 것이니 본문까지 서브 세션으로 바꿔 주세요")
15. **매듭.** "네, 매듭지어 주세요"(`875efc8`)
16. **M87 마침.** UX 점검 서브 세션이 F2 ~ F7 구현과 정리(`24508f1`)를 마치고 긴 작업(E2E · 전체 check · `test-list:strict`)을 요청 → `status.md`와 대기열에 반영, 메인테이너의 로컬 확인 뒤에 돌리기로
17. **F2가 안 된다.** "접기 영역 통째로 끌기가 반영이 됐다구요? 안 되는 것 같아요" → 허브가 서브 세션의 보고를 확인 없이 옮긴 것을 인정하고, 원문을 그 서브 세션에 넘김. 서브 세션이 브라우저에서 재현해 보니 동작(새로고침 · 끈 곳 등 짐작 다섯), 메인테이너에게 직접 물음
18. **허브의 일.** "허브 세션은 서브세션 관리에만 집중하는게 좋겠습니다." → 주제 일은 작아도 서브 세션에(`9d7140f`). "서브세션을 운영하는 목적은 무엇인가요?" → 기다리지 않고 진도, 주제를 섞지 않기, 언제든 매듭
19. **매듭.** "매듭지어 주세요"

## 결정

- 서브 세션은 허브 하나가 주제마다 열고, 서브 세션은 세션을 열지 않음. 세션 기록은 서브 세션이, 함께 고치는 문서는 허브가. 긴 작업(push · E2E · 전체 검사 · 커버리지 · 사이트 빌드)은 허브가 허락하고 `status.md`의 "긴 작업 대기열"에. 서브 세션은 턴마다 상태 한 줄 → [[dr-0023-hub-and-side-sessions|DR-0023]], [[how-we-work#본체와 분신]]
- 시간 테스트: T-1126은 로컬에서 `SKIP_TIMING=1`이면 skip하고 판정은 CI, T-0171은 시간 제한 60초 → `1b7b814`, [[02-test-architecture#5. 도구와 CI]]
- 어설픈 한국어 번역 금지(대화 · 문서), "곁 세션" → "서브 세션" → [[how-we-work#문서에서 쓰는 말]]
- 클라우드 세션 · 프로젝트(베타)는 지금은 쓰지 않음(대화형 일은 로컬)
- 허브는 서브 세션 관리에만 집중, 주제 일은 작아도 서브 세션에 → [[how-we-work#본체와 분신]]
