# 2026-11-22 LinkedIn 동영상을 다시 녹화해 다시 올림

"linkedin에 올린 동영상을 자세히 보니, for loop에 들어갈 내용을 먼저 작성하고 나중에 for loop로 감싸는데, … 보통 사람이 작성할 때 loop를 먼저 만들고 안에 블록들을 넣을 것 같아요."로 시작했다. inbox는 비어 있었다.

## 논의 흐름

1. **감싸기가 어색함.** 지난 동영상([[2026-11-22-05-linkedin-heap-sort-video]])은 반복문 셋(For 둘, `While True`)을 모두 몸을 먼저 쓰고 감싸서 만들었다. 같은 동영상의 If는 바깥부터 만들어 순서가 섞여 있었다. 처음 쓸 때는 바깥부터 쓰는 것이 자연스럽고, 감싸기는 나중에 되풀이가 필요함을 깨달을 때 빛난다고 의견을 냄.
2. **LinkedIn은 동영상을 바꿀 수 없음.** 메인테이너: "눈에 많이 거슬리거든요." 댓글이 없고 좋아요도 동영상과 상관없어 보여 지우고 다시 올리기로.
3. **다시 녹화를 네 번.** 에이전트가 `src/apps/web/promo/record.mjs`를 고쳐 녹화.
	- 반복문을 먼저 만들고 `j`로 빈 몸에 들어가 블록을 넣음(`a3602b3`).
	- 메인테이너: "copy해서 붙여넣기 하지 말아주세요. 오른 쪽 아래 키 동작을 보지 못했다면 뭐하는 거지? 싶을 수도 있습니다.", "while true도 감싸기 하지 마세요." → 둘째 호출을 직접 넣고 감싸기를 모두 뺌(`b0210e0`).
	- 메인테이너: "왜 궂이 첫번째 호출블록으로 올라가서 create method를 하나요?" → `gd`는 호출의 인자를 헤더의 매개변수로 옮기기 때문(둘째 호출이면 `sift_down(a, 0, end)`). 첫 호출 바로 뒤에서 `gd`로 바꾸려다 메인테이너가 멈춤.
	- 메인테이너: "첫 for 안에서 메소드에 들어갈 로직을 작성하고 그 로직을 메소드로 도출하는 것은 어떨까요?" → 첫 For 안에 내리는 로직을 직접 쓰고, 둘째 For를 만든 뒤 `While True`를 `m`(새 Method로 빼기)으로 빼 이름 칸에 `sift_down(a, i, n)`, 둘째 For에서 그 Method를 호출(`a4c500b`). 같은 로직이 또 필요해 함수로 빼는 흔한 리팩터링이라 키 표시 없이도 읽히고, 다른 NS 차트 도구에 없는 기능을 보여 줌.
	- 메인테이너: "처음 쓸 당시에는 break를 썼겠지요." → 빼기 전 heap_sort 안의 `return`은 정렬을 끝내 버리는 버그. 뺀 뒤는 While이 마지막 블록이라 `break` · `return` 둘 다 맞고, 메인테이너가 "break 그대로 두세요"(`7b0b74d`, 48.8초, 썸네일도 새로).
4. **첫 줄.** 메인테이너: "첫문장이 제 동료들에게 관심을 못 끌 것 같아요. 은근히 직접 개발하지 않고 claude활용한 것을 낮춰보더라구요." → (선택 창) "숫자로 시작": "6주 반, 테스트 1,768개, 결정 기록 62건. 프론트엔드를 처음 해 본 백엔드 개발자의 사이드 프로젝트입니다." Claude Code 이야기는 둘째 줄로(`996dce5`).
5. **태그.** `#SideProject`는 영어권에서도 흔한 말이고, 만든 과정을 앞세운 이 글에는 `#DeveloperTools` · `#OpenSource`보다 맞음(PR을 아직 받지 않으니 `#OpenSource`는 뒤에). 메인테이너가 태그는 그대로 둠.
6. **다시 올림.** https://www.linkedin.com/feed/update/urn:li:activity:7530170940547289088/ → [[promotion#올린 기록]](`1ac2854`)

## 결정

- 홍보 동영상은 처음 쓰는 순서대로: 반복문을 먼저 만들고 안에 적음. 감싸기 · 복사 · 붙여넣기 · `gd`는 쓰지 않고, 같은 로직이 또 필요할 때 새 Method로 빼기를 보여 줌. 빼기 전후 모두 `break`
- LinkedIn 첫 줄은 숫자로, Claude Code는 둘째 줄

## 발견한 것

- 녹화 중 앱의 결함은 없었다. 빈 몸에 `j`로 들어간 뒤 `Enter`를 누르면 텍스트 편집이 열려 `a c`가 글자로 들어가므로, 빈 블록 자리에는 `Enter` 없이 `a` + 종류를 누른다.
- 새 Method로 빼기의 이름 칸에 괄호와 인자를 적으면 헤더 인자와 남은 호출 블록의 인자가 함께 채워진다(문서대로).
