# 2026-11-21 Method가 없는 호출 블록

inbox의 호출 블록 요건 넷을 검토했다. 다른 문서의 Method 호출을 철회하고, Method를 잃은 호출 블록을 이름을 적는 호출 블록과 합치고, 호출 블록에서 Method를 만드는 명령을 더하기로 했다.

## inbox 원문

`# 3. 기능` › `## MVP` › `### 추가/변경 요건`:

```text
- 다른 문서의 Method를 호출하는 호출블록 기능을 요건에서 제외합니다.
- 호출하는 Method가 없더라도 호출블록의 ui가 달라질 필요 없습니다.
- 호출블록을 생성하면서 문서 내 없는 Method로 정할 수 있습니다.
- 호출블록이 바라보는 Method가 없을 때 호출블록이 가리키는 Method 다이어그램을 새로 만드는 방법을 제공합니다. (단축키, 우클릭 메뉴)
```

## 논의 흐름

1. 지금 설계와 견줌: 다른 문서의 Method 호출은 R-BLK-09(`P2`)이고 앱에는 없으며 모델의 `external`만 읽어 보존한다. 이름을 적는 호출 블록(`named`)은 이미 실선이고, Method를 삭제해 잃은 호출 블록(`lost`)만 점선과 `?`이며 편집할 수 없다. 문서에 없는 Method로 정하는 것은 "이름을 적어 호출하기"(R-BLK-08, CB6)로 이미 된다.
2. 메인테이너가 고른 것(모두 Claude의 추천안):
	- 잃은 호출 블록은 이름을 적는 호출 블록으로 합친다. Method가 없어지면 그 이름의 `named`가 되고 실선, 이름 · 인자 · 결과를 편집할 수 있다. 예전 파일의 `lost`는 열 때 `named`로 읽는다.
	- Method 만들기의 키는 `gd`: Method가 있으면 지금처럼 이동하고, 없으면 문서 끝에 Method 다이어그램을 만들어 잇고 그리로 이동한다. 컨텍스트 메뉴 "Method 만들기"(Method가 없을 때만).
	- 만든 Method의 헤더는 `이름(호출 블록의 인자 글)`, 본문은 빈 블록 하나. 문서 안에서 같은 이름을 적은 호출 블록도 모두 새 Method에 잇는다. 실행 취소 한 번으로 되돌린다.
	- 다른 문서의 Method 호출(R-BLK-09)은 철회하고, 모델 · 파일 형식에서 `external`도 빼며, 파일에 있으면 마지막에 본 이름의 `named`로 읽는다.

## 결정

- R-BLK-09 철회, 새 요구사항(Method 만들기), `lost` · `external`을 `named`로 합치는 ADR-0049 → 에이전트에게 맡김. 반영한 곳은 매듭 때 여기에 링크한다.
