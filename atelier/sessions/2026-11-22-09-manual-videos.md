# 2026-11-22 사용법에 힙 정렬 동영상(키보드만 · 마우스만)

"사용자 도움말 md가 뭐였지요?"로 시작했다. inbox에는 빈 제목 "7. 기타 › 매뉴얼"만 있어 그대로 두었다.

## 논의 흐름

1. **사용자 도움말의 원본.** md가 아니라 `src/apps/manual/pages/`의 HTML(둘러보기 `ko.html` · `en.html`, 찾아보기 `ref-*.html`)이고 `build.mjs`가 한 페이지로 합친다고 알림.
2. **동영상을 사용법에.** 메인테이너: "사용자 매뉴얼에 프로모션에서 썼던 동영상을 활용하고 싶습니다. … 같은 힙정렬에 마우스만 사용하는 버전을 추가해서 사용법을 설명하면 사용자들에게 도움이 많이 될 것입니다." "프로모션 동영상은 LinkedIn에 올렸던 동영상을 말합니다." 에이전트가 LinkedIn 녹화 스크립트를 본떠 `src/apps/manual/video/record.mjs`(`--mode keys|mouse --lang en|ko`)를 만들고 넷을 찍는 동안, 시안 M73(자리 V1 · 재생 V2 · 언어 V3)을 냄.
3. **고름.** V1 나란히, V2 누르면 재생, V3 처음엔 "영어 하나를 둘이 같이"였다가 "V3를 언어마다 따로 해주세요". If 참 분기는 `break` 그대로(갤러리 원본은 `return`). 에이전트가 둘러보기 맨 위에 넣음(`814ddd8`).
4. **마우스판 다시.** "마우스 버전은 가급적 툴바의 아이콘 드래그와 우클릭 메뉴를 사용해주세요. 메뉴는 가급적 피해주세요." "확대/축소는 단축키를 써주세요." 드래그 위주로 찍으니 If 위에 놓으면 그 If를 감싸 버려 아래 블록부터 그리게 됨. 메인테이너: "드래그 보다 마우스우클릭을 더 우선해야겠네요. 그런데 sift_down에 가장 밑의 블록을 먼저 만들고 그 다음 위쪽에 if 블록을 만들던데 이유가 있나요?" → 우클릭 › 삽입 위주, 드래그는 While 한 번, 위에서 아래로 다시 찍음(한국어 `2e6f26a`, 영어 `50da46f`).
5. **탭으로.** "그리고 키보드/마우스 버전 나란히 말고 탭으로 합시다." → 탭 "키보드만" · "마우스만"(`e5c4beb`). 메인테이너가 "탭 밑에 동영상이 또 있어요": 고른 탭과 상관없이 둘 다 보이던 결함. `.videos figure`의 `display: grid`가 `hidden`을 덮었다. 고침(`f628728`). 처음 확인 때 `hidden` 값만 보고 실제로 보이는지는 보지 않았다.

## 결정

- 사용법의 힙 정렬 동영상 → [[ux-decisions#MV1. 사용법의 힙 정렬 동영상|MV1]], 시안 M73

## 발견한 위험

- CSS로 `display`를 준 요소에 `hidden` 속성만으로는 숨지 않는다. 숨김을 확인할 때는 속성 값이 아니라 보이는 크기로 본다.
- 툴바 아이콘을 If 위에 놓으면 뒤에 삽입하지 않고 감싼다. 마우스만 쓰는 사람에게 "If 다음에 블록 넣기"는 우클릭 › 삽입이 자연스러운 길이다.
