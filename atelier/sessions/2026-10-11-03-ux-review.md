# 2026-10-11 요구사항과 UX 규칙 검토: 공통 규칙 일곱, 호출 블록 펴 보기, 프로토타입으로 하나씩

2026-10-11의 셋째 세션이다 (← [[2026-10-11-02-confirmations]]). 메인테이너가 inbox에 "가장 중요합니다. 최우선으로 해주세요"라고 적은 요구사항과 UX 규칙의 검토를 했다. Claude가 공통 규칙 일곱 개와 물음 23개를 내놓았고, 메인테이너는 호출 블록 펴 보기에 대한 물음 여덟에 답한 뒤 "너무 많은 결정들이 있었습니다. 혼란스럽네요."라며 프로토타입으로 하나씩 보자고 했다.

## 논의 흐름

1. **세션 시작.** 상태, 부채, 지난 세션 기록, inbox를 읽었다. inbox에 새 항목이 다섯 있었고, 원문을 지키려고 먼저 커밋했다. 처리 방향을 제안하면서 요구사항을 한 번 읽어 첫눈에 걸린 곳 열 가지를 표로 보였다.
2. **"좋습니다. 진행해주세요."** 메인테이너가 기준을 하나 더했다: 요구사항 문서는 "단순하고 합리적이며 우리가 원하는 결과를 만들고 평가하기에 부족함이 없어야" 한다.
3. **README의 라이선스 문장.** 표에 "이름" 줄을 더하고 문장을 바꿨다. 작업 중에 메인테이너가 "쓰다"는 두 뜻이 있다고 알려 "사용하다"로 바꿨다.
4. **검토 문서와 독립 검토.** Claude가 [[ux-decisions|ux-review]]를 쓰는 동안, 요구사항과 용어집만 건네받은 다른 Claude가 따로 읽었다 → 아래 "검토에서 나온 것".
5. **호출 블록 펴 보기 시안.** 말로 견주기 어려워 시안을 만들었다. 메인테이너가 Claude의 세 안이 아니라 전날 버린 시안(영역 강조 시안)의 A를 가져와 접기 영역의 모습까지 바꿨다 → 아래 "펴진 모습".
6. **물음에 하나씩 답함.** Q13, Q14, Q15, Q15-a, Q15-d(정했다가 바꿈), Q15-c, Q14-a.
7. **"선택지를 모르겠어요."** Q15-d, Q15-c, Q14-a를 Claude가 글로만 물었다. 메인테이너: "물어보는 것은 모두 시안을 확인할 수 있게 해주세요." 두 물음을 시안에 그려 넣고, 남은 물음도 모두 그림으로 옮긴 UX 규칙 시안을 만들었다.
8. **세션 중의 inbox.** 메인테이너가 inbox에 "단축키를 통일할 수 있나요?"를 적었다. Claude가 작업 중에 알아채 원문을 커밋하고 답했다.
9. **"프로토타입을 통해 하나씩 리뷰합시다."** 한 판에 한 묶음씩 넣는 순서를 정하고, 1판(37번째 판)을 다른 Claude에게 만들게 해 게시했다.
10. **마무리.** "힘드네요. 마무리 전에 결정이 필요한게 있나요?" 없다고 답했다. "마무리".

## 검토에서 나온 것

지금 요구사항의 편집 규칙은 60개쯤이고 블록 종류마다 따로 적혀 있다. 공통 규칙 일곱 개로 묶을 수 있다는 것이 검토의 결론이다. 아직 메인테이너가 받아들인 것은 아니다. → [[ux-decisions|ux-review]]

| 공통 규칙 | 한 줄 |
| --- | --- |
| 고치기 | 글자가 있는 것은 모두 같은 방법으로 고치기 시작하고 끝낸다 |
| 빈 글자 | 비울 수 없는 칸을 비우면 어디서나 같은 일이 일어난다 |
| 넣는 자리 | 새로 생기는 것은 고른 것 뒤에, `Shift`는 앞에 |
| 옮기기 | 블록 · 갈래 · 다이어그램의 순서를 명령 하나로 바꾼다 |
| 묶기와 풀기 | 묶는 명령은 셋, 푸는 명령은 하나 |
| 접기 · 펴기 | 보기만 바꾸는 명령은 하나이고, 무엇에나 같은 식으로 듣는다 |
| 실행 취소 | 내용을 바꾸면 대상이고, 보기만 바꾸면 대상이 아니다 |

inbox의 두 기능이 이 규칙에 들어맞았다. 호출 블록 펴 보기는 접기 · 펴기가 듣는 것에 호출 블록을 더하는 일이고, 치환은 "Method로 빼기"의 빠져 있던 짝이다.

독립 검토는 일곱 가운데 여섯에서 같은 결론에 닿았고, Claude가 놓친 것을 찾았다: "언제나 무언가 골라져 있게 하기", 접기가 듣는 곳을 한 문장으로, 우선순위 태그와 MVP 범위의 어긋남, "머리"와 "선택 블록"이 두 뜻으로 쓰임. "이 문서만 보고 만들고 평가할 수 있는가"에 걸리는 곳을 80개쯤 찾았다(지우기 규칙이 통째로 없음, "빈 블록"의 정의가 없음 등).

## 펴진 모습

Claude는 펴 보인 호출 블록의 모습 세 가지(이중선이 감싼다, 머리 줄 아래에 그대로, 왼쪽 띠)를 그렸다. 메인테이너의 답:

> 기존 접기영역 펼쳤을 때 디자인을 변경하고 싶습니다. EASYCode식으로 왼쪽 세로 막대 + 위에 이름 띠로 합시다. Q15도 이렇게 합시다.

이어서:

> NS 영역 강조 시안의 A를 참고해주세요. 이름띠 폭과 색깔만 현재 접기영역 펼쳤을 때와 비슷하게 해주세요.

2026-10-10에 강조 영역의 모양으로 견주고 고르지 않았던 A안(→ [[dr-0004-highlight-region-border|ADR-0015]])이, 접기 영역의 모양으로 돌아왔다. 그때의 단점("이름은 접기의 일이라 이 장점이 강조에는 필요 없다")이 지금은 장점이다.

## 발견한 위험

- **물음을 한꺼번에 너무 많이 냈다.** 23개에 딸린 물음 다섯. 메인테이너가 "혼란스럽네요", "힘드네요"라고 했다. 지난 세션에서 통했던 "하나씩 묻고 번호로 답하기"를 이번에는 문서 하나에 모아 내는 것으로 바꿨는데, 그것이 무리였다.
- **선택지를 글로만 적었다.** "선택지를 모르겠다"는 말이 세 번 나왔다. 시안이 있는 물음과 없는 물음이 섞여 있었고, 시안이 있어도 카드에 물음 번호가 없었다.
- **검토의 결론은 아직 받아들여진 것이 아니다.** 공통 규칙 일곱과 문서를 다시 짜자는 제안(Q18)에 메인테이너는 답하지 않았다. 요구사항 3.1과 3.2는 그대로다.
- **요구사항이 다시 프로토타입보다 앞서거나 뒤처진다.** 호출 블록 펴 보기는 요구사항과 프로토타입에 다 들어갔지만, 2026-10-11 둘째 세션에서 정한 다섯 가지는 여전히 프로토타입에 없다(6판으로 미룸).
- **프로토타입 37번째 판은 다른 Claude가 만들었고, Claude는 화면 한 장과 시험 결과만 보았다.** 만들면서 정한 것이 열 가지쯤이다 → [[outbox]]
- **"3번 이상 재귀 펼치기"의 풀이를 확인받지 못했다.** "같은 Method가 세 번째로 펴지는 때부터, 다이어그램 자신이 첫 번째"로 만들었다.
- **흑백에서는 접기 영역과 펴 보인 호출 블록을 띠의 글자로만 가를 수 있다.** C1을 고르며 따라온 것이다. While과 헷갈리는지(Q15-b)도 답을 받지 못했다.
- **독립 검토가 놀랍다고 한 것 가운데 어제 정한 것이 여섯 있다.** 숨긴 인자를 파일 밖에 기억하는 것 등. 그대로 두는 것을 기본으로 했고, 메인테이너에게는 목록만 보였다 → [[ux-decisions|ux-review]] 6.3
- **헤드리스 Chrome이 가끔 말없이 실패했다.** `--user-data-dir`를 따로 주고 다시 돌려 넘어갔다. 원인은 모른다.

> - [[README#라이선스]]에서 "`AriadneNSD`라는 이름을 제품의 이름으로 쓸 권리는 어느 쪽에도 들어 있지 않습니다." 이 말이 무슨 뜻인지 헷갈려요. 아마 다른 사람도 마찬가지일 것입니다. 읽은 사람이 본인에게 권리가 있다고 착각할 수 있겠어요.
