## 한 일

1. **본문 태그를 링크로.** 2026-10-18에 사이트를 펴낼 때 본문의 `#P0`을 일부러 글자로 두었다. 켜고 빌드해 보니 두 겹 아래 폴더(`docs/01-requirements/`)에서 링크가 `../.././../tags/P0`로 사이트 밖을 가리켰다. 원인: Quartz가 태그 링크를 지금 문서 기준 주소로 만드는데, 뒤의 CrawlLinks가 그것을 사이트 맨 위 기준으로 보고 `../..`를 또 붙인다. 태그 링크를 맨 위 기준(`tags/P0`)으로 만들게 `site/patch-quartz.mjs`에 패치를 더하고 켰다. 조사가 붙는 문제(`#P0은`)는 글 속의 우선순위를 코드 표기로 쓰는 규칙(CLAUDE.md, 2026-10-25)으로 이미 사라져 있었다(남은 것은 모두 코드 표기 안). → [[dr-0013-publish-docs-github-pages|DR-0013]] 이후 변경, [[github-pages-site#본문의 `#P0`이 링크가 되기까지]]
2. **ADR-0002의 패키지 목록을 표로.** 승인된 ADR이지만 메인테이너의 요청이고 글은 그대로라 모양만 바꾸고, 이후 변경 콜아웃에 적었다.
3. **자동 확장 예시를 그림으로.** 프로토타입에 예시 문서를 넣고 찍었다(`journal/assets/2026-10-25-multiselect-shots.mjs`, 그림 `docs/02-ux-design/assets/interaction-multiselect-1.png` · `-2.png`). 그림이 있으면 짧아서 접지 않고 펼쳤다. 메인테이너의 요청으로 두 번 고쳤다.
	- "while 안에 c외에 블록을 하나 더 넣고 c를 shift+클릭하는 것으로" → While 안을 C · D로. 클릭하지 않은 D도 함께 골라짐이 보인다
	- "왼쪽 다이어그램에서 C를 선택했음을 표시 해주면 좋겠어요 마우스 포인터라든지" → 포인터와 "Shift+클릭" 딱지를 얹음. 딱지 바탕은 고른 표시의 주황과 헷갈리지 않게 짙은 회색
4. **셸 그림을 Mermaid로.** `flowchart TB`에 셸마다 subgraph(안은 `direction TB`, 두 상자를 보이지 않는 선 `~~~`로 이음). 처음 `flowchart LR`로 그렸을 때는 세 셸이 위아래로 쌓였고, 셸 이름에 할 일을 붙였을 때는 이름이 잘렸다. 그려진 순서는 웹 · 데스크톱 · Obsidian이다.

## 발견한 것

- 지난 세션에 띄운 `quartz build --serve`가 아직 돌며 `site/.quartz/public`을 지운다. 이번에는 임시 폴더(`QUARTZ_DIR`)에서 따로 빌드했다. 메인테이너에게 꺼도 된다고 알렸다.
- Quartz 사이트의 그림은 화면 밖에 있으면 늦게 읽혀(lazy), 헤드리스로 찍을 때는 그 자리로 스크롤해야 보인다.
- `(#P1)`처럼 괄호 바로 뒤의 태그는 Quartz가 태그로 읽지 않는다(앞에 빈칸이 있어야 함).

## 마무리 뒤: 문서 태그 `ariadne-nsd`를 지움

메인테이너: "#ariadne-nsd 태그는 왜 필요한가요? 모든 문서에 다 붙어있는 것 같은데요?"

2026-10-07 첫 커밋에서 Claude가 `nsdrawing`으로 붙였고(이름을 바꿀 때 따라 바뀜), 까닭은 적지 않았다. 여러 프로젝트가 섞인 볼트에서 이 프로젝트의 문서를 골라내는 쓰임인데, 볼트가 이 저장소 하나라 쓸모가 없고, 121개 문서 가운데 78개에만 붙어 있었으며, 쓰는 곳도 없었다. 사이트에서는 거의 모든 페이지에 딱지가 붙었다. 고르는 창에서 "모든 문서에서 지움(추천)"을 골라 78개 문서의 속성에서 지웠다(`docs/README.md`는 태그가 이것뿐이라 `tags:`도 지움). CLAUDE.md의 규칙을 고치고, [[dr-0005-product-name|DR-0005]] · [[dr-0011-repo-name|DR-0011]]에는 이후 변경을 달았다. 세션 기록과 타임라인 속의 옛 언급은 그때의 기록이라 두었다.
