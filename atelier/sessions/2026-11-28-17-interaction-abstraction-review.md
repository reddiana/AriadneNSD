# 2026-11-28 조작 규칙 · 아키텍처 · 설계의 추상화 검토

본체가 연 분신. 조작 규칙의 추상화와 아키텍처 · 상세 설계 · 코드의 추상화를 함께 검토하고, 조작 규칙의 공통 규칙을 절과 표로 다시 세웠다. 브랜치 `claude/arch-review-interaction-rules-1284d9`(worktree `gallery-line-width-c35c3b`). 코드는 수정하지 않았고 push하지 않았다.

## 흐름

2. **첫 검토(공통 규칙만)**(`d2ff8a4`). 공통 규칙 C1 ~ C5와 명령 × 대상 매트릭스가 코드의 요소에 대응하는지 봄. C4 · C5 · 명령 레지스트리는 1:1, C1 · C2 · 매트릭스는 명령마다 `if` 사슬(선택의 종류 분기 21개 파일 약 200곳). 시안 M91과 ADR-0054(제안됨)를 만들고 Q1(매트릭스 대조 테스트 → 대상 해석기)을 물음. 메인테이너: "매트릭스 72칸이 뭐지요?" → 명령 12행 × 선택한 요소 6열이라고 설명 → "Q1 1번"
3. **범위가 좁았다.** 메인테이너: "ux interaction rules에서 오늘 변경한 것만 검토했나요? 전체를 검토해야해요." → 공통 규칙만 기준으로 삼았고 1 ~ 9장은 대조하지 않았다고 답함. 이어서 메인테이너: "내 의도는 이렇습니다. interaction rules가 추상화가 훌륭했다면, 그것을 구현한 아키텍처와 설계도 추상화가 훌륭해질 것이라는 신념입니다. 그래서 interaction rules와 아키텍처와 설계를 함께 검토해달라 요청드리는 것입니다."
4. **전체 검토**(`5fc010a` · `9ea41fc`). 조작 규칙 744줄을 모두 읽고, 코드의 사실 확인은 읽기 전용 에이전트 여섯(Sonnet)에 나눠 맡김(텍스트 필드, 보이는 나무와 방향키, 드래그 앤 드롭, 접기 대상 사슬, 블록 종류, 진입점과 실행 취소). 인용할 수치는 다시 세어 확인. 결과 → [[interaction-abstraction-review]], 시안 M91
	- 규칙이 개념 하나로 서 있는 곳은 코드도 요소 하나이고, 사례의 나열이나 "X는 Y처럼"으로 적힌 곳은 코드도 종류마다 분기한다(수준 A ~ D의 표)
	- 이름 없이 되풀이되는 개념 여섯: 컨테이너와 대표 요소, 명령마다 받는 대상, 삽입 위치, 블록 종류의 분류, 텍스트 필드, 실행 취소 단계의 묶음

	- 방향키가 쓰는 보이는 나무가 컨테이너를 한 구조로 표현한다. 이것을 드롭 · 명령의 대상 · 이동 명령까지 넓히는 것이 가장 큰 개선

## 발견한 위험

- 처음에 검토의 범위를 그날 고친 공통 규칙으로 좁게 잡았다. "깊게 검토"는 문서 전체였다
- 조사 에이전트의 보고 가운데 한 건은 사실이 아니었다(풀기의 알림이 무한 반복 · 병렬 처리에서 종류의 id를 보인다: 전용 알림 키가 있음). 보고의 수치와 사실은 인용하기 전에 다시 확인해야 한다
- 조작 규칙에 추가한 표의 일부 칸(빈 default 칸의 열, 접기 영역 만들기 · 풀기의 행, 호출 블록을 삽입한 직후 여는 필드)은 코드를 읽어 채웠고 앱에서 실행해 확인하지 않았다. 표 대조 테스트(0단계 다)에서 검증한다
- 결함 후보(고치지 않음, [[backlog#조작 규칙과 설계의 추상화]]): 접기 · 펴기의 알림이 무엇에 적용했는지 알리지 않음, 컨텍스트 메뉴에서 접기 영역을 선택하면 삽입 · 붙여넣기가 없고 헤더를 선택하면 삽입이 없음, 빈 default 칸에서 접기 영역 풀기는 거절, 헤더 · 분기 라벨 · 접기 영역의 이름에 줄 바꿈을 입력했을 때의 규칙이 없음
- 아키텍처 5.1 · 6장 · 3.2와 모델 4장에 지금과 다른 문장이 있다(실행 취소의 대상, 입력의 단일 경로)
- 이 기록의 번호 17은 같은 날 다른 분신의 기록과 중복될 수 있다(본체가 merge할 때 확인)
