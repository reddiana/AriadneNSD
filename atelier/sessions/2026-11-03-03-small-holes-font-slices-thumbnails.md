# 2026-11-03 작은 구멍 넷, 화면 글꼴을 조각으로(ADR-0040), 예제 썸네일을 미리 그림

메인테이너: "진도 나갑시다". inbox는 비어 있었다. 웹 베타의 문턱에 남은 것은 모두 메인테이너의 일이라, Claude가 혼자 할 수 있는 것 넷을 고르는 창으로 내고 메인테이너가 "작은 코드 구멍 묶음"(Claude 추천)을 골랐다.

## 작은 구멍 넷

backlog의 "MVP 코드에 남은 구멍"에서:

- "풀기"가 감쌀 것 없는 블록에서도 흐려지지 않던 것: 담은 제어 블록이 없으면(호출 블록 하나면 "아직 지원하지 않음") 메뉴 · 팔레트에서 흐려짐. T-0520
- `Ctrl`+`V` 바로 뒤의 `Ctrl`+`S`가 붙이기 전의 문서를 저장할 수 있던 것: 저장 · 다른 이름으로 저장이 진행 중인 붙여넣기를 기다림. T-0521
- 컨텍스트 메뉴의 하위 메뉴가 창 밖으로 넘치던 것: 오른쪽에 자리가 없으면 왼쪽으로, 양쪽 다 없으면 메뉴 위로 겹쳐, 아래로 넘치면 위로. `l`로 열고 `h`로 닫음. T-0522
- 좁은 화면 툴바의 줄 맨 앞 · 맨 끝 구분선: 맨 앞은 없애고 맨 끝은 보이지 않게만. T-0523
- 그 밖에 vitest 설정의 낡은 주석, 사용법 그림을 다시 찍음(새 그림에서 "풀기"가 흐림)
- 새 테스트 넷은 고치기 전 코드에서 실패하는 것을 확인함
- 문서: [[03-keymap]](K2 줄), [[03-editor]] 1장, [[05-screen-layout]]

메인테이너가 로컬에서 써 봄: "처리 블록 하나를 오른쪽 클릭 → "풀기"가 흐린지 : 흐림", "줄 끝에 구분선이 없는지 : 없음", "블록을 오른쪽 클릭 → "삽입"에서 l / h : ok"

## 화면 글꼴을 조각으로 (ADR-0040)

메인테이너: "이어서 진행". Claude가 추천한 다음 일, 휴대폰 첫 내려받기 줄이기(465 KB 가운데 320 KB가 한글 전체를 담은 화면 글꼴).

일하는 중에 메인테이너: "아, 글꼴을 나눠서 받을 수도 있는 거구나" → [[font-slices-unicode-range]]

- 재 본 것: 한글 2,350자(KS X 1001)만 묶어도 118 KB. 이 저장소 문서의 한글은 1,008종이고 앞 500자가 쓰인 글자의 98%
- 나눔: 기호 · 유럽 · 동아시아 셋, 자주 쓰는 한글 1,008자를 100자씩, 나머지를 코드 순서로 400자씩, 모두 38조각. 자주 쓰는 순서는 `hangul-order.txt`로 고정(다시 빌드해도 같은 조각)
- 조각의 목록은 처음에 43 KB(gzip 15 KB)라, 자주 쓰는 조각은 글자 자체, 나머지는 첫 · 끝 코드만 적고 브라우저가 `unicode-range`를 계산하게 함(gzip 4 KB). 끝의 작은 조각은 Vite가 JS에 끼워 넣어서 앞 조각에 합침
- 결과: 첫 내려받기(gzip) 465 KB → 176 KB. 번들 사이즈 체크의 한도 540 → 212 KB. 테스트 T-0524 ~ T-0528
- 측정이 날마다 0.5초 넘게 흔들려(지난번 1.8초가 오늘 같은 코드로 3.2초), 고치기 전 코드를 같은 날 다시 재어 견줌. 다시 방문할 때 글꼴까지 3.4초 → 2.1초. 첫 화면은 그대로였다
- 조각을 시작부터 등록하면 첫 그림이 한글 조각을 받으러 가서, 조각 0이 온 뒤에 등록함
- 메인테이너: "1.8초도 빠른 것은 아니지요." Claude: 네트워크를 빼고 CPU만 느리게 해도 2초가 넘어, 첫 화면은 JS 실행과 그리기의 일이다
- 메인테이너: "ADR-0040: 승인"

## 예제 썸네일을 미리 그림

메인테이너: "썸네일 열 개를 미리 그려두면 어떨까요? 그려둔 썸네일을 내려받아서 보여주는 것은 시간이 짧겠지요."

- 먼저 썸네일을 빼고 재어 원인임을 확인(첫 방문, CPU만 느리게 2.2 ~ 2.6초 → 1.6초)
- 형식은 쓰인 글자의 서브셋 글꼴(WOFF)을 넣은 SVG. 예제 · 화면 언어마다 하나, 20개(10 ~ 51 KB). 코어에 모델 없는 그림 SVG `assembleImageSvg`, 편집기에 `exampleThumbnailSvg`, 셸이 `ExamplesHost.thumbnailUrl`로 넘김(없으면 모달이 직접 그림)
- `pnpm --filter @ariadne-nsd/web thumbnails`로 만들고, 낡으면 T-0529가 실패
- 결과(CPU 6배 느림, 다섯 번 중앙값): 첫 방문의 편집 화면 2.2 ~ 2.6초 → 1.7초, slow 4G 3.2 ~ 3.5초 → 2.5초. 썸네일 그림은 그 뒤 1초쯤에 채워짐
- 측정 스크립트가 이미지의 load도 보게 고침
- 문서: [[06-web]] 5장과 7장, [[05-screen-layout]]

## 발견한 위험

- 시작 시간의 측정은 날마다 크게 흔들린다. 고치기 전과 후는 같은 날 같은 기계에서 여러 번 재어 견줘야 한다
- 썸네일 그림은 예제 · 렌더러가 바뀔 때마다 다시 만들어야 한다(테스트가 알림)
- 썸네일 이미지를 그리는 동안 글꼴 조각 0이 늦어진다(첫 방문의 `data-ready`가 CPU 6배 느림에서 약 3초)
