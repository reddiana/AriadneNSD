- [x] (2026-11-01 세션 01, 메인테이너: "그대로 확정해 주세요") 2026-11-01 MVP 조작 물음에서 Claude가 정한 세부 (M43 → [[ux-decisions#10. 2026-11-01의 결정]]): 이름 없는 접힌 줄("⋯ 블록 n개")의 더블클릭은 펼치기 · 세모(`▸` `▾`)는 저장되는 그림에 넣지 않음 · 옮기기 키 `Alt`+방향키(`Alt`+`h` `j` `k` `l`) · If의 참 · 거짓을 맞바꿀 때 조건은 그대로 두고 알리기만 · 갈래 이름에서 `h` `l`은 옆 갈래 이름, `j`는 첫 블록 · `Shift`+`L`은 갈래 안 블록에서 바로 이름을 고치는 지름길로 남김
- [x] (2026-11-01 세션 01, 메인테이너: "그대로". 1의 정식은 미결정에 그대로, 5의 설정 줄은 66번째 판에서 설정 모달로 바뀌어 지나감) 프로토타입 62번째 판에 결정을 넣으며 Claude가 정한 것 (2026-10-31) → [[prototype#지금 판]]
	- MD3에서 묻는 모양(고르는 목록)과 바꿀 때 글자를 옮기는 법은 임시: Case → If는 조건 = Case의 글자 · 참 갈래 이름 = 남은 갈래의 이름 · 거짓 갈래 = default, If → Case는 참 갈래가 첫 갈래 · 새 갈래(이름 `2`)를 사이에 · 거짓 갈래가 default. 정식은 미결정 → [[02-interaction-rules#9. 미결정 사항]]
	- If 갈래 이름에 처음 이름("참" · "거짓")을 그대로 적으면 고치지 않은 것으로 봄(모델에 남기지 않음). 긴 이름은 그 갈래를 넓힘(Case와 같은 셈)
	- `r`로 "새 Method를 만들고 호출"을 하면 이름을 처음 적는 동안 괄호가 없어 인자가 지워질 뻔함. 그 칸에서 괄호 있는 이름을 적으면 인자를 되살림
	- 호출 블록의 칸은 한 줄이라 `Enter`는 `Shift`와 함께여도 받아들이기. 칸의 자리는 이름 앞(결과) · 이름 뒤 괄호 안(인자)
	- 키 안내 상자를 끄는 "키 안내"와 "머리 모양" · "결과 기호"를 캔버스 위 설정 줄에 둠
- [x] (2026-11-01 세션 01, 메인테이너: "그대로", 절 순서만 3.1 · 3.2 · 3.3으로 바로잡음) 파일에 들어가는 이름 (2026-11-01 → [[01-file-format#3.3 노드별 필드]]): 모델 요소 `ans:document`, 필드 이름은 모델 1장의 것 그대로(`kind` 값 `process` · `if` · `case` · `while` · `doWhile` · `for` · `call`), 줄(`Seq`)은 따로 객체를 두지 않고 주인의 `body` · `folds`에 펼침, 머리가 없으면 `head`를 적지 않음, v1의 `textKind`는 `"plain"`, `theme`은 `"default"`이고 모르는 값은 기본으로 그리되 그대로 저장. 공개한 뒤에는 바꾸기 어려우니 이름이 어색하면 지금 알려 주세요
- [x] (2026-11-01 세션 01, 메인테이너: "그대로") 레이아웃 설계 1장을 쓰며 Claude가 정한 것 (2026-10-25) → [[02-layout#1. 레이아웃 알고리즘]]
	- 여러 다이어그램의 배치 계산: 두 무리(Event와 머리 없는 것 · Method)가 **같은 줄 높이**를 쓴다. 줄 높이의 후보(4px씩 올림) 가운데 16 : 10에 가장 가까운 것을 고르고, 같으면 낮은 줄 높이. M38의 그림이 이 셈으로 그린 것이고, 메인테이너는 무리 사이 넓이만 골랐음(DA1). 규칙([[02-interaction-rules#5. 여러 다이어그램의 배치]])에는 "비율을 보고 고른다"까지만 있었음
	- `LayoutResult`에 블록의 상자와 따로 **누르는 자리**(제어 블록은 머리만, 접기 영역 · 펴 보기는 띠만, 갈래 이름 줄)를 담는다. 프로토타입이 하던 대로
	- 빈 글자도 한 줄 높이로 잰다
	- 테스트 전략 초안([[07-testing]])에서 Claude가 정한 것: 층마다의 시험 표, 골든 파일은 `.ns.svg` 하나가 입력이자 기대 출력, MVP 인수 시험 열 개(AT-01 ~ AT-10)의 고름, CI의 순서와 "10분 안" 목표, 문서 사이트 빌드와 따로 둠
	- 프로토타입에 숫자로만 있던 값 여덟에 토큰 이름을 붙여 시각 디자인 명세의 치수 표에 옮김(값은 그대로): `size.if-head-extra` 70 · `size.case-head-extra` 90 · `size.label-room` 18 · `size.hat-room` 24 · `size.diagram-min-w` 160 · `size.band-text-x` 10 · `size.fold-icon-room` 20 · `size.fold-extra-h` 4 → [[04-visual-design#5. 기하와 해부도]]
	- default가 없는 Case의 빈 default 칸(CD1)에서의 동작: 빈 블록처럼 고를 수 있고, 글자를 적거나 블록을 넣으면 그때 default 갈래가 생긴다(실행 취소 한 번). 지우기 · 잘라내기는 아무 일도 하지 않는다. 레이아웃은 그 칸을 "없는 default"로 표시해 넘긴다 → [[02-interaction-rules#Case 블록]]
	- 짧은 갈래를 고르게 늘릴 때(SB1)의 세부: 나머지 px은 마지막 블록이 받는다. 제어 블록이 더 받은 높이는 머리가 아니라 안쪽 줄에 가서 다시 나뉜다(If · Case는 갈래마다, 반복은 본문). 글자는 늘어난 블록의 위쪽에 둔다

## 용어 정리

메인테이너: "대한민국에서 일하고 있는 SW엔지니어로서 어색한 한국어 용어들이 많습니다. 영어를 직역한 것 아닌가 싶은데, SW엔지니어가 사용하는 언어를 사용해주세요."

- 첫 묶음(네 물음): 시험 → 테스트, 판 → 버전, 고치기 → 편집, 넣기 → 삽입, 지우기 → 삭제, 옮기기 → 이동, 글자 → 텍스트, 임시 보관 → 로컬 백업, 갈래 → 분기, 머리 → 헤더 등. "펴 보기"는 그대로. 제목 25개를 바꾸고 저장소 전체의 링크를 스크립트로 고친 뒤, 본문은 에이전트 다섯에게 규칙 표와 함께 나눠 맡김(1,500곳 남짓, 코드 블록 주석까지)
- 둘째 묶음 36개: 메인테이너가 "하나씩 물어봐주세요", 이어서 "앞으로 변경전, 변경후 비교해서 보여주세요", "36개 다 연속해서 물어봐주세요", "내 결정을 다 받은 다음에 작업을 해주세요. 내가 기다리는 시간이 너무 많습니다." → 결정을 모두 받은 뒤 에이전트 셋이 반영. 손잡이 → 핸들, 누르는 자리 → 클릭 영역, 들임 → 들여쓰기, 맞춤 형식 → 사용자 정의 형식, 껍데기 → 래퍼, 블록 텍스트의 종류 → 언어, 돌리다 → 실행하다 등. 자판의 자리 · 덩어리는 그대로
- 용어집이 기준. 옛 이름은 용어집에 "예전에는"으로 남김. `atelier/`의 지난 기록은 그대로
