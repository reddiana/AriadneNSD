# 작업 공간

메인테이너와 Claude가 지금 하고 있는 일이 모두 여기서 일어납니다. 지금 어디에 있는지([[status]]), 무엇이 남았는지([[backlog]]), 메인테이너의 답을 기다리는 것([[outbox]]), 프로토타입의 상태([[prototype]])가 있고, 결정의 근거(ADR과 DR)와 세션 기록이 쌓입니다. `docs/`가 내놓는 작품이라면 여기는 그것을 만드는 방(atelier)입니다.
애플리케이션 자체에 대한 문서(요구사항, 아키텍처, UX 설계, 상세 설계, 명세)는 `docs/`에 있습니다. → [[docs/README|문서 색인]]

## `docs/`와의 차이

| | `docs/` | `atelier/` |
| --- | --- | --- |
| 대상 | 애플리케이션 | 우리가 하고 있는 일 |
| 내용 | 지금의 모습: 요구사항, 설계, 명세 | 지금 하는 일: 현재 상태, 할 일, 답을 기다리는 것, 프로토타입. 거기에 이른 과정: 결정 기록(ADR · DR), 세션 기록, 검토 |
| 수명 | 제품과 함께 계속 유지 | 세션 기록은 쌓이고, 계획은 진행에 따라 갱신 |

논의 끝에 결정이 나면 **무엇이 되었는지**는 `docs/`(요구사항, 설계)에 반영하고, **왜 그렇게 정했는지**는 ADR(`adr/`, 아키텍처) 또는 DR(`decisions/`, 그 밖)에 남깁니다. 세션 기록과 상태 문서에는 링크만 남깁니다.

이 폴더의 이름은 `collab/`(2026-10-07) → `plan/`(2026-10-09) → `atelier/`(2026-10-12)로 바뀌어 왔습니다. 세션 기록과 타임라인에 적힌 `plan/…` 경로는 그때의 기록이고, 지금의 `atelier/…`입니다.

## 구성

질문 하나에 문서 하나입니다. 한 항목은 한 곳에만 적고, 다른 문서에서는 링크로 가리킵니다.

| 위치 | 내용 |
| --- | --- |
| [[status]] | 지금 어디인가: 바로 가기, 지금 단계, 이번과 다음 세션에 할 것. 한 화면 |
| [[backlog]] | 무엇이 남았나: 아직 하지 않은 일 전체, 미뤄 둔 일 |
| [[outbox]] | 메인테이너가 무엇을 답해야 하나: 정해 주세요, 확인해 주세요. [[inbox]]의 짝(Claude → 메인테이너) |
| [[prototype]] | 프로토타입은 지금 어떤가: 판, 리뷰 순서, 넣지 못한 것, 알려진 구멍, 시험한 곳 |
| [[sketchbook]] | 스케치북. 시안과 스파이크가 어디 있나: 주소, 저장소의 사본, 거기서 정한 것 |
| [[inbox]] | 세션 사이에 메인테이너가 생각을 적어 두는 페이지. 세션을 시작할 때 함께 검토 |
| [[atelier/sessions/README\|sessions/]] | 세션 기록: 작업 세션마다 하나씩, 논의한 것, 결정한 것, 다음 할 일. 목록이 그 폴더의 첫 페이지에 있음 |
| [[atelier/adr/README\|adr/]] | 아키텍처 결정 기록(ADR): 결정 1건이 파일 1개. 배경, 검토한 대안, 결정, 결과. 목록이 그 폴더의 첫 페이지에 있음 |
| [[atelier/decisions/README\|decisions/]] | 결정 기록(DR): 아키텍처가 아닌 결정. ADR과 같은 형식. 목록이 그 폴더의 첫 페이지에 있음 |
| [[requirements-rework]] | 요구사항 다시 짜기: 다시 짤 때 고칠 것의 목록 |

## 검토 문서
