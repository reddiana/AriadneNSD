# DR-0009: 단축키에 Vim 키를 들이고, 키 배열은 하나로 둔다

> [!NOTE] 이후 변경
> - 2026-10-17: 아키텍처 결정 기록 ADR-0025에서 결정 기록 DR-0009로 옮겨 왔다. ADR은 아키텍처 결정만 두기로 했기 때문이다 → [[dr-0001-split-decision-records|DR-0001]]. 본문은 그대로이고, 번호와 링크만 새 것으로 고쳤다. 본문의 "이 ADR"은 이 기록을 말한다.
> - 2026-10-17: 키 표가 편집기 설계([[03-editor]])의 4장에서 UX 설계의 [[03-keymap]]으로 옮겨졌다. 키는 사용자의 조작 규칙이라서다(메인테이너가 UX 문서 구조 S 1번을 고름). 조작 규칙 [[02-interaction-rules]]에는 이제 명령의 이름만 적는다
> - 2026-10-13: 아래 "확인하지 못한 것" 가운데 브라우저는 확인했다. 메인테이너가 프로토타입에서 한글 입력 상태로 `j`, `dd`, `zf`가 듣는 것을 보았다. Obsidian과 데스크톱은 남아 있다. "후속 작업"에 적은 프로토타입의 스위치는 같은 날 없앴고, 프로토타입 39번째 판부터 Vim 키만 듣는다 → [[prototype]]
> - 2026-10-13: 갈래의 이름을 고를 수 있게 하기로 했다([[ux-decisions]] Q10 · 2번). 그러면 갈래를 넣고 빼는 전용 키(`+` `-`)가 필요 없어질 수 있다. 없앨지는 정하지 않았다

## 배경

프로토타입의 단축키는 기능을 넣을 때마다 그때그때 고른 것이다(`P` `I` `K` `W` `D`로 넣기, `S` 다음 글자로 감싸기, `U` 풀기, `F` · `Shift`+`F` · `Ctrl`+`Shift`+`F`로 접기, `G` 따라가기 …). 한꺼번에 다시 설계하기로 미뤄 두었고, 방향은 [[backlog]]에 "Vim 키, 사실상 표준은 유지, 겹치는 키 정리"로 적혀 있었다.

2026-10-13에 메인테이너가 이 일을 앞당겼다.

> vim 단축키 진행합시다. 이거 하고 싶어요. vim 단축키 중 어떤 것들을 도입할지 제안해주세요.

Claude가 들일 키의 표와 정할 것 넷을 냈고, 메인테이너가 넷 모두 추천대로 정했다("1: 추천수용, 2: 추천 수용, 3: 추천 수용, 4: 추천 수용").

편집기에는 이미 Vim의 세 모드와 같은 상태가 있다: 블록을 고른 상태(Normal), 글자를 고치는 중(Insert), 영역을 고르는 중(Visual). 그래서 모드를 새로 만들지 않고 키만 얹을 수 있다.

관련 요구사항: [[01-requirements#EDIT-03]], [[01-requirements#NFR-05]]

## 결정 기준

- Vim에 익은 손이 배우지 않고 쓸 수 있을 것 (`hjkl`, `o`, `dd`, `p`, `u`, `v`)
- Vim을 모르는 사람이 잃는 것이 적을 것 (방향키, `Enter`, `Delete`, `Ctrl`+`C` `X` `V` `Z` `Y`는 그대로)
- 브라우저와 Obsidian이 가져가는 조합(`Ctrl`+글자, `Alt`+글자)을 쓰지 않을 것
- 시험하고 문서로 적을 키 배열이 적을 것
- 한글 입력 상태에서도 들을 것

## 검토한 대안

### 1. 키 배열의 수

- **하나로 (고름):** 표준 키 위에 Vim 키를 더한 배열 하나.
	- 장점: 시험할 배열이 하나다. 도움말과 메뉴에 적는 키가 하나다
	- 단점: 한 글자로 넣던 키(`I` `W` `D` `K`)가 없어진다. Vim을 모르는 사람은 두 번 누르기(`a` + 종류)를 새로 배운다
- **설정으로 켜고 끄기:** 지금 키와 Vim 키를 둘 다 두고 고르게 한다(Obsidian의 Vim 모드처럼).
	- 장점: 누구도 잃는 것이 없다
	- 단점: 기능을 넣을 때마다 키를 두 벌 정하고 시험한다. 도움말 · 메뉴 · 문서가 두 벌이 된다

### 2. 글자를 고치다 누른 `Esc`

- **적은 대로 받아들이고 나간다 (고름):** Vim에서 `Esc`는 Insert 모드를 나가는 키이고 적은 것은 남는다.
	- 단점: "`Esc`는 그만두기"에 익은 사람은 되돌리려면 `u`를 눌러야 한다
- **고치기 전으로 되돌린다** ([[ux-decisions]] Q3의 처음 추천):
	- 단점: Vim에 익은 손은 고칠 때마다 `Esc`를 누르므로 적은 글자를 매번 잃는다

### 3. 제어 블록을 넣는 키

한 글자 키 `I` `W` `D` `K`는 Vim의 `i`(고치기) · `d`(잘라내기) · `k`(위로)와 겹쳐서 자리를 옮겨야 한다.

- **`a` / `A` + 종류 (고름):** `ai` If, `aw` While, `ad` Do-While, `ak` Case, `ac` 호출. `a`는 뒤, `A`는 앞. 처리 블록은 `o` / `O` 한 번.
	- 장점: 소문자는 뒤, 대문자는 앞이라는 규칙이 `o` / `O`, `p` / `P`와 같다. 감싸기(`s` + 종류)와 종류 글자가 같다
	- 단점: Vim의 `a`(커서 뒤에서 고치기)를 포기한다
- **`o` / `O` + 종류 (`oo`가 처리 블록):**
	- 단점: `o`를 누르고 바로 글자를 치는 Vim 습관과 부딪힌다. `o` 다음에 `i = 0`을 치면 If가 들어간다

### 4. `dd`

- **잘라내기 (고름):** Vim에서 지운 것은 붙일 수 있다. `ddp`로 블록을 한 칸 아래로 옮기는 관용구가 그대로 된다. 복사 없이 지우는 것은 `Delete`
- **지우기:** `dd`와 `Delete`가 같은 일을 하고, 옮기려면 `Ctrl`+`X`를 따로 눌러야 한다

## 결정

1. **키 배열은 하나다.** 표준 키(방향키, `Enter`, `F2`, `Delete`, `Ctrl`+`C` `X` `V` `Z` `Y`)는 그대로 두고 Vim 키를 그 위에 더한다. 켜고 끄는 설정을 두지 않는다.
2. **글자를 고치다 누른 `Esc`는 적은 대로 받아들인다.** `Enter`와 같다. 되돌리려면 실행 취소를 한다.
3. **처리 블록은 `o` / `O`, 그 밖의 블록은 `a` / `A` + 종류 글자로 넣는다.**
4. **`dd`는 잘라내기다.** `Delete`는 복사 없이 지운다.

키 전체의 표는 [[03-keymap]]에 있다. 이 ADR은 위의 넷만 정하며, 표의 나머지 키는 그 문서에서 바뀔 수 있다.

들이지 않는 것: 횟수와 동사 + 이동 조합(`3j`, `d2j`), 레지스터, 매크로, 마크, `:` 명령줄, 글자 칸 안의 Vim 키, `Ctrl`+글자 조합(`Ctrl`+`R` 포함. 다시 하기는 `U`).

## 결과

- 좋아지는 점: 접기의 키 셋이 Vim의 `za` · `zf` · `zd`로 모이고, Obsidian의 전체 검색과 겹치던 `Ctrl`+`Shift`+`F`가 없어진다. "고른 상태에서 바로 글자를 치면 고치기로 들어가는가"(2026-10-10의 질문)는 "아니다"로 닫힌다. 붙여넣기에 "앞에"(`P`)가 생긴다
- 감수하는 점: 한 글자로 넣던 키가 두 번 누르기가 된다. `Esc`로 그만두던 사람은 `u`를 눌러야 한다. 갈래 이름 고치기(`L`)는 `l`과 겹쳐 키가 없어졌다([[ux-decisions]] Q10에서 함께 정한다). 다시 하기 `U`는 Vim과 다르다(Vim은 `Ctrl`+`R`. 브라우저의 새로 고침이라 쓰지 않는다)
- 확인하지 못한 것: 글자를 자판의 자리로 읽으면 한글 입력 상태에서도 듣는다고 보았으나, 실제 한글 입력기를 켠 브라우저 · Obsidian · 데스크톱에서 두 번 누르기(`dd`, `zf`)까지 듣는지는 써 봐야 안다 → [[prototype]]
- 후속 작업: 프로토타입의 "Vim 키 (시험)" 스위치로 써 본다(리뷰가 진행 중이라 기본값은 꺼짐. 제품에는 스위치가 없다). 써 본 뒤 [[03-keymap]]의 표를 굳히고, [[02-interaction-rules]]에 적힌 옛 키를 걷어 낸다. 옮기기 명령([[ux-decisions]] Q6)의 키를 정한다
